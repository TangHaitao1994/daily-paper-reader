## 摘要
口语对话是人机交互的一种自然形式，然而大多数语音语言模型仍局限于轮流式操作，缺乏实时适应性，例如用户插话。近期的双工语音到语音和语音到文本模型通过替代多级流水线来降低延迟，但往往牺牲语音质量，因为准确的 ASR、打断处理和高保真合成必须联合优化。我们提出 VoiceChat-TTS，一种面向交互式智能体的低延迟、连续且可流式传输的文本到语音模型。VoiceChat-TTS 直接由 LLM 文本 token 流驱动，通过控制 token 支持显式打断，并在没有文本输入时产生静音。该模型能够实现始终在线、响应迅速的语音生成，同时保持模块化和高语音质量，并且支持在话语中途打断而无需重置 KV 缓存。

## Abstract
Spoken dialogue is a natural form of human--computer interaction, yet most speech language models remain limited to turn-based operation and lack real-time adaptability, such as user barge-in. Recent duplex speech-to-speech and speech-to-text models reduce latency by replacing multi-stage pipelines, but often compromise speech quality because accurate ASR, interruption handling, and high-fidelity synthesis must be optimized jointly. We propose VoiceChat-TTS, a low-latency, continuous, and streamable text-to-speech model for interactive agents. VoiceChat-TTS is driven directly by LLM text-token streams, supports explicit interruption via control tokens, and produces silence when no textual input is available. The model enables always-on, responsive speech generation while preserving modularity and high speech quality, and it supports mid-utterance interruptions without resetting the KV cache.

## 1. 核心问题与整体含义

- **研究背景**：口语对话是人机交互中最自然的模态之一。面向交互式语音智能体，语音生成不仅需要高质量、低延迟，还必须支持“始终在线”的连续合成，以及用户随时插话（barge-in）的实时适应能力。
- **现有问题**：
  - 大多数语音语言模型仍局限于**轮次式（turn-based）**操作，缺乏对用户中途插话等实时动态的支持。
  - 近年来的**全双工语音到语音（S2S）或语音到文本（STT）模型**虽然通过端到端方式降低延迟、简化部署，但往往牺牲语音合成质量。原因是 ASR、打断处理、高保真语音合成需要在单一架构中联合优化，数据和建模难度高。
  - 近期流式 TTS（如 Audio Flamingo 3-Chat、VoXtream、SpeakStream、Qwen3-TTS）显著降低了首包音频延迟，但这些系统主要面向**单轮响应内**的流式生成，并未原生建模全双工智能体所需的连续、跨轮、静音与打断行为。
- **整体含义**：VoiceChat-TTS 提出一种**低延迟、连续、可流式**的文本到语音模型，由大语言模型（LLM）文本 token 流直接驱动，既能生成高质量语音，又能在无文本输入时输出静音，并通过控制 token 实现显式中途打断。其目标是作为模块化语音解码器嵌入到全双工交互框架或语音到语音流水线中，兼顾质量、延迟与交互实时性。

## 2. 方法论

VoiceChat-TTS 建立在 Audio Flamingo 3-Chat 的流式语音解码器之上，针对全双工交互做了多项扩展。

### 2.1 核心架构组件

- **音频编解码器（Audio Codec）**：
  - 采用全因果卷积自编码器，将 22 kHz 波形压缩为 12.5 Hz 帧率的离散 token。
  - 使用 31 个码本的残差向量量化（RVQ），每个声学 token 帧对应 **80 ms** 音频。
  - 为高效流式推理，对卷积块的感受野内输入进行缓存。

- **文本分词器（Text Tokenizer）**：
  - 使用 NVIDIA Nemotron Nano 2 子词分词器，并增加 **BOS token** 和 **interruption token**。
  - 文本流被右填充到与声学序列等长，以支持逐帧增量处理。
  - 文本通道领先音频通道一个 token，提供有限的语言前瞻信息。

- **字符感知子词编码器（Character-Aware Subword Encoder）**：
  - 解决 LLM 子词词表与 TTS 训练语料词表分布不匹配的问题。
  - 将每个子词转换为字符序列，用浅层 Transformer 编码后平均池化，得到对未见子词更鲁棒的嵌入。
  - 额外引入子词续接 token 的专用嵌入，以提升长词或碎片化词的发音连续性。

- **混合高斯估计头（MoGH）**：
  - 用于加速深层 RVQ 层次生成。
  - 不采用 31 步自回归逐码本解码，而是迭代式 unmask RVQ token：每轮预测被 mask token 的连续嵌入，再量化为离散 token。
  - 通常 4–8 次迭代即可实现高保真重建。

- **音频提示条件（Audio Prompt Conditioning）**：
  - 使用 3 秒参考音频 prompt 提供显式说话人线索。
  - 训练时 prompt 的声学 token 作为前缀，且其损失被 mask；推理时用同一 3 秒 prompt 初始化声学上下文。

- **边界嵌入与门控融合（Boundary Embeddings and Gated Fusion）**：
  - 为 BOS 和 interruption token 引入可学习嵌入，增强轮次与打断的边界信号。
  - 使用门控融合稳定文本嵌入与声学嵌入的融合，缓解 RVQ 嵌入幅值过大导致的混合精度溢出问题。

- **模型规模**：
  - 总参数约 **977M**。
  - 其中 778M 为基于 Gemma 3 的流式 TTS 模块，199M 为 codec 模型。

### 2.2 训练策略

- **两阶段训练**：
  1. **预训练**：仅使用单轮 TTS 数据，训练 **1.4M 步**。
  2. **微调**：使用完整混合数据（单轮 + 多轮 + 真实对话 + 合成双工对话），训练 **200k 步**。
- **数据增强**：
  - 对 50% 单轮数据随机前置 0.5–5.0 秒静音，以模拟多轮对话中用户说话、智能体保持安静的分布，减小单轮与多轮之间的模态差异。
- **训练混合比例**：
  - 40% 单轮 TTS 数据、15% 词/专有名词列表、10% 真实对话数据、35% 合成双工对话数据。
- **优化器**：AdamW，学习率 \(4 \times 10^{-5}\)。
- **批处理**：使用 Lhotse 动态分组，每批约 240 秒音频。

### 2.3 推理与打断流程

- 推理时使用 multinomial top-p 采样（\(p=0.95\)）、CFG scale 0.2、噪声 scale 0.001，MoGH 迭代 8 次。
- 当检测到 interruption token 时，模型学习自动过渡到静音。
- 可选 **Force Silence** 推理：在 interruption token 对应位置注入固定的静音 codec token 帧，确定性强化静音输出，且无需重置 KV cache。
