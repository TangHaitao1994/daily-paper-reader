## 摘要
虽然长音频会议理解（LAMU）正受到越来越多的关注，但面向特定任务的问答（QA）数据集仍然稀缺。现有的语音问答范式以及最先进的语音大语言模型存在声学信息丢失和长时上下文记忆不佳的问题。为了解决这些问题，我们构建了 LongAudioQA 数据集，并提出了 GRGA 模型，该模型将异构音频特征建模为多维图，并利用智能体规划进行检索和答案生成。

## Abstract
While long-form audio meeting understanding (LAMU) is garnering growing attention, task-specific question answering (QA) datasets remain scarce. Existing speech QA paradigms and state-of-the-art Speech LLMs suffer from acoustic information loss and poor long-term context memory. To address these issues, we construct the LongAudioQA dataset and propose the GRGA model, which models heterogeneous audio features into a multi-dimensional graph and leverages agent planning for retrieval and answer generation.

## 1. 论文的核心问题与整体含义

- **研究背景**：长音频会议理解（LAMU）在语音处理中日益重要，但任务型问答（QA）数据集稀缺。现有工作多聚焦于转录识别，缺少面向长时间、多说话人会议的专门 QA 基准。
- **核心痛点**：
  - **声学信息丢失（Acoustic Missing）**：主流 Speech LLM 倾向于先通过 ASR 将语音转成文本，再基于文本推理，丢失了音量、情绪、语调等副语言信息。
  - **上下文碎片化（Context Fragmentation）**：现有语音 QA 和 RAG 方法大多面向短音频（<30s），对长会议中跨时间、跨说话人的多跳依赖难以有效建模；一次性检索也难以捕捉分散的证据链。
- **整体含义**：本文通过构建 LongAudioQA 数据集并提出 GRGA（Graph-based Retrieval-Generation Agent）模型，将长音频会议建模为多维图，并引入智能体规划与反思机制，以同时缓解声学信息缺失和长程上下文记忆不足的问题。

## 2. 论文提出的方法论

- **总体思想**：GRGA 模仿人类专家处理会议的方式，按照“搜索—推理—验证”的认知循环进行检索与生成，而不是一次性检索。
- **音频到图索引（Audio-to-Graph Indexing）**：
  - **VAD 与转写**：利用 FSMN-VAD 分割音频，高保真 ASR 转写，并通过 CTC 强制对齐获得词级别精确时间戳。
  - **说话人分离与角色生成**：使用 ERes2NetV2 提取说话人嵌入并聚类；为每位说话人聚合其全部话语，由 LLM 生成结构化的说话人画像（角色、性别、立场等）。
  - **多维图建模**：每个话语（utterance）作为节点，包含文本、说话人、时间戳、音频等属性。边类型包括：
    - 时间边（相邻话语）
    - 回复边（5 秒窗口内不同说话人）
    - 同说话人边
    - 实体边（关键词共现）
    - 语义边（共指消解，如代词指向前文实体）
- **GRGA 规划过程**：
  - 形式化为部分可观测马尔可夫决策过程（POMDP），图 \(G\) 为环境。
  - **查询分解**：将用户问题投影到约束空间 \(C = \{c_e, c_c, c_t, c_m\}\)，分别对应实体、概念、时间、元数据约束。
  - **执行规划**：基于当前信念状态 \(b_t\)，由 LLM 策略生成多步原子操作计划 \(P_t = [op_1, op_2, \dots, op_k]\)。
  - **工具执行**：在图上执行计划，得到观察 \(o_t\)，更新信念状态。
  - **答案合成与反思**：合成候选答案 \(\hat{A}_t\) 和引用证据；反思器对证据与答案的逻辑蕴含关系打分 \(s_{ver}\)，转换为稀疏奖励：
    - 若 \(s_{ver} \ge \tau\)：成功，终止；
    - 否则给予负奖励，将批评反馈注入信念状态，触发重新规划。
- **动作空间（工具集）**：包括关键词搜索、语义搜索、混合搜索、时间范围过滤、说话人过滤、关系遍历（图遍历）、音频段访问等。

## 3. 实验设计

- **数据集**：
  - 构建 **LongAudioQA**，基于三个原始语料：
    - **AliMeeting**：普通话多说话人会议，含远场/近场音频；
    - **AMI Meeting**：非母语英语会议，声学复杂；
    - **DailyTalk**：高质量双人对话，拼接 20 个片段以形成中等长度输入。
  - 数据集规模：总时长约 54.7 小时；问答对数量：AliMeeting 3,013、AMI 3,243、DailyTalk 10,200，共 16,456 对。
  - 问题类型：事实型、推理性、时间型、摘要型、声学感知型五类。
- **对比方法**：
  - 端到端 Speech LLM：Qwen3-Omni、Audio Flamingo 3、MiMo-Audio，分别以“语音作为上下文”和“转录作为上下文”两种模式。
  - RAG 基线：BGE-M3 文本 RAG、CLASP 音频 RAG，二者使用与 GRGA 相同的 LLM 骨干。
- **评估指标**：
  - 语义准确率：使用 LLM-as-a-Judge（GPT-OSS-120B）判断生成答案与标准答案的语义等价性。
  - 证据引用 Precision/Recall（±2s 容差）。
  - 人类评估：随机抽取 150 个问题，涵盖五类问题，从正确性、接地性、连贯性三维度评分（1–5）。
- **其他分析**：上游错误分析（WER/DER）、步骤分析、噪声敏感性分析、案例研究、消融实验。

## 6. 论文的主要结论与发现

- GRGA 在 LongAudioQA 三个数据集上均显著优于端到端 Speech LLM 和 RAG 基线，尤其在推理型、摘要型和声学感知型问题上优势明显。
- 端到端 Speech LLM 在长音频上性能急剧下降：如 AudioFlamingo3 在 DailyTalk 上约 65%，在 AMI 上降至约 16%，验证了固定上下文窗口的局限。
- 朴素 RAG 在推理性问题上表现差（如 Text RAG 在 AMI 推理型上 24.6%，GRGA 为 65.3%），说明一次性向量检索无法捕捉多跳依赖。
- 音频 RAG 效果较差（约 20%），证明原始声学检索噪声大，结构化图中间表示更有效。
- 消融显示所有模块均有贡献，移除语义搜索导致系统崩溃式下降（−33.21%），移除反思导致 −9.84%，证明规划与验证机制关键。
- 噪声环境中，GRGA 比 Text RAG 更鲁棒，性能差距在高噪声下从 +5.37% 扩大到 +14.87%。
- 人类评估显示 GRGA 在接地性上提升最大（+0.97），说明精确的时间锚定和证据引用有效减少了幻觉。

## 7. 优点

- **数据贡献**：构建了覆盖多种问题类型、多说话人、长时间戳的 LongAudioQA 数据集，为 LAMU 提供系统基准。
- **方法创新**：将长音频建模为多维度异构图，显式刻画语义、说话人、时间和声学关系，有效解决声学缺失与上下文碎片化。
- **智能体设计**：以 POMDP 形式组织规划—执行—反思循环，支持自适应计算和多跳推理，而非一次性检索。
- **强接地性**：引入反思机制和证据引用，显著提升答案的接地性和可靠性。
- **实验全面**：不仅包含自动评估，还提供了人类评估、消融、噪声鲁棒性、步骤分析和案例研究，验证维度多元。
- **噪声鲁棒**：图结构充当噪声缓冲，在高 WER/DER 下仍保持较高准确率。
- **开源承诺**：提供数据和代码 GitHub 链接，有利于复现和后续研究。

## 8. 不足与局限

- **上游误差传播**：图构建依赖 ASR、强制对齐、说话人分离等模块，若上游错误严重，会污染推理图，影响最终答案。
- **推理延迟**：迭代式规划与反思带来比单轮 RAG 更高的计算开销，不利于实时应用。
- **领域特定性**：评估集中在结构化会议场景，未验证对电影、vlog 等非结构化长音频的泛化能力。
- **数据集潜在偏差**：使用 LLM 自动生成 + 人工验证，虽有人工筛选（κ=0.91），但仍可能存在 LLM 引入的偏差或幻觉未被完全消除。
- **实验覆盖不足**：
  - 消融实验仅在 AMI 数据集上进行；
  - 人类评估只对比 Qwen3-Omni 一个基线；
  - 噪声分析只对比 Text RAG；
  - 未系统比较其他长上下文 Speech LLM（如 Kimi-Audio）或更先进的 agentic RAG 变体。
- **评估方法局限**：自动准确率依赖 LLM-as-a-Judge，可能对某些模型输出存在偏好；语义等价判断可能忽略细微事实错误。
- **硬件环境非主流**：使用 Ascend 910B，若研究者使用 NVIDIA GPU，可能面临复现成本或兼容性问题。
- **模型规模与公平性**：不同基线模型参数量差异较大，可能影响对比的公平性；GRGA 本身无训练，性能上限受骨干 LLM 能力限制。
- **时长覆盖**：DailyTalk 拼接后平均约 10 分钟，AliMeeting/AMI 约 32 分钟，尚未覆盖数小时级别的超长会议。
