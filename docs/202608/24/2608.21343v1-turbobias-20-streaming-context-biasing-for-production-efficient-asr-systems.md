## 摘要
上下文化对于生产级自动语音识别（ASR）系统至关重要，因为用户提供的短语必须在严格延迟约束下被准确识别。尽管许多上下文偏置方法提高了识别准确率，但它们通常未解决现代生产 ASR 系统的实际需求：流式推理、高效批量解码、用户特定上下文列表以及低运行时开销。我们提出 TurboBias 2.0，一个面向生产的框架，用于在基于 Transducer 的 ASR 系统中进行高效短语增强。该框架扩展了 GPU 加速的 TurboBias，加入了不区分大小写的增强图和逐流批量解码，使批次中的每条语音都能使用独立的上下文偏置配置。这为多个并发用户提供了个性化上下文偏置，而无需共享或混合他们的上下文列表。所提框架支持离线和流式推理，并可与贪心解码和束搜索解码一起使用。实验表明，TurboBias 2.0 提高了上下文短语识别能力，同时保持低延迟和高吞吐量。

## Abstract
Contextualization is essential for production automatic speech recognition (ASR) systems, where user-provided phrases must be recognized accurately under strict latency constraints. Although many context-biasing methods improve recognition accuracy, they often do not address the practical requirements of modern production ASR systems: streaming inference, efficient batched decoding, user-specific context lists, and low runtime overhead. We propose TurboBias 2.0, a production-oriented framework for efficient phrase boosting in Transducer-based ASR systems. The framework extends GPU-accelerated TurboBias with a case-insensitive boosting graph and per-stream batched decoding, allowing each utterance in a batch to use an independent context-biasing configuration. This enables personalized context biasing for multiple simultaneous users without sharing or mixing their context lists. The proposed framework supports both offline and streaming inference and can be used with greedy and beam-search decoding. Experiments show that TurboBias 2.0 improves contextual phrase recognition while preserving low latency and high throughput.

    - 低运行时开销与易于动态更新。
- **本研究目标**：提出 **TurboBias 2.0**，一个面向生产的 Transducer ASR 短语增强框架，在保持低延迟和高吞吐的同时，提升上下文短语识别准确率。

## 2. 论文提出的方法论

### 2.1 不区分大小写的 GPU 短语增强图

- 原始 TurboBias 使用大小写敏感的短语增强树，存在一个问题：用户输入的短语常常是小写或格式不规范，而 ASR 输出可能带有大写、标题大小写等，导致匹配失败。
- **字符 tokenizer 模型**：将每个字符弧替换为两个平行的大小写变体弧，即可紧凑地实现大小写不敏感匹配。
- **BPE tokenizer 模型**：由于 BPE 词汇表通常不包含每个 token 的所有大小写变体，论文提出“变体 BPE 表示”：
  - 将短语先做贪心 SentencePiece 分词；
  - 将每个 token 分解为规范字符级片段（canonical character-level pieces）；
  - 对每个字符位置添加单片段 token 弧，并枚举所有能覆盖连续片段的词汇 token，添加合并弧；
  - 对大小写不敏感匹配，所有 token 都映射到小写规范序列，因此不同大小写的 BPE 分段都能被接受。
- **分数分配**：由于同一短语可能通过不同数量的弧被匹配，直接给每个弧相同分数会导致路径长度不同、总奖励不一致。论文使用**累积分数势能（score potential）**：
  - 设第 k 个贪心 BPE token 的增强分数为 \(w_k\)，分解为 \(m_k\) 个字符片段；
  - 将 \(w_k\) 按公式分布到内部字符状态：
    \[
    \Delta_{k,i} = w_k \frac{\exp((i+1)\tau)}{\sum_{j=0}^{m_k-1}\exp((j+1)\tau)},\quad i=0,\dots,m_k-1
    \]
  - 其中 \(\tau\) 控制分数在 token 末端的集中程度；\(\tau=0\) 为均匀分配，\(\tau\) 较大时接近原始 TurboBias 行为。
  - 这样不同大小写和不同 BPE 分段路径最终获得相同的总短语奖励。

### 2.2 每流（per-stream）独立上下文偏置

- 生产场景中，同一 GPU 批次可能包含来自不同用户 / 会议的多个流，每个流需要独立的上下文列表，且不能相互干扰。
- **实现方式**：
  - 将多个独立的增强树张量（弧标签、目标状态、弧权重、出弧范围、后缀链接等）拼接为统一的“多模型存储”；
  - 每个模型 id 记录其对应的状态 / 弧偏移和增强权重；
  - 每个流携带一个 biasing model id；id 为 -1 表示无偏置；
  - GPU kernel 根据 model id 读取相应偏移，再执行与单树相同的后缀链接遍历，因此不同流可以在同一批次中使用独立短语列表，且不共享干扰项。
- **动态生命周期管理**：
  - 添加模型：将张量追加到合并存储并记录偏移；
  - 删除模型：标记 inactive 并左移后续区间，操作在 GPU 上并行高效完成；
  - 提供三级缓存策略：磁盘缓存（持久化预编译树）、CPU 内存缓存（按需复制到 GPU）、解码器级注册（在识别会话前预加载，完全隐藏更新开销）。

### 2.3 流式束搜索支持

- 将离线 Transducer 束搜索扩展到流式：流式解码逐 chunk 处理编码器输出，需跨 chunk 维护搜索状态。
- 将已完成 chunk 的假设存储在扁平树中，保存累积分数和边界解码器状态；后续 chunk 继续、合并、剪枝新扩展假设。
- 实现保持与 CUDA Graphs 和 GPU 批量操作兼容，支持低延迟流式 Transducer 束搜索，同时保留离线算法的执行模式。

## 3. 实验设计

### 3.1 数据集与场景

- **Contextual Earnings-22（C-Earnings22）**：
  - 公共上下文 ASR benchmark，基于 Earnings-22 构建，聚焦财报电话会议转录；
  - 每个样本为 15 秒音频片段，包含至少一个上下文关键词；提供人工校验文本和上下文列表；
  - 提供 local（仅当前片段关键词）和 global（整段通话关键词清单，含干扰项）两种上下文设置；
  - 测试集约 2.63 小时，1,259 个关键词实例，738 个唯一关键词。
- **内部医疗领域测试集**：
  - 约 3 小时英语医疗语音，3.05 小时，2,630 个关键词实例，489 个唯一关键词；
  - 包含疾病、手术、药物等专业术语（如 linezolid、quinapril、abciximab）。

### 3.2 使用的 ASR 模型

- **parakeet-tdt-0.6b-v2（TDT-v2）**：600M 参数，FastConformer 编码器 + TDT 解码器，离线强基线。
- **nemotron-speech-streaming-en-0.6b（Nemotron-streaming）**：600M 参数，缓存感知 FastConformer + RNNT 解码器，低延迟流式基线。
- **parakeet-unified-en-0.6b（Unified）**：600M 参数，支持离线和流式，FastConformer + RNNT，参数共享，MCR-RNNT 训练缩小离线 / 流式差距。

### 3.3 对比方法

- **CTC-WS（CTC-based Word Spotter）基线**：
  - 使用 parakeet-tdt-0.6b-v2 做贪心 TDT 解码，另用 parakeet-tdt-ctc-110m 做 CTC 关键词检测与后校正；
  - 由于 Contextual Earnings-22 论文中的修改版 CTC-WS 缺少实现细节，论文报告了一个“最接近复现”以及已发表的 Argmax 结果作为参考。
- **无上下文基线（No biasing）**。
- **TurboBias 2.0 变体**：
  - 大小写敏感 vs 不敏感；
  - 全量（full）、每流全局（per-stream global）、每流本地（per-stream local）上下文配置；
  - 贪心解码（label-looping）与束搜索（ASLD++，beam size = 32）；
  - 离线与流式模式。

### 3.4 评价指标

- **WER**：完整 ASR 输出的词错误率。
- **关键词精度 / 召回率 / F-score**：仅针对上下文短语的匹配质量。
- **RTFx**：逆实时因子，即音频时长 / 解码耗时，越高表示解码越快。
- **流式延迟**：最坏情况算法延迟，由 chunk size 和 right context 之和计算。

## 6. 论文的主要结论与发现

- **TurboBias 2.0 有效提升上下文识别**：
  - 在 C-Earnings22 上，离线 Unified 模型 + 每流全局增强 + 束搜索达到 **87.5 F-score、12.6% WER**，接近已发表 Argmax CTC-WS 的 88.2 F-score，并取得更低 WER；显著优于论文中的 TDT-v2 + CTC-WS 复现（82.0 F-score / 13.7% WER）。
  - 在内部医疗集上，TurboBias 2.0 也显著提升上下文 F-score 并降低 WER。
- **大小写不敏感图有效**：
  - 使用小写上下文列表时，原始大小写敏感图提升微弱；使用目标大小写（如首字母大写）时性能大幅提升；
  - TurboBias 2.0 的不区分大小写图无需依赖上下文短语的书写格式，性能略优于目标大小写敏感树：贪心 75.4 vs 74.8 F-score，束搜索 81.4 vs 80.6 F-score。
- **每流偏置进一步带来收益**：
  - 每流全局设置下，贪心 F-score 从 75.4 升到 81.5，束搜索从 81.4 升到 87.5；WER 同步下降，说明避免跨流干扰有助于整体质量。
  - 每流本地设置（已知当前语音中出现的精确短语）可获得更高 F-score，但该设置在实际部署中不现实，因此每流全局是主要生产设定。
- **流式推理中收益保持**：
  - Unified 流式模型在 1.12s 最坏延迟下，经全局增强 + 束搜索后 F-score 从 62.2 提升到 81.7，WER 从 16.3% 降到 14.3%；0.56s 延迟配置也呈现相同趋势。
  - Nemotron-streaming 在 C-Earnings22 上表现类似，但在内部医疗集上弱于 Unified。
- **低开销**：
  - 单树全局增强对 RTFx 影响很小（例如贪心 1812 → 1726 RTFx，束搜索 1150 → 1005 RTFx）；
  - 每流偏置在采用解码器级注册后，速度与全局增强基线相当（例如每流全局贪心 1714 vs 全量 1717，束搜索 988 vs 989）；
  - 磁盘缓存对批量小上下文列表的收益不稳定；CPU 内存缓存只引入约 9–17% 的识别速度开销。

## 7. 优点

- **强生产导向**：从实际部署需求出发，同时解决流式、批处理、个性化、低开销、动态更新等关键问题。
- **大小写不敏感的紧凑图设计**：避免为每种大小写变体扩展短语列表，减少了树大小、编译时间和内存占用；通过累积分数势能解决不同路径长度导致的奖励不一致问题。
- **每流独立偏置**：在多用户并发场景下避免上下文列表互相污染，并以 GPU 友好的张量拼接方式实现，保持推理效率。
- **支持流式束搜索**：将 TurboBias 扩展到流式 Transducer 束搜索，有利于低延迟实时应用。
- **无需重训练模型**：可直接应用于现有 Transducer ASR 模型，不需要辅助 CTC 推理路径或后校正阶段。
- **已开源**：在 NVIDIA NeMo 工具包中发布（提供 PR 编号），具有实际可复现性。
- **多模型、多数据集验证**：在公共 benchmark 和内部专业领域数据上，用三种不同模型和两种解码模式进行验证，结论较稳健。
