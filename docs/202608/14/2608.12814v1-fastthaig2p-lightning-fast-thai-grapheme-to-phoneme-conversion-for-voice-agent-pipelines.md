## 摘要
FastThaiG2P 为文本到语音流水线提供亚毫秒级泰语字素到音素转换（遵循国际音标和 Kokoro-TTS 规范），使用经 PyThaiNLP 分词的可扩展词典以及面向常见中部泰语语音的规范化规则。该方法在包含 27,242 条合成生成话语的基准测试上实现了每句平均 0.15 毫秒的延迟，其中 30% 用于分词，12% 用于规范化，58% 用于集外词回退（集外词率为 0.5%）。为验证其有效性，我们使用 FastThaiG2P 对 Som-TTS（一个包含 20 小时字素-音频对的开放数据集）进行音素化，然后基于 Kokoro-TTS 配方训练了一个 82M 参数的 StyleTTS 2 模型。所得模型能够生成可懂的泰语语音，适合原型设计和开发，在 CPU 上使用 ONNX 推理时实时因子为 0.25（4 倍实时）。

## Abstract
FastThaiG2P provides sub-millisecond Thai grapheme-to-phoneme conversion for text-to-speech pipelines (International Phonetic Alphabet and Kokoro-TTS conventions) using a PyThaiNLP-tokenized, extensible dictionary and normalization rules for common Central Thai speech. The approach achieves an average latency of 0.15 ms per utterance on a benchmark of 27,242 synthetically generated utterances, of which 30\% is spent on tokenization, 12\% on normalization, and 58\% on out-of-vocabulary fallbacks (0.5\% OOV rate). To demonstrate its effectiveness, we used FastThaiG2P to phonemize Som-TTS, an open dataset containing 20 hours of grapheme-and-audio pairs, then trained an 82M-parameter StyleTTS 2 model based on a Kokoro-TTS recipe. The resulting model vocalizes intelligible Thai speech suitable for prototyping and development at 0.25 real-time factor (4x real-time) with ONNX inference on CPU.

## 1. 论文的核心问题与整体含义

- **研究动机**：泰语 TTS 的 G2P（字素到音素转换）具有特殊性：无词边界、五声调、不连续元音、非透明字素-音素映射、大量数字/缩写/英文混合等。实时语音代理流水线对延迟要求严格，整个 TTS 预算通常仅 500–1000 ms，因此 G2P 必须“既全面又快速”。
- **现有工具缺口**：TLTK、Epitran、thai-g2p、CharsiuG2P 等要么规则化但缺乏大词典，要么需要外部分词/规范化，要么神经模型延迟过高。它们不能同时满足：大词典、完整文本规范化、亚毫秒延迟、鲁棒 OOV 回退。
- **G2P-free 泰语 TTS 的局限**：MMS-TTS、ThonburianTTS、JaiTTS、Qwen3-TTS 等大型模型虽可直接从字素合成语音，通常需要 GPU 和 336M–2B 参数；在 CPU-only、低延迟、小内存、边缘设备等场景，基于音素的紧凑声学模型仍然实际必要，因此快速 G2P 前端仍有价值。
- **整体含义**：FastThaiG2P 旨在弥合“词典精度”与“实时速度”之间的鸿沟，为 CPU 上的音素驱动泰语 TTS 提供一个实用、可扩展、亚毫秒级前端。

## 2. 方法论

FastThaiG2P 采用四阶段流水线：

- **阶段 1：文本规范化**
  - 固定顺序处理 15 类不可直接朗读内容，包括：泰语重复标记、泰文数字转阿拉伯数字、邮箱、英文缩写/品牌名、单位、符号、时间、电话号码、字母数字标识符、千分位数字、小数、泰语缩写、残余拉丁字符等。
  - 短数字（≤6 位）按泰语位值读法；长数字（≥7 位）按位逐字读，符合电话号码/账号/ID 习惯。
  - 该模块是级联语音代理管道中 LLM 提示失败时的最后防线。

- **阶段 2：分词**
  - 使用 PyThaiNLP 的 `newmm` 最大匹配引擎，并加载自定义词典。
  - `data/dict.txt` 与 `data/ipa.json` 同时用于分词和 IPA 查找，保证每个分词结果（除 OOV）都有对应 IPA。

- **阶段 3：词典构造**
  - 62,112 条约 IPA 词典，合并优先级从高到低为：
    - 手动覆盖：人工验证条目，持续改进。
    - Wiktionary：约 13,000 条，来自泰语 Wiktionary dump，作为转录格式参考标准。
    - LLM 转录：约 49,000 条，由 Claude Opus 4.6 via Amazon Bedrock 批量生成（每批 100 词）。
  - LLM 生成经过白名单校验（38 个音素码位），无白名单外字符或缺少斜杠的条目会被拒绝并记录。
  - Prompt 在 500 条 Wiktionary 验证集上验证；错误分为非致命（声调不符、元音长度、双元音标记、韵尾变体）和致命（音节数错、首辅音或元音音质错）。最终 prompt 精确匹配率 78.8%，致命错误率 1.8%；Pali/Sanskrit 外来词不计入致命错误。

- **阶段 4：OOV 回退**
  - 未命中词典的词使用从 TLTK 移植的规则回退：trigram 音节切分 → 基于辅音类别、元音模式、声调规则映射为罗马化 → 转换为 IPA。
  - 回退总能产生音系合法的泰语 IPA，但外来词/巴利-梵语复合词等不规则词可能不准确。

- **关键工程优化：正则缓存**
  - 原 TLTK 每次调用都重新编译正则，Python 内置 LRU 缓存（512 条）溢出导致重复编译。
  - FastThaiG2P 在回退的三个热循环中引入显式无界正则缓存，并在导入时预加载音节规则。
  - 这使整体 G2P 延迟从约 2 ms 降至约 0.15 ms，最高约 15 倍加速。

- **IPA 约定与映射**
  - 遵循英语 Wiktionary 泰语 IPA，使用 Chao 声调字母和 38 个音素相关码位。
  - IPA 到 Kokoro 映射：将未使用的 token ID 170 重新用作“高音调”，从而区分泰语五个音调，避免高音调与升调合并；同时去除 IPA 中仅有的附加符号，并用 Kokoro 等价音替换塞擦音和 `g` 字符。
