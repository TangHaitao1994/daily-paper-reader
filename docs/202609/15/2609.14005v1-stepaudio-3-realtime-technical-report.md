## 摘要
实时语音交互需要深度推理、快速响应和流畅的话轮转换。我们提出 StepAudio 3 Realtime，一个围绕连续的“聆听—对话—思考—行动”循环组织的音频-语言基础模型。Deep Perception（深度感知）捕捉丰富的声学线索以理解用户意图，而 Seamless Duplex（无缝双工）对同步音频流进行建模，以自然处理停顿、反馈和打断。关键的是，我们通过 Think-While-Speaking（边说边想）解决了深度思考与延迟之间的张力，在语音输出的同时并行执行内部推理。在推理模式下，StepAudio 3 在 StepAudioChat 上达到 73.0 的宏平均值。借助 Think-While-Speaking，它在实时说话的同时实现了与专用推理模型相当的对话和推理性能。此外，集成的 Voice Agent 可在不打断对话流的情况下处理异步工具执行。StepAudio 3 Realtime 在关键维度上取得顶级性能：在 MMSU 基准上取得出色的 90.6 分，在 Artificial Analysis Full-Duplex Bench 上总体得分 98.9，在 $τ$-Voice 上的宏任务成功率为 56.0%。

## Abstract
Realtime spoken interaction demands deep reasoning, prompt responses, and fluid turn-taking. We present StepAudio 3 Realtime, an audio-language foundation model organized around a continuous listen-converse-think-act loop. Deep Perception captures rich acoustic cues to interpret user intent, while Seamless Duplex models synchronized audio streams to handle pauses, backchannels, and interruptions naturally. Crucially, we resolve the tension between deep deliberation and latency via Think-While-Speaking, executing private reasoning in parallel with spoken delivery. In reasoning mode, StepAudio 3 reaches a 73.0 macro average on StepAudioChat. With Think-While-Speaking, it achieves dialogue and reasoning performance comparable to dedicated reasoning models while speaking in real time. Furthermore, an integrated Voice Agent handles asynchronous tool execution without disrupting the dialogue flow. StepAudio 3 Realtime achieves top-tier performance across key dimensions: an exceptional 90.6 on the MMSU benchmark, 98.9 Overall on the Artificial Analysis Full-Duplex Bench, and a 56.0% macro task-success rate on $τ$-Voice.

## 1. 论文的核心问题与整体含义

- 论文要解决的问题：**实时口语交互**同时要求深度推理、快速响应和自然的话轮转换，但模型往往难以兼顾。
- 现有挑战包括：
  - 用户在说话过程中可能出现停顿，需要区分“话没说完”和“轮次结束”；
  - 模型正在说话时用户可能插话，插话可能是简单反馈（backchannel），也可能是实质性打断；
  - 复杂请求需要仔细推理，但实时对话不能等待过长的推理延迟；
  - 外部工具执行可能比当前对话轮次持续时间更长，需要在不中断对话的情况下协调。
- StepAudio 3 Realtime 的整体思路是：将交互组织为**连续的“聆听—对话—思考—行动”循环**，让感知、话轮管理、私有推理和工具执行能够并行推进。
- 其目标是：在保持实时说话的同时，达到接近专用推理模型的对话和推理水平；在真实语音交互基准上取得领先成绩。

## 2. 论文提出的方法论

### 2.1 总体架构

- 采用**混合专家（MoE）架构**：总参数约 **196B**，每个 token 激活约 **11B** 参数。
- 语言骨干基于 **Step 3.7 Flash**。
- 音频前端使用来自 **Qwen3-Omni 的 Audio Transformer（AuT）编码器**，通过 adapter 映射到 LLM 表示空间。
- 系统包含**双工输入路径**：用户音频流 + 模型自身音频流，二者都送入音频编码器和 adapter，再进入 LLM 解码器；文本 token 有单独输入路径。
- 语音生成器产生流式模型音频，并反馈回模型音频流，用于后续交互。

### 2.2 训练流程

- **三阶段预训练**：
  - 模态对齐阶段：建立音频表示与语言模型之间的接口；
  - 多模态混合训练：大规模联合音频-文本建模；
  - 冷却阶段：更多高质量数据，进一步精炼基础模型。
  - 固定序列长度 **32K**，处理约 **1.2T 训练 token**。
- **Midtraining（中段训练）**：
  - 上下文长度扩展到 **128K**，以容纳更长对话历史、早期用户需求、中间工具结果；
  - 增加音频理解数据和 agent 交互数据的比例；
  - 使用超过 **10,000 小时**合成全双工交互数据训练全双工建模。

### 2.3 Deep Perception：语音识别与音频理解

- 分为两个分支：
  - **StepAudio 3 ASR Max**：专门用于转录；
  - **StepAudio 3 Realtime**：面向更广泛的音频理解和口语交互。
  - 二者共享预训练和 midtraining，仅在 SFT 阶段分化。
- ASR 训练要点：
  - 使用 SpecAugment 风格的时间-频率掩码增强；
  - 支持上下文感知转录，可提供对话历史、场景描述、任务术语等作为可选证据，但目标 transcript 始终以输入波形为准；
  - 数据构建包括短标注语音、长伪标注录音、ROVER 多系统融合、LLM 标点和一致性恢复；
  - **长尾术语增强**：针对同音词、罕见名、技术术语、缩写等构建合成训练样本，只保留发音与目标文本一致的样本。
- 音频理解数据构建：
  - 层级 taxonomy 覆盖词汇内容、副语言、声学事件、说话人和时间结构、音乐、音频推理；
  - 流程：采样 → 描述 → 能力标记 → 查询构建 → 多模型标注
