## 摘要
文本到语音（TTS）是以大语言模型（LLM）为中心的口语对话系统（SDS）中提供语音响应的关键模块。为确保准确的TTS合成，LLM生成的响应必须通过文本规范化（TN）模块转换为TTS可读格式，这在实时SDS场景中提出了严格的低延迟要求。现有TN解决方案大多基于规则，依赖人工工程，对未见过的模式泛化能力差。尽管LLM本身可以通过提示工程执行TN，但它面临关键限制：非流式处理导致的首token延迟高、幻觉风险，以及当核心LLM模块仅为TN进行微调时智能或推理能力下降。为应对这些挑战，我们提出StreamTN，一种基于轻量级LLM的中文流式TN模型。StreamTN基于Qwen3-0.6B，采用双轨流式框架，输入token和输出token在两条并行轨道上处理，无需复杂提示即可实现低延迟实时推理。此外，任务特定的微调比基于规则系统和通用LLM带来了更优的TN性能和更少的幻觉。我们还引入了一个涵盖多种文本场景的TN基准，为口语对话系统中的语音生成提供全面评估标准。实验证明了StreamTN在准确性和推理延迟方面的有效性。

## Abstract
Text-to-Speech (TTS) is an essential module that provides spoken responses in a spoken dialogue system (SDS) centered on a large language model (LLM). To ensure accurate TTS synthesis, responses generated by an LLM must be converted into TTS-readable formats via a Text Normalization (TN) module, imposing strict low-latency requirements in real-time SDS scenarios. Existing TN solutions are largely rule-based, rely on manual engineering, and generalize poorly to unseen patterns. Although an LLM itself can perform TN through prompt engineering, it faces key limitations: high first-token latency due to non-streaming processing, hallucination risks, and degraded intelligence or reasoning when the core LLM module is fine-tuned solely for TN. To address these challenges, we propose StreamTN, a lightweight LLM-based Chinese streaming TN model. Built on Qwen3-0.6B, StreamTN employs a dual-track streaming framework in which input tokens and output tokens are processed on two parallel tracks, enabling low-latency real-time inference without complex prompting. Moreover, task-specific fine-tuning yields superior TN performance and fewer hallucinations than rule-based systems and general-purpose LLMs. We also introduce a TN benchmark that spans diverse text scenarios, providing a comprehensive evaluation standard for speech generation in spoken dialogue systems. Experiments demonstrate the effectiveness of StreamTN in accuracy and inference latency.

  - 直接使用通用 LLM 进行 TN 虽然泛化更强，但存在非流式处理导致的首 token 延迟高、输出格式不稳定和幻觉风险；若对核心 LLM 微调专做 TN，又可能损害其原本的智能与推理能力。
- **整体含义**：论文提出 **StreamTN**，一个轻量级的、基于 LLM 的中文流式 TN 模型，目标是同时满足对话级联系统中的两个关键要求：**输出准确、TTS 可读的规范化文本**，以及**在部分输入到达时即可增量式、低延迟地生成结果**。此外，作者还构建了一个面向对话场景的中文 TN 基准，以弥补现有评估资源与真实流式对话需求之间的差距。

## 2. 论文提出的方法论

- **模型基础**：StreamTN 建立在 **Qwen3-0.6B** 上，复用其通用文本建模能力，但不依赖复杂提示工程。
- **双轨流式框架**：
  - 将 LLM 产生的原始文本 token 与规范化输出 token 分别放在**两条并行轨道**上。
  - 两条轨道的嵌入通过**逐元素相加**融合，再送入 Qwen3 Transformer 主干，并使用因果注意力掩码。
  - 输入轨道提供当前可用的原始文本前缀；输出轨道携带已经生成或延迟等待的规范化文本历史。
- **延迟参数 \(d\)**：
  - \(d\) 表示模型在生成第一个规范化 token 之前，需要先观测多少个原始输入 token。
  - 原始输入轨道定义为：
    \[
    \bar x_t = x_t,\quad 1\le t\le n;\quad \bar x_t=\langle pad\rangle,\quad t>n
    \]
  - 输出历史轨道定义为：
    \[
    \bar y_t = \langle delay\rangle,\quad 1\le t\le d;\quad \bar y_t=y_{t-d},\quad d<t\le m+d;\quad \bar y_t=\langle pad\rangle,\quad t>m+d
    \]
  - \(\langle delay\rangle\) 和 \(\langle pad\rangle\) 在嵌入后都映射为零向量，普通 token 则使用 Qwen3 原有的 token 嵌入。
- **训练目标**：
  - 模型在部分输入上下文的条件下预测目标 token，而不是依赖完整输入序列。
  - 使用负对数似然：
    \[
    L_{TN}=-\sum_{i=1}^{m}\log p_\theta\left(y_i\mid x_{\le\min(n,i+d-1)},y_{<i}\right)
    \]
  - 训练时监督只施加在有效规范化目标 token 上，零填充位置通过目标掩码排除。
- **推理流程**：
  - 推理阶段使用自回归 KV cache。模型先接收 \(d\) 个原始 token 并预测第一个输出 token；之后每个对齐步骤同时利用上一输出 token 和下一个可用原始 token 预测后续输出。
  - 当上游 LLM 输入流结束后，输入轨道变为 \(\langle pad\rangle\)，模型继续基于输出历史解码，直到生成结束符或达到最大生成长度。
- **延迟衡量**：
  - 端到端首包延迟定义为：
    \[
    FPD_{e2e}(d)=T^{LLM}_{wait}(d)+T^{TN}_{first}(d)
    \]
  - 其中 \(T^{LLM}_{wait}(d)\) 是等待上游 LLM 产生前 \(d\) 个 token 的时间，\(T^{TN}_{first}(d)\) 是 StreamTN 自身计算首个规范化 token 的时间。论文将二者分开报告，以便区分模型自身延迟与上游 token 到达速率的影响。

## 6. 论文的主要结论与发现

- **StreamTN 整体有效**：在 4 帧延迟配置下，StreamTN 取得 Micro-F1 = \(0.8937 \pm 0.0009\)，Micro-P = \(0.8931 \pm 0.0022\)，首包延迟为 213 ms。其在准确率上与 BiLSTM 相当，但精确率更高，同时支持增量式流式处理。
- **优于规则系统和通用 LLM**：规则式 WeTextProcessing 的 Micro-F1 为 0.7853，通用 Qwen3-0.6B 仅 0.4872，说明任务特定微调能大幅提升规范化质量，并减少格式不稳定和幻觉问题。
- **延迟与准确率存在权衡**：
  - 非流式模型 Micro-F1 最高，为 0.9639，但无法在输入完整前输出。
  - 随着延迟从 1 帧增加到 16 帧，Micro-F1 从 0.7030 提升到 0.9239，FPD 从 75 ms 增加到 756 ms。
  - 4 帧配置是实际权衡后的选择。
- **类别难度差异明显**：
  - 物理单位（0.977）、金额（0.975）、时间（0.967）等规则性强的类别表现最好。
  - 复杂数学方程（0.750）和化学式（0.791）最困难，主要受专用符号、长 verbalization 和结构多样性影响。
- **全参数微调很关键**：LoRA 微调将 Micro-F1 降至 0.6335，说明低秩适配不足以学习 TN 所需的精确变换。添加系统提示反而略微降低性能（0.8852），表明 StreamTN 无需复杂提示即可工作。

## 7. 优点

- **面向真实流式场景设计**：双轨流式架构使 TN 模块可以在上游 LLM 尚未生成完整回复时就开始输出规范化结果，符合级联对话系统对低延迟的要求。
- **延迟可控**：通过单一延迟参数 \(d\) 明确控制输入 lookahead 数量，能够在准确率和首包延迟之间进行可解释的权衡。
- **无需复杂提示**：任务特定微调使模型可以直接学习结构化输出，避免通用 LLM 提示工程带来的高 prefill 成本和格式不稳定。
- **轻量化**：基于 0.6B 参数模型，训练和推理成本相对较低，更适合实际部署。
- **构建了对话导向中文 TN 基准**：覆盖 14 类常见及科学场景，补充了现有 TN 评测中对话真实分布和科学表达覆盖不足的问题。
- **实验设计较严谨**：使用多种子重复实验、微平均指标、字符级对齐，并分别报告模型自身延迟与上游等待时间，有助于公平比较。

## 8. 不足与局限

- **复杂科学类别性能有限**：复杂数学方程和化学式仍是主要错误来源，F1 仅 0.750 和 0.791，离实用要求可能还有差距。
- **语言与领域单一**：目前仅针对中文，未扩展到英文或其他语言；应用场景主要局限于中文对话系统。
- **数据集规模与来源限制**：
  - 测试集仅 1,262 条，规模较小，可能不足以完全反映真实对话中长尾文本分布。
  - 训练数据部分

- 训练数据部分由 Qwen3-32B 自动生成，尽管经过人工审核，但生成式标注可能引入与参考规范不一致的隐性偏差；且人工抽检仅覆盖 5%，剩余 95% 未逐一验证。
- **未进行端到端语音合成评估**：TN 输出只在文本层面用字符匹配评价，没有验证其对下游 TTS 发音可懂度、自然度和实际语音质量的影响。
- **延迟评估依赖上游生成速度**：FPD_e2e 中的上游等待时间基于 Qwen3-32B 约 20 token/s 的生成速度，若实际部署中上游速度不同，延迟权衡结论需要重新校准。
- **流式对齐假设较理想**：模型假定输入 token 与输出 token 可按固定延迟对齐，但真实对话中可能包含标点、分词、特殊符号和句子边界，这些情况下的工程处理尚未讨论。
