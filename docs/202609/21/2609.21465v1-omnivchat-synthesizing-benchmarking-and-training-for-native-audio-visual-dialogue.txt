ABSTRACT
We deﬁne OmniVChat (Omni Video Chat) as the task of native audio-visual di-
alogue between a user and an omni model. In OmniVChat, omni models directly
and simultaneously receive audio and video from a user and return text. The user’s
query is embedded in the audio and video, without a separate text question, exter-
nal captioning, or speech recognition. Direct audio-visual input reduces external
latency and computation while preserving perceptual cues. However, research on
OmniVChat faces two constraints: data availability and evaluation. Recordings of
people using their own devices are scarce. Furthermore, a good reply often needs
to account for the user’s surroundings, facial expressions, and nearby objects,
and such responses can be expressed in many different ways, making keyword
matching unreliable for evaluating reply quality. Recent progress in agent systems
and video generation makes generation for comprehension viable, which means
using synthesized dialogues for training and evaluation. Therefore, we present
OmniVChat-Studio, a multi-agent data engine for synthesizing single- and multi-
turn audio-visual dialogues. We use synthesized dialogues to build OmniVChat-
Bench, an evaluation benchmark that evaluates omni models’ basic dialogue abil-
ities across ﬁve ability categories. We also present OmniVChat-RL, a reinforce-
ment learning reward design that jointly targets reply correctness, efﬁciency, and
style in OmniVChat. Training Qwen3-Omni-Instruct with OmniVChat-RL on
synthesized dialogues improves its performance on both OmniVChat-Bench and
the human-recorded OmniVChat-Bench-Human. These gains validate the re-
ward design and show transfer to real-world dialogues in training and evaluation.

INTRODUCTION
We deﬁne OmniVChat (Omni Video Chat) as the task of native audio-visual dialogue between
a user and an omni model (Jiang et al., 2025). In OmniVChat, omni models directly and simul-
taneously receive audio and video from a user and return text. The user’s query is embedded in
both inputs, without a separate text question or external captioning or automatic speech recognition
(ASR) (Prabhavalkar et al., 2023). Direct audio-visual input reduces external latency and computa-
tion while preserving acoustic and visual cues. However, research on OmniVChat faces two con-

straints: data availability and evaluation. The ﬁrst challenge is limited data availability. Open-source
recordings of people using their own devices are scarce. Noise, camera motion, and device posture
create a long tail of input conditions. The second challenge is evaluating reply quality. Dialogues
contain complex scenes and many rare cases, where a good reply should account for rich multi-
modal context such as the user’s environment, facial expressions, emotion, nearby objects and so
on. Because such information can be expressed in various ways, it is difﬁcult to reliably assess reply
quality through keyword matching or other rule-based methods. Few datasets and benchmarks target
this native dialogue (Pourreza et al., 2026; Lu et al., 2026). Models thus tend to rely on external
components such as ASR cascades (Yao et al., 2026). While practical, these designs inevitably omit
subtle prosody and vocal affect, and add latency, computation, and potential transcription errors.
Progress in agent systems (Dorri et al., 2018; Yang et al., 2025) and video generation (Xing et al.,
2024; Ma et al., 2025) makes generation for comprehension possible. This means using synthe-
sized dialogues for training and evaluation. Our contributions are as follows. First, we present
OmniVChat-Studio, a controllable and extensible multi-agent data engine for synthesizing native
audio-visual dialogue data at scale for training and evaluation. It contains four agents that synthesize
single- and multi-turn dialogues using a conﬁguration for each subcategory. Second, we introduce
OmniVChat-Bench, an evaluation benchmark that evaluates omni models’ basic dialogue abilities
across ﬁve ability categories. Each instance includes a rubric. A rubric contains several tiers, and
each tier has one or more criteria. A large language model checks whether the reply meets each
criterion. Tier 0 checks whether the reply uses the user’s language. It gives no points, and failing it
makes the rubric score zero. In later tiers, a criterion earns one point only after every criterion in all
earlier tiers is met. Example 1 below shows how these rules apply to one instance. Third, we present
OmniVChat-RL, a reinforcement learning (RL) reward design that jointly targets reply correctness,
efﬁciency, and style in OmniVChat (Kaelbling et al., 1996). A rubric reward for reply correctness is
ﬁrst introduced using the same scoring method as in evaluation, followed by two additional reward
terms for efﬁciency and style. OmniVChat-Bench-Train serves as the training corpus synthesized
by OmniVChat-Studio for OmniVChat-RL, whereas OmniVChat-Bench-Human provides a man-
ually recorded benchmark for testing transfer to real-world dialogues. Fine-tuning Qwen3-Omni-
Instruct (Xu et al., 2025b) with OmniVChat-RL on OmniVChat-Bench-Train yields consistent per-
formance gains across both OmniVChat-Bench and OmniVChat-Bench-Human, while simultane-
ously making responses more concise. These gains validate the OmniVChat-RL and demonstrate
successful transfer to real-world dialogues. Given that the two benchmarks overlap across single-
turn subcategories, consistent gains in these shared areas suggest that the synthetic and recorded
dialogue distributions are well aligned.
The paper is organized as follows. Section 2 describes the OmniVChat-Studio framework and its
single-turn and multi-turn subsystems. Section 3 presents OmniVChat-Bench for evaluating basic
dialogue abilities. Section 4 presents OmniVChat-RL and the training results. Appendix B provides
an overview of the related work.

OMNIVCHAT-STUDIO: SYNTHESIZING DIALOGUES FROM CORPUS
We present OmniVChat-Studio, a multi-agent data engine that takes a text corpus as input and syn-
thesizes native audio-visual dialogue data. The resulting data contain rendered audio-visual clips,
the corresponding reference replies, and rubrics for scoring model replies. OmniVChat-Studio con-
sists of two subsystems, as shown in Figure 2. The single-turn subsystem on the left synthesizes
one-turn dialogue data. The multi-turn subsystem on the right synthesizes a sequence of dependent
turns, where later turns use accepted earlier clips and dialogue as history.
Both subsystems use the four agents shown in the lower-left legend of Figure 2. Each module has
the same color as the agent responsible for it. The Director handles all text-based input and output
tasks. The Renderer turns an accepted prompt and any media references into a synchronized audio-
visual clip. The Reviewer examines the rendered audio and video, writes a caption and quality
report, and answers focused questions when more evidence is needed. The deterministic Validator
checks structured scripts or dialogue records against the conﬁgured rules and returns either a pass or
a list of rule violations.

MULTI-TURN SUBSYSTEM
The multi-turn subsystem handles dependencies across turns. This subsection focuses on its main
differences from the single-turn subsystem. The right side of Figure 2 shows these changes, and
Example 3 in Appendix C.2.2 matches the modules circle by circle in one real run.
Unlike the single-turn Plan & Review 2 , the multi-turn subsystem separates Plan b from Plan
Review c . Plan b expands the storyline into a joint plan that speciﬁes every turn and selects the
earlier clips, audio, or ﬁnal frames used by later turns within a reference budget. Plan Review c
checks all turns and media links in a separate Director call, then accepts the plan, requests revision,
or discards the run. In Example 3, circles b and c plan the return to the same room, then correct the
language, media link, and ﬁnal silent wait.
The multi-turn subsystem also replaces the single-turn Script Generation 3 and Video Plan 7 with
per-turn Prompt Generation d . This module writes a rendering prompt for each turn based on
the reviewed joint plan and shared rendering instructions. It uses the available media identiﬁers as
placeholders for earlier clips, audio, or ﬁnal frames. Prompt Review e checks the prompt and its
media links before rendering, then accepts it, requests a local rewrite, or requests a plan update. In
Example 3, circle d links the Turn 2 prompt to the Turn 1 clip, while circle e repairs the denser Turn
1 prompt and accepts the Turn 2 prompt.

Dialogue-State & Link Perception (DSLP) evaluates whether a model understands the current state
of a dialogue. It covers connection status, turn boundaries, and camera orientation. For example, the
model should wait when a user pauses before ﬁnishing a request and interpret left and right from the
current camera view. Multimodal Entity Alignment (MEA) evaluates whether a model connects
speech with the correct visible objects and speakers. For example, the model should identify the cup
indicated by a gesture and address the active user when several people are speaking. Model Self-
Awareness (MSA) evaluates whether a model states its identity and physical limitations correctly.
For example, it should not claim that it can move an object, but it can explain what the user can
do instead. Anti-Hallucination (AH) evaluates whether replies remain grounded in the available
audio and visual evidence. For example, the model should say when a requested object is absent or
correct a false description of a visible object’s color. Emotion Recognition (ER) evaluates whether
a reply uses facial and vocal emotion cues. For example, a worried expression and tone should lead
to a reply that addresses both the user’s emotion and request. Appendix D.4 compares model scores
on matched single-turn and multi-turn subcategories. The recorded probe contains only single-
turn dialogues and does not test live interruption; Appendix D.2 describes the procedures for both
recording and annotating these dialogues.

OMNIVCHAT-RL: REWARDS FOR BETTER DIALOGUE
We present OmniVChat-RL, an RL reward design that jointly targets reply correctness, efﬁciency,
and style in OmniVChat. These three reply-quality signals also deﬁne the evaluation metrics. An
auxiliary format term is used only during training to require a valid reply. Training and evaluation
use separate dialogues from the same subcategory conﬁgurations. OmniVChat-Bench measures
training gains, while recorded dialogues test transfer. Matched gains can indirectly suggest aligned
distributions across the shared single-turn subcategories (§4.3).
4.1
TRAINING SETUP
To support training and test generalization to real-world dialogues, we introduce two datasets.
OmniVChat-Bench-Train contains 5,600 training dialogues and a separate 560-dialogue devel-
opment split. Each dialogue and its rubric are synthesized by OmniVChat-Studio. Development
scores select the checkpoint. OmniVChat-Bench-Human contains 360 human-recorded single-
turn dialogues for testing transfer to real-world dialogues (recording and annotation procedures in
Appendix D.2). It is used only for evaluation. The base model is the Thinker of Qwen3-Omni-30B-
A3B-Instruct. It has video and audio encoders and a text decoder.

CONCLUSION
We deﬁne OmniVChat as the task of native audio-visual dialogue between a user and an omni
model. We present OmniVChat-Studio, a multi-agent data engine that synthesizes single- and
multi-turn audio-visual dialogues from a subcategory conﬁguration and a text corpus. It supports
single-turn probes and dependent turns, with reference replies and tiered rubrics. We introduce
OmniVChat-Bench, an evaluation benchmark that evaluates omni models’ basic dialogue abilities
across ﬁve ability categories. Its 17 subcategories use these rubrics. We also present OmniVChat-
RL, an RL reward design that jointly targets reply correctness, efﬁciency, and style in OmniVChat.
Training on 5,600 synthetic dialogues raises OmniVChat-Bench from 0.465 to 0.652. The recorded
OmniVChat-Bench-Human rises from 0.402 to 0.632 without training on its recordings. Mean reply
length falls from 79 to 36 words. RE rises from 5.75 to 18.38, and Style rises from 0.710 to 0.992.
These results support the training design and the use of synthetic data for training and evaluation
in real-world dialogues. The components connect controlled synthesis, semantic evaluation, and
training within one task. Agreement across synthetic and recorded dialogues indirectly suggests
aligned dialogue distributions for the shared single-turn subcategories.

AGENTIC VIDEO AND AUDIO GENERATION
Agentic generation systems coordinate specialized agents across planning, generation, evaluation,

AniMaker (Shi et al., 2025) uses four specialized agents, MCTS-inspired candi-

B.5
RL ALGORITHMS
Recent RL methods use different policy objectives and reward sources. Proximal policy optimiza-
tion (PPO) (Schulman et al., 2017) uses a clipped surrogate objective. It supports several minibatch
updates from one batch of sampled trajectories. Instruction tuning with human feedback (Ouyang
et al., 2022) starts with supervised demonstrations. It then applies RL from preference comparisons.
GRPO (Shao et al., 2024) estimates advantages without a separate value model. It uses the mean re-
ward for responses to the same prompt as a baseline. DeepSeek-R1-Zero (Guo et al., 2025) uses pure
RL. It develops reasoning behavior without human-labeled reasoning trajectories. DAPO (Yu et al.,
2026) uses asymmetric clipping bounds. It also resamples groups that have no learning signal. Dr.
GRPO (Liu et al., 2025a) changes group-relative optimization. The change removes biases linked
to response length and difﬁculty. GSPO (Zheng et al., 2025) uses sequence-likelihood importance
ratios and sequence-level clipping, which notably stabilizes mixture-of-experts training. Rubrics as
Rewards (Gunjal et al., 2026) grades responses with instance-speciﬁc rubrics. It builds rewards for
domains without directly veriﬁable answers.

C.1
DESIGN RATIONALE
First, the design keeps each sampled assignment ﬁxed during repair. Otherwise, a failed difﬁcult
dialogue could become an easier dialogue and change the requested batch distribution. The repair
budget limits the cost of retaining the original setting.
Second, observation and judgment remain separate. The Reviewer reports the rendered audio and
video. The Director compares this evidence with the plan. It then chooses the next action. The reply
follows the rendered evidence instead of the intended script.
Third, deterministic checks enforce rules in the conﬁguration before semantic review. The synthesis
prompt and Validator use the same rules. Validation Review 5

C.2.2
SUPPLEMENTARY STAGE CHECKS, REPAIRS, AND MULTI-TURN TRACE
Beyond the stage interfaces in §2.1 and §2.2, both subsystems apply target-speciﬁc checks and
repair rules. Some rules depend on sampled values. A completed-turn probe requires a completion
cue near the clip end. A mid-dialogue probe may forbid an explicit report of a dropped line or the
word again. Rear-facing mode may forbid the phrase facing the camera. These rules prevent an
instance from revealing the subcategory under evaluation.
Plan & Review 2 also checks object presence and conﬂicts between speech and visible facts. It
checks whether the user yields the turn. Script Generation 3 writes contiguous timed segments. Its

prompt includes the validation rules before drafting. Validation 4 checks the speaking rate for each
language, timeline continuity, and every value in the conﬁguration.
Validation Review 5 checks reported violations in context. A forbidden word may occur within an
unrelated compound. A device may appear only in ambient sound. Fast speech may be appropriate
during an argument or emergency. If every report is a contextual exception, the subsystem retains the
script. Otherwise, the violations and earlier errors return to Script Generation 3 . An unparseable
verdict also returns the script for revision.
Script Review 6 checks whether the script tests the target subcategory. It checks object presence,
false premises, visual necessity, and ofﬂine answerability. For example, a red-and-white cup can
make red cup ambiguous. A question that audio alone can answer does not test visual grounding. A
pass ﬁnalizes the script. A repairable defect returns to drafting. The subsystem discards the whole
instance when the defect cannot be repaired.
Video Plan 7 selects prompt fragments for continuous motion, camera constraints, plausible bodies,
lip synchronization, and no subtitles. A fragment can conﬂict with the sampled scene. For example,
a clear-face rule conﬂicts with a camera that faces away from the user. Strong backlight may also
hide facial detail by design. The Director selects compatible fragments. If this selection cannot be
parsed, the system includes all fragments.

D.1.1
HUMAN INSPECTION OF THE DELIVERED SUITE
Instances accepted by OmniVChat-Studio receive two additional checks before delivery. Audio
post-processing repairs recurring tail artifacts (Appendix D.1.2). Human inspectors then reject any
remaining defect. Thus, every delivered instance passes the synthesis gates, audio repair, and human
review before it enters the benchmark.
Human inspection checks whether each clip shows the intended dialogue. OmniVChat-Studio al-
ready checks timelines, banned words, and scripted speaking rates. It also limits each repair route
and rejects runs that exhaust a budget. Its semantic gates use the Reviewer’s description and the
Director’s judgment. These agents can make the same error. Human inspection detects such cases.
D.1.2
TAIL-ARTIFACT DETECTION AND REPAIR
Audio post-processing addresses two recurring defects. One is a broadband click near the clip
end. The other is a sudden cutoff during active sound. A click forms a narrow vertical band in a
20


Under Review
spectrogram. It can extend above 16 kHz, where the codec removes most speech and room sound. A
cutoff ends active sound without a natural fade. Both defects affect the waveform used for evaluation.
Detection combines ﬁxed measurements with model-based ranking of waveform and spectrogram
panels. The audio is ﬁrst decoded to mono. The procedure then locates the end of non-silent content.
A transient score compares the ﬁnal 150 ms with the preceding second across frequency bands.
A truncation score measures the remaining loudness and fade. A model ranks six candidate tails
together. Isolated judgments often ﬂag valid tails and report unsupported measurements. Repair
therefore uses the relative severity tier supported by both methods. In the strong tier, the model ﬂags
654 of the 692 clips found by the ﬁxed measure.

D.2
CONSTRUCTION OF OMNIVCHAT-BENCH-HUMAN
OmniVChat-Bench-Human tests the transfer claim in §4.3 with 360 human recordings. Each of the
twelve single-turn subcategories has 30 instances. The ﬁve multi-turn subcategories are outside its
scope. Figure 6 uses the layout of Figure 3 to show this composition.
Construction starts with an actor guide for each of the twelve single-turn subcategories. Each guide
explains the dialogue in plain Chinese. It also lists probe variants and everyday scenes. An op-
tional synthetic clip can illustrate the dialogue. Performers do not need to copy its exact content or
rendering quality. Each performer selects one variant and improvises the dialogue. The dialogue
is recorded on a phone in a real setting. All 360 recordings are in Chinese. Performers receive no
clip-level script. Thus, unlike synthesized dialogues, the records have no timeline, scene setup, or
conﬁguration block. Appendix F.1 shows these ﬁelds for synthetic examples.

clear speech and usable audio and video. Recordings that fail are corrected or recorded again, then
rechecked. Only accepted recordings enter annotation. This process applies the same subcategory
deﬁnitions to human speech and real settings. It preserves natural framing and performance. The
probe tests whether the same subcategories transfer to recorded dialogues.

on different evidence, and a third includes a transcript. The annotation process merges them into

D.5
DETAILED SUBCATEGORY DEFINITIONS
The benchmark contains 17 subcategories: twelve single-turn subcategories and ﬁve multi-turn ex-
tensions. The single-turn set has 2,550 instances, each with one clip for one user turn. The multi-turn
set has 250 instances and adds memory, retrieval, or updates across turns. The following deﬁnitions
cover all 17 subcategories under the ﬁve ability categories in §3.
Voice-Connectivity Conﬁrmation (VCC). Initial Connectivity Conﬁrmation (ICC) tests opening
connection checks. Mid-Dialogue Connectivity Conﬁrmation (MDCC) extends ICC to later con-
nection checks. Its reply conﬁrms the connection and remains consistent with the earlier dialogue.
Fixed clips use direct questions rather than simulate random link loss.
Voice Turn-Taking (VTT). User Paused but not Completed (UPC) tests an unﬁnished request amid
visual distraction and calls for waiting or a brief acknowledgment. User Completed Request (UCR)
tests a completed request under similar distraction and calls for an answer.
Visual Dialogue-Mode Cognition (VDMC). Single-turn Visual Mode Recognition (SVMR) tests
user-relative left and right. In these tasks, the user’s left and right map to the opposite image sides
when the camera faces the user. They map to the same image sides when the camera faces out-
ward. Multi-turn Visual Mode Switching (MVMS) extends SVMR by testing the updated left-right
mapping after a camera change.
Reference Comprehension (RC). Anaphoric Reference (AR) resolves pronouns and gestures,
while Descriptive Reference (DR) resolves spoken descriptions. Multi-turn Reference Retrieval
(MRR) extends both AR and DR by testing recall of information about an object shown earlier. The
object leaves the current view, and other topics are discussed before the ﬁnal query. The answer
therefore uses earlier visual evidence.
Speaker Diarization & Identiﬁcation (SDI). Single-turn Primary Speaker Disambiguation (SPSD)
identiﬁes the main user among competing voices. Multi-turn Interactor Shift Tracking (MIST) ex-
tends SPSD to changes in the active user. The reply addresses the person who takes over the dia-
logue.
Identity Consistency (IC). Single-turn Identity Consistency (STIC) tests correct model identity in
one turn. Multi-turn Identity Consistency (MTIC) extends STIC to identity questions across turns,
including misleading user claims. The reply reﬂects the model’s true identity despite those claims.
PLA, AOR, FGC, and ER are themselves subcategories. Their deﬁnitions are in §3. The ﬁve multi-
turn extensions use the subsystem in §2.2. Figure 3 shows their turn counts and durations.
