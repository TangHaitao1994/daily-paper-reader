## 摘要
我们介绍了 NemotronLabs VoiceChat，一个具备原生工具调用能力的开源全双工语音到语音模型。NemotronLabs VoiceChat 将流式语音编码器和仅解码器语言模型与并行专用输出流（用于智能体文本和结构化函数调用）、用于增量用户转录的辅助 RNN-T 分支以及流式 TTS 解码器相结合。这种设计使模型能够在统一的流式架构中听、转写、推理、调用工具和说话，同时保持自然对话所需的时序行为。在 Full-Duplex-Bench 1.0 上，NemotronLabs VoiceChat 在已评估的开源权重系统中实现了最低的停顿处理接管率，用户打断后实现 100% 接管，打断后响应质量评分为 4.33/5。在 Full-Duplex-Bench 1.5 上，它在 93% 的情况下会在用户发出反馈（backchannel）后恢复响应。NemotronLabs VoiceChat 在 VoiceBench 上获得了 55.1 的标准化平均分，并在 Full-Duplex-Bench 3.0（FDB 3.0）上实现了 82.5% 的工具选择 F1 分数，而参数准确率和端到端工具执行仍有待改进。这些结果表明，全双工交互、语音识别与生成、通用语言能力以及外部工具使用可以集成到单一的开源语音到语音模型中，而不会牺牲实时对话行为。

## Abstract
We introduce NemotronLabs VoiceChat, an open full-duplex speech-to-speech model with native tool-calling capabilities. NemotronLabs VoiceChat combines a streaming speech encoder and decoder-only language model with parallel specialized output streams for agent text and structured function calls, an auxiliary RNN-T branch for incremental user transcription, and a streaming TTS decoder. This design enables the model to listen, transcribe, reason, invoke tools, and speak within a unified streaming architecture while preserving the temporal behavior required for natural conversation. On Full-Duplex-Bench 1.0, NemotronLabs VoiceChat achieves the lowest pause-handling takeover rates among evaluated open-weight systems, 100\% takeover following user interruptions, and a 4.33/5 post-interruption response-quality score. On Full-Duplex-Bench 1.5, it resumes its response after user backchannels in 93\% of cases. NemotronLabs VoiceChat obtains a 55.1 normalized average on VoiceBench and, on Full-Duplex-Bench 3.0 (FDB 3.0), achieves 82.5\% tool-selection F1, while argument accuracy and end-to-end tool execution remain areas for improvement. These results demonstrate that full-duplex interaction, speech recognition and generation, general language capabilities, and external tool use can be integrated in a single open speech-to-speech model without sacrificing real-time conversational behavior.

## 1. 论文的核心问题与整体含义

- **问题背景**：传统语音助手多采用级联式 ASR–LLM–TTS 架构，且大多为半双工：依赖 VAD 检测用户说完后才响应，无法自然处理打断、重叠、反馈（backchannel）和实时轮换。
- **核心挑战**：全双工语音交互要求模型在“听”的同时“说”，并能在统一流式系统中完成识别、生成、推理和工具调用；开源模型在工具调用与全双工特性结合方面研究较少。
- **本文目标**：提出并开源 **NemotronLabs VoiceChat**（文中也称 V-Model），一个统一的全双工语音到语音模型，原生支持结构化工具调用，同时保持低延迟和自然对话时序。

## 2. 方法论

### 2.1 整体架构
- 由四部分组成：流式语音编码器、仅解码器 LLM、辅助 RNN-T 转录分支、流式 TTS 解码器。
- LLM 输出两条**并行专用流**：智能体文本（agent text）和结构化函数调用（function call），避免将异质动作串行化到同一输出流，从而保持低延迟。

### 2.2 语音识别与理解（STT）
- 语音编码器：600M 参数、24 层 Cache-aware FastConformer，隐藏维度 1024，因果卷积与 70 帧左上下文注意力，无右上下文；下采样 8 倍，每 80 ms 产生一个状态。
- LLM 骨干：**NVIDIA Nemotron-Nano-9B-v2-Base**。
- 编码器输出分两路：原始 FastConformer 状态用于 RNN-T 分支；经模态适配和投影后进入 LLM。
- RNN-T 包含两层 640 维预测网络和 640 维联合网络，预测 1024 BPE 词汇加 blank，输出增量用户转录，不作为 LLM 输入以保持直接语音条件路径。

### 2.3 工具调用通道
- 独立的自回归**函数通道**与文本通道并行；每帧融合编码音频、前一文本 token 嵌入和前一函数 token 嵌入（权重 1、1、2）。
- 通道协议：无工具时输出 padding（负监督防止误触发）；需要工具时生成 `<SOTC>`（Start of Tool Call）开始调用段、`<EOTC>` 结束调用、`<EOTR>` 结束工具响应。
- 调用格式为 JSON 列表：`[{"name": tool_name, "arguments": tool_args}]`，可支持多工具并行调用。
- 训练时工具响应 token 作为上下文但不计算损失；推理时工具执行期间用预定义的确认消息（“filler message”）填充智能体文本，避免长时间静默。

### 2.4 TTS 解码器
- 基于 **VoiceChat-TTS**，是一个持续流式 TTS，不因单轮响应重新初始化，全程跟踪对话时间线。
- 声学骨干：778M 参数 Gemma 3 解码器 + 199M 因果音频编解码器，共 977M 参数；编码 22 kHz 音频为 12.5 Hz、31 层 RVQ 的声学 token，每帧对应 80 ms。
- 使用 **Mixture-of-Gaussians 估计头**一次预测多个 RVQ 层级，减少顺序解码深度（实际使用 4–8 次细化迭代）。
- 文本表示采用 Character-Aware Subword Encoder，将子词分解为字符后平均池化，提高生僻 token 的发音一致性。
- 支持显式 BOS 和 interruption token 控制轮换与打断；可注入固定静音 token 实现确定性停止。

### 2.5 训练目标与数据
- 两阶段：持续预训练（CPT）和监督微调（SFT）。
- 目标函数：  
  \(\mathcal{L}_{\text{STT}} = (1 - \lambda_{\text{T2T}})(\lambda_{\text{text}}\mathcal{L}_{\text{text}} + \lambda_{\text{FC}}\mathcal{L}_{\text{FC}}) + \lambda_{\text{T2T}}\mathcal{L}_{\text{T2T}}\)  
  SFT 中 \(\lambda_{\text{text}}=1, \lambda_{\text{FC}}=1, \lambda_{\text{T2T}}=0.5\)；CPT 中 \(\lambda_{\text{text}}=3, \lambda_{\text{FC}}=1, \lambda_{\text{T2T}}=0\)。
- 加权交叉熵：文本通道权重（SFT：开始 12.5、结束 7.5、内容 5.0、padding 1.0）；函数通道权重（`<TOOLCALL>` 内容 64、`<SOTC>`/`<EOTC>` 各 6、`<EOTR>` 3、padding 0.3），通过上采样稀疏 token 学习轮换与工具协议。
- 数据构造：CPT 将文本段落交替为伪对话并用 TTS 合成；SFT 加入指令、对话、工具调用和安全数据，并包含在线增强（早期打断、backchannel 注入、文本通道延时 160 ms、噪声/RIR/编解码增强）。

- 附录还评估了 ASR（Hugging Face OpenASR Leaderboard 8 个数据集）、TTS 质量（LibriTTS 多轮稳定性）、安全性（AdvBench 拒答率）和推理效率。
