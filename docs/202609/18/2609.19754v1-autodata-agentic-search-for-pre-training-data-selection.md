## 摘要
近年来，LLM 智能体在通过执行反馈修改模型与训练代码来自动化机器学习工程方面展现出前景。然而，数据在很大程度上仍处于这一智能体优化循环之外。我们将预训练数据选择形式化为对每篇文档特征（即词汇统计、类别标签和困惑度）的启发式工程。我们提出 AutoData，一个直接对可执行选择算法进行搜索的智能体。与以往在固定领域集合上优化权重的数据混合方法不同，AutoData 在评分、分层和随机选择规则构成的更丰富程序空间中搜索，并通过代理模型的验证反馈迭代优化算法来自动发现特征交互。在一次过夜搜索中，AutoData 发现了一种优于现有人工设计数据策展流程的选择算法。尽管该算法仅在小规模代理模型上搜索得到，但发现的数据配方可迁移至更大规模并提升下游指标 CORE。这些结果表明，数据工程可被视为一个智能体机器学习问题，将自主研究从模型和训练代码优化扩展到数据。

## Abstract
LLM agents have recently shown promise in automating machine learning engineering by editing model and training code under execution feedback. Data, however, remains largely outside this agentic optimisation loop. We frame pre-training data selection as heuristic engineering over per-document features, i.e., lexical statistics, categorical labels, and perplexity. We introduce AutoData, an agent that searches directly over executable selection algorithms. Unlike prior data mixture methods that optimise weights over a fixed set of domains, AutoData searches a richer program space of scoring, stratification, and stochastic selection rules, discovering feature interactions automatically by iteratively refining algorithms with validation feedback from a proxy model. Within an overnight search, AutoData discovers a selection algorithm that outperforms existing human-designed curation pipelines. Despite being searched only on this small proxy, the discovered recipe transfers to larger scales and improves the downstream metric CORE. These results suggest that data engineering can be treated as an agentic machine learning problem, extending autonomous research from model and training-code optimization to the data.

- **搜索信号**：分别使用 validation bits-per-byte（val-bpb）和下游 CORE 作为优化目标，各运行单独搜索。

## 6. 论文的主要结论与发现

- **AutoData 可发现优于人工基线的方法**：在 val-bpb 上，AutoData 配方从 depth=8 到 20 显著优于全部 4 个基线；在 CORE 上多数尺度优于基线，但统计上不显著。
- **人工设计方法在已高质量策展的数据池上失效**：DCLM、PPL 过滤、RegMix 未能一致改善 val-bpb 或 CORE，说明这些方法对源数据池敏感，需要重新设计。
- **发现的方法具有多样性保持机制**：AutoData 配方普遍包含随机骨干、锦标赛/分层配额等选择规则，而非简单的全局 Top-B 或硬阈值过滤；评分聚合上偏好复合规则（线性或乘法），并采用特征交互（如多样性门控困惑度）。
- **不同 LLM 智能体策略偏好差异明显**：GPT-5.5 偏好乘法复合 + 锦标赛选择；Gemini-3-Pro-Preview 和 Claude-Opus-4.7 偏好线性复合 + 分层配额；所有智能体都避免单特征评分。
- **特征空间的影响**：LLM 注释特征带来最佳结果，但仅使用 cheap features（词汇、困惑度、类别）也能获得 +1.8–2.1σ 的提升，表明一个小的、精心选择的特征集已足够支撑有效搜索。
- **可迁移性**：小代理模型上搜索到的配方可迁移到更大模型（125M–897M 的 val-bpb 保持优势），但到 1.3B 时优势消失，接近默认 ClimbMix。

## 7. 优点

- **首次将数据选择纳入智能体优化循环**：突破以往“数据静态”的假设，扩展了自主研究的边界。
- **搜索空间丰富、可解释**：直接搜索可执行算法，而非仅优化领域权重，能发现特征交互和多样性保持规则。
- **实验设计严谨**：固定选择预算、统一的两阶段协议、多训练种子、配对 t 检验，比较公平。
- **分析深入**：对生成配方进行特征使用、操作分类等多角度剖析，提供了有价值的可解释性洞察。
- **低成本、可迁移**：仅需小规模代理搜索即可发现跨尺度有效的配方，实用性强。

## 8. 不足与局限

- **数据与规模局限**：仅在 ClimbMix 单一英语语料上验证，最大模型 1.3B 参数，泛化到其他语料、领域和更大规模仍未知。
- **CORE 提升不显著**：下游 CORE 方差大，AutoData 的优势大多缺乏统计显著性，方法论上仍有局限。
- **代理目标依赖性**：优化 val-bpb 和优化 CORE 得到的配方不同，说明搜索信号的选择至关重要；若代理目标选择不当，可能无法反映真实需求。
- **LLM 注释成本高**：最强增益涉及 LLM 生成的语义注释（事实错误、推理步骤等），其注释成本不可忽视，成本-质量权衡需要进一步研究。
- **大规模迁移有限**：depth=24 时 AutoData 与默认 ClimbMix 表现相当，说明代理搜索在大规模上的收益可能衰减。
- **搜索开销大**：虽然单次代理训练较快，但整个搜索需数百次代理训练，总 GPU 成本可观；论文未提供总成本统计。
- **潜在偏差**：使用固定参考模型（Qwen2.5-0.5B）计算困惑度，以及依赖特定分类器，可能引入模型偏差。
