## 摘要
记忆是对话代理的核心组件，使其在长时间交互中表现出连贯且具有上下文感知的行为。近期方法通常依赖基于LLM的记忆构建，将原始交互重写为结构化记忆单元，随后通过RAG流水线进行检索。虽然在受控环境中有效，但我们表明该范式在长时程、高熵对话中会出现问题：随着上下文长度和信息复杂度的增长，记忆构建变得越来越有损且不稳定，并由于重复调用LLM而产生高昂成本。为解决这些局限性，我们提出Threader，一种将重点从记忆构建转向对原始交互进行高效、结构感知访问的记忆系统。Threader不再重写交互，而是将其作为一等记忆保留，通过轻量级增量分割将其组织为主题连贯的片段，并通过多视图表示实现精确检索。在查询时，它执行多信号检索，结合片段级访问与局部证据匹配，确保完整性与连贯性。大量实验表明，Threader持续提升答案准确率和证据召回率，同时显著降低记忆构建开销。

## Abstract
Memory is a core component of conversational agents, enabling coherent and context-aware behavior over long interactions. Recent approaches commonly rely on LLM-based memory construction, where raw interactions are rewritten into structured memory units and later retrieved via a RAG pipeline. While effective in controlled settings, we show that this paradigm breaks down in long-horizon, high-entropy conversations: memory construction becomes increasingly lossy and unstable as context length and information complexity grow, and incurs prohibitive cost due to repeated LLM invocation. To address these limitations, we propose Threader, a memory system that shifts the focus from memory construction to efficient, structure-aware access over raw interactions. Instead of rewriting interactions, Threader preserves them as first-class memory, organizes them into topic-coherent segments via lightweight incremental segmentation, and enables accurate retrieval through multi-view representation. At query time, it performs multi-signal retrieval that combines segment-level access with localized evidence matching, ensuring both completeness and coherence. Extensive experiments demonstrate that Threader consistently improves answer accuracy and evidence recall, while significantly reducing the memory construction overhead.

## 1. 论文的核心问题与整体含义

- **研究背景**：对话代理依赖长期记忆来维持跨多轮交互的连贯性、个性化与上下文感知。现有主流范式是“基于 LLM 的记忆构建”：将原始交互重写、摘要或抽取为结构化记忆单元，再通过 RAG 流水线进行检索。
- **核心问题**：该范式在**长时程、高熵的真实对话**中存在两个根本缺陷：
  - **记忆构建有损且不稳定**：随着会话长度增加、主题交错、证据稀疏分布，LLM 重写会丢失关键证据，导致下游问答精度下降（例如 Mem0 在会话拼接后准确率从 55% 降至 5%）。
  - **构建成本过高**：重复调用 LLM 进行记忆构建，产生大量 token 放大（100K 交互 token 下，A-Mem 放大 21 倍，EverMemOS 放大 13 倍），限制可扩展性。
- **整体含义**：论文主张**将设计重心从“记忆构建”转向“对原始交互的结构感知访问”**，即不再对原始对话进行有损抽象，而是将其作为一等记忆直接保留，通过高效的组织与检索来获取证据。

## 2. 论文提出的方法论

Threader 是一个面向长时程、高熵对话代理的记忆系统，其核心思想是**避免 LLM 重写，只做轻量级的结构组织和查询时检索**。系统包含三个关键组件：

### 2.1 增量主题连贯分割（Incremental Topic-Coherent Segmentation）
- 将交互流分割为语义连贯的“主题片段”，每个片段作为检索单元。
- 采用**流式二分类**：给定当前片段 \(s'\) 和新传入 turn \(t'\)，构建输入 \(x = \text{Concat}(s', [SEP], t')\)，预测标签 \(y \in \{0,1\}\)（CONTINUE 或 SEGMENT）。
- 使用**轻量 BERT 编码器**实现，支持在线增量处理，无需全上下文重算。
- 训练标签结合两类信号：
  - **硬标签**：来自会话边界；
  - **软标签**：由 LLM（GPT-4.1-mini）标注的会话内主题边界。

### 2.2 多视图片段表示（Multi-View Segment Representation）
- 针对对话中用户证据和助手内容异构的问题，为每个片段构建三个互补视图：
  - **用户视图** \(x^{(u)}\)：仅含用户消息；
  - **助手视图** \(x^{(a)}\)：仅含助手回复；
  - **全交互视图** \(x^{(f)}\)：用户-助手交替拼接。
- 三个视图通过共享编码器 \(f_{\text{enc}}\) 分别得到嵌入 \(e^{(u)}, e^{(a)}, e^{(f)}\)，避免用户侧弱信号被助手侧长内容掩盖。

### 2.3 多信号证据检索（Multi-Signal Evidence Retrieval）
检索分两阶段：

- **Stage I：高召回片段粗召回**
  - 融合**稠密语义信号**（三个视图的加权余弦相似度）和 **BM25 词法匹配信号**。
  - 取两者 top-\(K_1\) 结果的并集作为候选池 \(C\)。
- **Stage II：证据级精排序**
  - 在候选片段内，将稠密匹配从片段级细化为**消息级**：计算查询与每个用户/助手消息的相似度，取 top-\(K_2\) 平均作为细化稠密分数。
  - 将细化稠密分数与 BM25 分数按权重 \(\beta\) 线性融合，得到混合分；
  - 再用**交叉编码器重排**，按权重 \(\alpha\) 融合最终分数；
  - 最终选出 top-\(K\) 个**片段**作为证据，保持话语连贯性。

整体算法流程为：原始对话 → 增量分割 → 多视图索引 → 查询时粗召回 → 消息级精排 + 交叉编码器重排 → top-K 片段 → 响应生成。

## 3. 实验设计

### 3.1 数据集与评估场景
- **LongMemEval**：500 个 QA 实例，平均每会话约 2.16K token；覆盖单会话用户信息、单会话助手信息、偏好、多会话推理、知识更新、时间推理等六类问题。评估使用 **LLM-as-a-Judge**（GPT-4.1-mini，四分类：correct / partially_correct / incorrect / insufficient，仅 correct 计为正确）。
- **PersonaMem**：589 个 QA 实例（37 个样本），平均每会话约 26.17K token；覆盖新场景泛化、偏好对齐推荐、召回用户共享事实、召回用户提及事实、更新原因、新想法、偏好演化七类。评估采用 **exact match**（选项字母精确匹配）。

## 6. 论文的主要结论、局限性与未来工作

- **主要结论**：
  - Threader 通过“增量主题连贯分割 + 多视图片段表示 + 多信号证据检索”实现了对原始交互的结构感知访问，在 LongMemEval 和 PersonaMem 两个基准上均一致超越现有记忆构建类与 Agentic RAG 基线，验证了避免 LLM 记忆构建、直接检索原始证据的有效性。
  - 消融实验证实各组件均有贡献：主题连贯分割优于无分割或固定分块；多视图表示缓解了用户侧弱信号被助手长内容淹没的问题；稠密+BM25+交叉编码器重排的混合检索以及消息级细化显著提升证据定位精度。
  - 资源与成本分析表明，Threader 构建阶段无需调用 LLM，大幅降低了 token 放大和构建成本，查询延迟与基线可比或更低，证明了方法在长时程部署中的可扩展性。

- **局限性**：
  - 分割器基于轻量 BERT，训练数据规模和分布可能限制其在极端长会话、多语言或高噪声交互上的泛化能力。
  - 多视图权重、BM25 融合权重、重排融合权重等超参数依赖目标数据集上的网格搜索，实际部署时可能需要额外调参成本。
  - 在偏好建模、抽象概括等任务上，显式记忆构建方法可能更有优势，因为原始证据检索难以直接提炼用户的高层次偏好。
  - 评估基于静态 QA 数据集，未在在线对话代理中进行端到端验证，且部分实验仅报告单一指标，缺乏多次运行方差或统计显著性检验。

- **未来工作**：
  - 探索自适应分割策略和在线更新机制，以处理无限流式对话场景。
  - 研究更高效的超参数自动优化方法，或引入轻量策略网络动态调节检索参数。
  - 将 Threader 集成到端到端对话系统中，评估其在真实多轮交互中的表现与用户满意度。
