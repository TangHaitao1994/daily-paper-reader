## 摘要
全双工语音对话模型能够像人类对话的实时动态一样同时听和说。对于自然对话，实时搜索外部信息的能力同样重要。许多模型仍受困于参数化知识，无法访问实时信息和执行工具。此外，即使大语言模型（LLM）检索到信息，许多双工语音模型也是在压缩的潜在空间中处理这些信息，而非以其原始文本形式处理，这可能导致压缩造成的信息损失。为解决这一问题，我们提出 Context Spanning，这是一种通过实时分块预填充在全双工语音模型与外部 LLM 后端之间进行信息注入的框架。注入的帧在实时帧预算内通过单次前向传播进行编码，并将检索到的信息原样馈送给语音模型，使其能够独立地对信息进行推理并生成响应。借助该方法，我们的模型在全双工基准上取得了高性能，并在问答任务上获得了优异结果，展示了其对话潜力。Context Spanning 表明，外部信息可以直接注入双工语音模型，为双工系统引入了一种新的简单而强大的机制。

## Abstract
Full-duplex spoken dialogue models can listen and speak simultaneously like the real-time dynamics of human conversation. For natural dialogue, the ability to search for external information in real-time is also an important capability. Many models remain trapped in parametric knowledge, leaving them unable to access real-time information and tool execution. Furthermore, even when Large Language Models (LLM) retrieve information, many duplex speech models process it within a compressed latent space rather than in its raw text form, which can lead to information loss from compression. To address this issue, we propose Context Spanning, a framework for information injection between a full-duplex speech model and an external LLM backend via real-time chunked prefill. The injected frame is encoded in a single forward pass inside the real-time frame budget. It feeds the retrieved information to the speech model as-is, enabling it to reason over the information independently and generate responses. With this approach, our model achieves high performance on Full-Duplex benchmarks and strong results on Question Answering tasks, demonstrating its conversation potential. Context Spanning shows that external information can be injected directly into a duplex speech model, introducing a new simple and powerful mechanism for duplex systems.

## 2. 论文提出的方法论

- **总体 Pipeline**
  - 系统分为前端全双工语音模型和后端异步 LLM。
  - 前端使用代理文本、代理音频、用户音频进行实时双工推理，并与基于检索 token 的后端结合。
  - Context DB 初始化时可包含用户位置、时区等元数据；用户音频经实时 ASR 转写后不断累积到 Context DB。
  - 当前端预测到检索 token `<ret>` 时，后端基于 Context DB 执行 RAG、MCP、工具调用等任务。

- **Context Spanning 注入机制**
  - 后端返回结果后，信息被放在由 `<sos>` 和 `<eos>` 包围的 span 中注入语音模型。
  - 在 span 内部：
    - 代理语音设为静音；
    - 用户音频输入设为 440 Hz 正弦波；
    - 注入文本 token 直接作为模型输入，不需要自回归采样。
  - 由于 Moshi 架构完全由因果 Transformer 构成，span token 可以在单次前向传播中完成预填充，只更新 KV cache，后续解码即可使用。
  - 训练时，注入的 span 部分被排除在损失函数之外，避免模型学习到外部信息本身的生成任务。

- **声学延迟处理**
  - Moshi 的声学 token 比同一帧的语义 token 晚 τ 帧。
  - 为简化预填充，训练数据准备时在声学延迟应用之后注入 span；推理时也直接插入已经应用声学延迟的帧流中。

- **数字与文本处理**
  - 常规 Moshi 将数字拆成单个数字并采用 byte-backoff，但作者观察到这在因果推理中容易造成帧错位，尤其是大数字。
  - 因此，所有输入先使用 NeMo 文本归一化模型完全口语化，再进行 tokenization。

- **训练设置**
  - 从公开的 PersonaPlex-7B checkpoint 微调所有可训练参数。
  - 使用 AdamW，上下文长度 3000 帧。
  - 时间 Transformer 学习率 2e-6，深度 Transformer 学习率 4e-6。
  - 后端检索时，span 内容由 Gemma 4-26B-A4B 生成；延迟采样自 U(0.6, 2.0) 秒。

- 在问答任务中，尤其是数学推理数据集上，本文模型

表现显著优于 Vanilla Moshi 和 MoshiRAG，在参考文档提供时和最终响应正确率上均有明显提升；特别是在 GSM8K、SVAMP 等数学推理任务上，本文模型对精确数字的保留和推理能力更强，说明原始文本注入有效避免了潜在空间压缩带来的信息损失。
