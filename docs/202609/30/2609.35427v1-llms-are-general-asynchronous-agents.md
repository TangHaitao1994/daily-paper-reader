## 摘要
现代大语言模型作为自主智能体的能力日益增强，但它们仍遵循顺序交互循环：读取、思考、回复或调用工具，然后重复。许多现实世界用例并非顺序性的：语音助手、具身智能体以及监控系统会在它们思考或执行另一任务时接收新的输入。现代大语言模型通过针对语音交互和视频流的专用架构、用于机器人控制的视觉-语言-动作模型（VLA）、用于 API 使用的异步工具调用等方式来解决这一问题。在本工作中，我们将不同的异步任务推广为通用异步智能体，使其能够适应不同类型的并发。为此，我们开发了一个异步大语言模型框架，允许用户（或智能体自身）定义具有重叠内存状态的推理协程。我们展示了 Qwen 3.x 系列模型能够在无任务特定训练的情况下，对流式视频理解、电子游戏和监控等任务执行异步操作。

## Abstract
Modern LLMs are increasingly capable as autonomous agents, but they follow sequential interaction cycles: read, think, reply or call tools, repeat. Many real-world use cases are not sequential: voice assistants, embodied agents, and monitoring systems receive new inputs while they think or perform another task. Modern LLMs address this with specialized architectures for voice interaction and video streams, VLAs for robot control, asynchronous tool calling for API usage, and others. In this work, we generalize from different asynchronous tasks to general asynchronous agents that can adapt to different types of concurrency. To achieve this, we develop an asynchronous LLM framework that lets users (or the agents themselves) define inference coroutines with overlapping memory states. We showcase that Qwen 3.x models are capable of asynchronous operation for streaming video understanding, videogames, and monitoring, without task-specific training.

# 论文总结：LLMs are General Asynchronous Agents

## 1. 核心问题与整体含义
- 现代大语言模型（LLM）智能体通常遵循**顺序交互循环**：读取输入 → 思考 → 回复或调用工具 → 重复。这种串行模式无法很好地应对现实世界中大量存在的**并发与异步场景**。
- 语音助手需要在说话的同时听用户的新输入与打断；具身智能体需要在思考规划时实时响应环境变化；系统监控智能体需要持续处理日志流并及时报警。
- 现有解决方案往往为每个具体场景设计专用架构：如全双工语音模型、流式视频模型、视觉-语言-动作模型（VLA）、异步工具调用框架等，彼此割裂，且通常需要专门的训练或微调。
- 本文的核心思想是：**将异步性视为一种通用能力**，提出一个统一的、训练无关的异步 LLM 框架，让同一类模型（如 Qwen 3.x）无需任务特定训练即可适应多种并发场景。

## 2. 方法论
### 2.1 AsyncLLM 编程模型
- 基于 Python 的 `asyncio` 异步编程模型，允许用户（或智能体自身）定义多个并发执行的 LLM 推理协程（coroutine）。
- 每个推理协程向自己的**缓存块（CacheBlock）**写入内部记忆状态（注意力 KV 缓存 + Gated Delta Network 递归状态），同时可以通过**缓存视图（cache_view）**读取其他协程的缓存块。
- 协程之间通过共享缓存块实时“看到”彼此的进展，而不必像传统 token 通信那样反复重新编码。
- 结合 `asyncio` 的事件、锁、队列等同步原语，可表达中断、事件触发、子任务协调等异步行为。

### 2.2 多缓存块推断算法
- **全注意力 + RoPE**：借鉴已有工作，不重新排列过去 KV，而是对当前 query 按相对位置旋转，使注意力结果等价（公式：\(\langle \rho(q,i), \rho(k,j)\rangle = \langle \rho(q,i-j), k\rangle\)）。
- **线性注意力 / Gated Delta Networks（GDN）**：将每个缓存块的状态更新概括为仿射变换对 \((\hat{A}, \hat{B})\)，其中 \(\hat{A}\) 是该块内逐 token 状态转移矩阵的乘积，\(\hat{B}\) 是相应累加项。两个连续块的状态可直接通过矩阵乘法和加法组合：
  \[
  (\hat{A}_L, \hat{B}_L) \circ (\hat{A}_R, \hat{B}_R) = (\hat{A}_L \hat{A}_R,\ \hat{B}_L \hat{A}_R + \hat{B}_R)
  \]
  从而使任意缓存视图顺序可以在 \(O(N_\text{blocks})\) 而非 \(O(N_\text{tokens})\) 内完成状态拼接。该方法也可泛化到 KDA、标准线性注意力等所有状态更新为仿射的递归注意力。
- **多模态注意力（MRoPE）**：对图像/视频 token 的多维旋转位置编码，在缓存块拼接时保持空间轴不变，只在时间轴上对当前 query 做相对旋转校正，并显式记录每块的位置跨度。

### 2.3 推理引擎与调度
- 构建于 mini-SGLang 之上，支持批量并行推断，同时处理来自不同协程的 prefill 与 decode 请求。
- 采用**分块预填充（chunked prefill）**和**均衡调度**，避免快速反应协程被大型后台请求“堵塞”。
- 利用 Paged Attention 实现轻量级 CacheBlock，支持合并、清空、更新等操作。
- 支持 CUDA graphs、MoE 优化等，并兼容权重量化、KV 压缩、投机解码（作为未来方向）。

## 3. 实验设计
### 3.1 单次异步输入的健全性检验
- **文本异步输入**：使用 MATH-500-Sharded（500 道数学题，拆分为不完整提示 + 补全信息），在推理进行到第 k 步时插入澄清信息。
- **图像异步输入**：构建 ShardedVQA 数据集（513 对图像，来源包括 MathVista、MathVision、CharXiv、ChartQA、TabMWP、MapQA-U、CLEVR），先展示含有错误的图像，推理一段时间后替换为正确图像并告知输入已更新。
- 评估不同 k 值（16 到 512 步）下模型修正推理的能力，模型为 Qwen3.x 混合 MLLM。

### 3.2 流式视频理解
- **数据集**：SoccerNet-Caption（体育解说流式协议）和 ProactiveVideoQA（4 个子集：WEB、EGO、TV、VAD）。
- **Agent 架构**：事件探针（每帧判断是否有新事件）→ 背景思考协程（重建视频事件）→ 输出探针（判断思考中是否出现新事件）→ 描述生成协程 → 非 LLM 编译器。
- 探针不使用额外训练，直接以冻结 LLM 单次前向 + 预填模板完成。
- **对比方法**：Mage-VL（专门为流式视频训练的模型）。

### 3.3 交互式视频游戏 Agent
- **环境**：ViZDoom 的两个场景——HealthGathering 和 DeadlyCorridor（帧跳过 4）。
- **Agent**：背景思考模块决定行动策略，快速行动子程序逐帧执行；还评估了 agent 自己定义协程的方式。
- **对比基线**：顺序思考 agent（单段推理后行动）、仅探针 agent（每帧一次前向直接选动作）。
- 指标：平均奖励 vs. 平均延迟（从前一次观察到行动的前向次数），每场景 100 个回合。

### 3.4 系统监控 Agent
- **数据集**：DevOps-Gym 的 Monitoring 子集（34 个任务），检测内存泄漏、文件描述符失控等异常。
- Agent 以日志块（最多 1 秒或 1024 字符）形式持续接收流式日志。
- **对比基线**：顺序完整序列 agent、带提前回答工具的 agent、带跳过行策略的 agent。
- 指标：准确率、平均前向次数、平均处理的事件百分比。

## 6. 主要结论与发现
- 现代 MLLM 具备作为**通用异步智能体**的能力，无需任务特定训练即可处理多种并发场景。
- AsyncLLM 框架能统一支持文本、图像、视频、日志流等输入，并适配混合注意力（GDN）和多模态（MRoPE）架构。
- 在流式视频理解上，基于 Qwen 3.x 的 AsyncLLM 在 SoccerNet 和 ProactiveVideoQA 上**优于专门训练的 Mage-VL**。
- 在视频游戏和系统监控中，AsyncLLM 能以**明显更少的计算延迟**接近或达到串行智能体的性能，展现了实时响应优势。
- 智能体可以尝试**自行定义协程**（自我修改推理代码），但目前该能力尚不可靠，在 DeadlyCorridor 上表现较差。

## 7. 优点
- **高度通用**：一个框架覆盖语音、视频、游戏、监控等多种异步模式，减少重复设计。
- **训练无关**：直接使用现有 Qwen 3.x VLM，无需微调或额外数据。
- **算法创新**：将线性注意力状态更新转化为块级仿射组合，大幅降低多缓存块拼接开销；支持 MRoPE 多模态位置校正。
- **工程实用**：调度策略保证短任务不被长任务阻塞，分块预填充提升交互性。
- **可复现性**：提供参考实现和数据集，实验提示词、配置公开。
- **对比公平**：与专用模型和多种串行基线比较，并进行了超参数调优。

## 8. 不足与局限
- **自我定义协程不可靠**：智能体自动构建推理结构的能力仍不成熟，需要进一步研究。
- **准确率与速度的权衡**

- **准确率与速度的权衡**：在部分任务上，AsyncLLM 为追求低延迟而牺牲了部分准确率，例如在 ProactiveVideoQA 的某些子集和系统监控任务中，异步版本相比串行完整序列基线仍有差距，说明实时响应与推理深度之间存在固有张力。
- **模型与架构覆盖有限**：实验主要基于 Qwen 3.x 混合 MLLM，对其他纯 Transformer、非 GDN 或非 MRoPE 架构的适用性尚待验证；虽然文中给出了理论推导，但缺乏在更多架构上的实证结果。
- **对比基线范围有限**：虽然与 Mage-VL 和若干串行基线进行了比较，但未广泛纳入最新的专用异步语音/视频模型或商业系统，难以完全定位该方法在领域内的相对水平。
- **工程实现与可扩展性**：虽然报告了 1 到 32 个并发协程的吞吐与延迟，但未充分讨论大规模并发（如数百个协程）下的调度开销、显存占用和缓存块管理复杂度；对分布式多 GPU 场景也未涉及。

总体而言，该论文以统一、训练无关的异步框架解决了 LLM 智能体从串行到并行的关键瓶颈，理论推导扎实、实验覆盖多类真实场景，证明了通用异步能力的可行性与潜力。其主要贡献在于将 asyncio 编程模型与多缓存块推断算法结合，使同一种模型能应对多种异步任务，并展现了优于部分专用模型的实时性能。不过，如何平衡准确率与延迟、增强智能体自主构建异步逻辑的可靠性，以及扩展至更多模型架构和更大规模并发，仍是后续研究的重要方向。
