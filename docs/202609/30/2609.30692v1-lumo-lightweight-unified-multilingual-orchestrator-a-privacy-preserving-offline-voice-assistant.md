## 摘要
可靠的语音交互在互联网连接有限且隐私要求高的环境中至关重要。然而，现有的大多数语音助手依赖云端服务，这会导致延迟问题、对互联网接入的依赖以及隐私漏洞。本研究提出了 LUMO（轻量级统一多语言编排器），一种面向边缘计算环境的隐私保护离线语音助手。该系统将本地自动语音识别（ASR）、本地部署的量化大语言模型（LLM）和文本转语音（TTS）合成集成到一个完全离线的流水线中，运行在配备 8 GB 内存的 Raspberry Pi 5 上。为了在资源受限的硬件上高效运行，语言模型采用 4 位 GGUF 量化进行压缩，在保持实用对话能力的同时减少内存占用。现有的边缘语音助手 Mycroft 提供部分离线功能但不具备生成式大语言模型，延迟约为 5 秒，功耗约为 12 瓦；而 Rhasspy 支持完全离线运行但缺乏生成能力，延迟约为 3 秒，功耗约为 11 瓦。相比之下，LUMO 在低噪声条件下对短英语语音的词错误率（WER）为 6.8%，端到端响应延迟为 2.0-4.0 秒，峰值功耗更低，约为 9.0 瓦。该系统还实现了对孟加拉语语音的有效离线识别，支持低资源环境下的多语言可访问性。通过完全离线运行，LUMO 提供了强大的数据隐私保护，减少了对云连接的需求，并适用于隐私敏感的边缘场景，如农村医疗、教育和灾害响应。

## Abstract
Reliable voice interaction is essential in environments with limited internet connectivity and strong privacy. However, most existing voice assistants depend on cloud-based services, which leads to latency issues, dependency on internet access, and privacy vulnerabilities. This research presents LUMO (Lightweight Unified Multilingual Orchestrator), a privacy preserving offline voice assistant designed for edge computing environments. This system integrates local Automatic Speech Recognition (ASR), locally deployed quantized Large Language Model (LLM), and Text-to-Speech (TTS) synthesis into a fully offline pipeline running on a Raspberry Pi 5 with 8 GB RAM.   To enable efficient operation on resource constrained hardware, the language model is compressed using 4-bit GGUF quantization, which reduces memory usage while preserving practical conversational capability. Existing edge based voice assistants Mycroft provides partial offline functionality without a generative LLM, with an approximate latency of ~5 s and power consumption of ~12 W, while Rhasspy supports full offline operation but lacks generative capabilities, with ~3 s latency and ~11 W power usage. In contrast, LUMO achieves a Word Error Rate (WER) of 6.8% for short English utterances in low noise conditions, an end-to-end response latency of 2.0-4.0 s, and a lower peak power consumption of approximately 9.0 W. The system also achieves effective offline recognition for Bangla speech, supporting multilingual accessibility in low resource settings. By operating entirely offline, LUMO provides strong data privacy, reduced need for cloud connectivity, and suitability for privacy sensitive edge execution such as rural healthcare, education, and disaster response scenarios.

## 2. 论文提出的方法论

LUMO 采用**模块化流水线架构**，所有处理均在本地完成，主要组件与流程如下：

- **系统总览**
  - 流水线顺序：**语音活动检测（VAD）→ 语音转文本（STT/ASR）→ 本地大语言模型（LLM）→ 文本转语音（TTS）**。
  - 硬件平台：Raspberry Pi 5，8 GB RAM。
  - 交互状态：通过 NeoPixel LED 环指示“聆听、处理、说话”三种状态。

- **语音活动检测与语音识别**
  - 使用 **WebRTC VAD** 检测语音帧，避免对非语音段做无效处理。
  - 使用 **VOSK 离线 ASR 框架**（基于 Kaldi）完成语音转文本，适合嵌入式设备。

- **本地 LLM 集成**
  - 识别文本送入本地部署的 LLM 生成回复。
  - 采用 **GGUF 量化格式**，将模型权重量化到低精度，降低内存和计算开销。
  - 最终选择 **TinyLLaMA（1.1B 参数）** 作为本地语言模型，平衡推理速度与内存占用。

- **文本转语音模块**
  - 使用 **Piper TTS** 将生成文本转为语音，计算开销低、可离线运行。

- **并发与控制逻辑**
  - 使用**多线程**分别处理音频采集、语音识别、LLM 推理和音频播放。
  - 模块之间通过**队列传递音频和文本**，减少阻塞，支持低延迟实时交互。

- **部署优化**
  - 使用 4-bit GGUF 量化降低模型内存需求。
  - 使用短音频帧（约 0.25 秒）降低处理延迟。
  - 使用 USB SSD 提升模型加载速度。
  - 使用主动散热维持长时间推理时的温度稳定。

## 6. 论文的主要结论与发现

- LUMO 在 Raspberry Pi 5 上实现了**完全离线、隐私保护、支持生成式对话**的语音助手。
- **语音识别性能**：
  - 30 dB 安静环境：WER 4.1%。
  - 50 dB 办公室噪声：WER 6.8%。
  - 70 dB 高噪声：WER 14.2%。
  - 噪声增大时识别性能下降，但在安静与中等噪声下表现良好。
- **多语言能力**：
  - 英语短句 WER 6.8%。
  - 孟加拉语短句 WER 9.9%。
  - 孟加拉语 WER 更高，符合低资源语言训练数据稀缺的预期。
- **模型与量化**：
  - TinyLLaMA 在三款候选模型中推理速度最快、内存最低。
  - 4-bit GGUF 量化使模型大小从 FP16 的 2.2 GB 降到 640 MB，减少 72%。
- **延迟**：
  - 端到端总延迟约 3.2 s：VAD+STT 0.7 s，LLM 推理 1.8 s，TTS 0.7 s。
  - LLM 推理占总延迟约 56.3%，是主要瓶颈。
- **功耗与热稳定性**：
  - 空闲 4.2 W，语音识别 6.8 W，LLM 推理 9.0 W。
  - 峰值功耗低于 Rhasspy（约 11 W）和 Mycroft（约 12 W），分别降低约 18.2% 和 25.0%。
  - 持续 LLM 推理时 CPU 温度低于 70°C，未出现热降频或突然性能退化。
- **隐私与云独立性**：
  - 离线运行期间对外网络流量 \(V_{\text{net}}=0\)，外部数据暴露时间 \(T_{\text{exp}}=0\)。
  - 相比 Mycroft（本地/云端混合）和 Rhasspy（本地但无生成能力），LUMO 在隐私与生成能力结合上更具优势。
- **总体结论**：通过模型压缩、量化、多线程流水线和全离线设计，隐私保护型对话语音助手可以成功部署在低功耗边缘设备上。
