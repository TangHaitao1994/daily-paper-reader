## 摘要
AI 智能体需要能够在用户-智能体交互、用户间对话以及有或没有智能体参与的群组对话中保留信息的记忆，同时支持在证据发生变化或被移除时进行更新。我们提出 Stashbird，这是一种通过显式溯源将源情节与派生记忆状态关联起来的智能体记忆系统。Stashbird 将记忆组织为情节记录、语义关系、社区摘要和持久化图状态，并提供用于增量更新和情节级删除的生命周期操作。我们在四个长期记忆基准上评估了问答准确率和面向模型的工作负载。在 LoCoMo 上，Stashbird 使用的摄取提示 token 数量仅为 Graphiti 的 1/76.4。与在同一基准上复现的 Hindsight 相比，它使用的检索提示 token 数量少 8.1 倍，准确率低 1.6 个百分点。在 LongMemEval-S 和 GroupMemBench 上，Stashbird 的准确率高于 Hindsight，在 EverMemBench 上准确率相当。

## Abstract
AI agents require memory that preserves information across user-agent exchanges, user-to-user conversations, and group conversations with or without agent participation, while supporting updates as evidence changes or is removed. We present Stashbird, an agent memory system that links source episodes to derived memory state through explicit provenance. Stashbird organizes memory into episodic records, semantic relations, community summaries, and persisted graph state, with lifecycle operations for incremental updates and episode-level deletion. We evaluate question-answering accuracy and model-facing workload across four long-term memory benchmarks. On LoCoMo, Stashbird uses 76.4x fewer ingestion prompt tokens than Graphiti. Compared with reproduced Hindsight on the same benchmark, it uses 8.1x fewer retrieval prompt tokens, with accuracy 1.6 percentage points lower. It achieves higher accuracy than Hindsight on LongMemEval-S and GroupMemBench and comparable accuracy on EverMemBench.

  - 当证据发生变化或被删除时，系统需要能够追溯、修改或移除相关记忆，而不破坏其他记忆。
- **整体含义**：论文提出 **Stashbird**，一种以情节（episode）为锚点、通过显式 provenance 将源对话与派生记忆状态连接起来的记忆系统。目标是在保证问答准确率的同时，大幅降低构建和查询记忆所需的模型调用与 token 成本，并支持增量更新和情节级删除。

## 2. 方法论

### 2.1 总体架构与存储视图

Stashbird 将记忆组织为多种结构化视图（表 1）：

- **Episodes（情节）**：对话块，支持追加/删除，用于证据召回。
- **Entities（实体）**：规范实体，支持合并/失效，用于指代锚定。
- **Relations（关系）**：实体间关系，支持替换/版本化，用于推理。
- **Preferences（偏好）**：用户特质，支持覆盖，用于个性化（实验中默认关闭专用偏好检索）。
- **Communities（社区）**：实体聚类，支持重新摘要，用于提供高层上下文。

系统分为三个核心操作：摄取与更新、删除、检索（图 1）。

### 2.2 摄取与更新

- 对话被处理为有序、带时间戳的情节序列，每条情节记录说话人、内容、消息时间和摄取时间。
- 为避免反复全历史 LLM 调用，采用分层处理：
  - 全局摘要窗口：15K token。
  - 情节分块：20K token，10% 重叠。
  - 实体中心滚动上下文：4K token 上限，必要时压缩或剪枝低支持度实体。
- 先使用 NER 模型（如 spaCy）减少漏检实体，再让骨干 LLM 从文本块、全局摘要和滚动上下文中抽取实体和关系。
- **实体协调**：同时满足余弦相似度和 Levenshtein 比率 > 0.85 则接受匹配；任一指标 > 0.75 的候选交给骨干模型裁决。
- **关系协调**：同一实体对内重复关系扩展 provenance，矛盾关系替换早期版本。
- **社区摘要**：可选用标签传播对实体图聚类，每个簇生成一个社区节点。
- **增量更新**：通过持久化 checkpoint 保存对话摘要、滚动上下文、最后处理情节和实体数；新情节追加入图，复用已有实体/关系。

### 2.3 删除

- 删除以情节为单位，依赖 provenance 找到受影响实体、关系、社区。
- 对关系：从支持情节集合中移除被删情节；若仍有支持则仅更新 provenance，若不再有支持则从图和检索索引中删除。
- 对实体：
  - 有剩余支持：仅更新 provenance。
  - 无剩余支持且无邻居：从图与索引删除。
  - 无剩余支持但有邻居：保留为“连接锚点”，清除由情节派生的元数据，删除其搜索文档。
- 最后删除情节本身，重连其前驱/后继，标记受影响社区为 dirty 并移除过期社区文档，等待延迟重新摘要。

### 2.4 检索

- 保留原始查询，并让骨干模型生成最多 4 个聚焦子查询。
- 每个查询变体嵌入，并将时间表达相对于问题日期解析。
- 对话范围混合检索：对情节、实体、关系以及社区文档分别执行 top-60 混合搜索。
- 使用倒数排名融合（RRF，k=60）合并多查询结果。
- 使用 LLM 相关性评分器对候选打分，默认保留 top-30 证据。
- 回答生成器只基于检索到的证据回答问题。

## 3. 实验设计

### 3.1 数据集与场景

- **LongMemEval-S**：用户-助手长历史记忆，500 个问题，每个问题约 115K token；覆盖信息抽取、多会话推理、时间推理、知识更新、弃权。
- **LoCoMo**：双人多会话对话；覆盖单跳、多跳、时间、开放域问题；对抗类问题按先前工作排除。

## 6. 主要结论与发现

- **LongMemEval-S**：Stashbird 总体准确率高于 Hindsight，GPT-4o-mini 为 75.6% vs 74.8%，GPT-4.1-mini 为 81.0% vs 78.3%；单会话偏好问题提升最明显，且波动更小。
- **LoCoMo**：Stashbird 准确率略低于 Hindsight（GPT-4o-mini 80.4% vs 85.9%，GPT-4.1-mini 87.5% vs 89.1%），但成本大幅下降：检索 prompt tokens 少 8.1 倍，摄取 prompt tokens 比为 Graphiti 少 76.4 倍。
- **EverMemBench**：Stashbird 平均准确率 55.4%，与复现 Hindsight 的 54.8% 相当；在单跳召回、约束意识和画像理解上较强，在多跳/时间/主动性/知识更新上较弱。
- **GroupMemBench**：Stashbird 平均准确率 51.1%，远高于 Hindsight 的 24.9%；在时间推理（72.3% vs 2.2%）和用户隐含问题上优势明显。
- **Top-K 影响**：K 从 10 到 50 准确率基本稳定，说明融合和重排后 top 证据通常已足够。
- **Backbone 影响**：更强模型在 LoCoMo 上稳定提升，在 EverMemBench 上提升有限，表明后者更受检索瓶颈限制。
