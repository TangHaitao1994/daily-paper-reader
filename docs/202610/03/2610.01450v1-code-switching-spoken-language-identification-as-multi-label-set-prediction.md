## 摘要
语码转换（CS）语音会穿过用于整理大规模语音语料库的单语语言识别（LID）过滤器，这要求面向语码转换的语言识别（CS-LID）。我们将话语级CS-LID形式化为多标签语言集合预测，并提出一种集合生成器，直接输出话语中的语言，将其与原子对和基于分数的分类基线进行比较。Oracle Top-k 是最强的基线，但阈值化失败，因为没有单一阈值能将CS语音与单语语音区分开。我们的集合生成器在不假设语言数量的情况下，对未见语言对预测了正确的语言数量，但在精确集合准确率上不如 Oracle Top-k。我们的分析确定了稳健CS-LID的关键障碍：oracle基数、阈值不稳定性、CS训练数据中的语言偏见以及合成到真实的差距。

## Abstract
Code-switched (CS) speech leaks through the monolingual language identification (LID) filters used to curate massive speech corpora, calling for CS-aware LID (CS-LID). We formulate utterance-level CS-LID as multi-label language-set prediction and propose a set generator that directly outputs the languages in an utterance, comparing it against atomic-pair and score-based classification baselines. Oracle Top-k is the strongest baseline, but thresholding fails because no single threshold separates CS from monolingual speech. Our set generator predicts the correct language count on unseen pairs without assuming the number of languages, but underperforms oracle Top-k in exact set accuracy. Our analysis identifies the key obstacles to robust CS-LID: oracle cardinality, threshold instability, language bias in CS training data, and the synthetic-to-real gap.

## 1. 论文的核心问题与整体含义

- **问题背景**：大规模多语种语音语料库（如 YODAS、Emilia、VoxPopuli）在预处理阶段依赖单语种语言识别（LID）过滤器来清理语言标签。但语码转换（code-switching, CS）语音会“漏过”这些单语种过滤器，导致语料库中单语标签与多语内容不匹配。
- **核心矛盾**：CS 语音本身不是问题，问题在于单语标签与多语内容的错配。这会偏置语言均衡采样、污染特定语言的评估，并把非目标语言泄漏到语言条件 ASR 训练中。
- **研究目标**：提出 CS 感知的语言识别（CS-LID），识别每段话语中出现的**语言集合**（monolingual 为一元集合，双语 CS 为二元集合），而非单一语言标签。
- **整体含义**：将话语级 CS-LID 重新形式化为**多标签语言集合预测**，避免传统原子对分类的“未见语言对无法预测”缺陷，也避免 Top-k 的 oracle 基数假设和阈值化的操作点不稳定问题。

## 2. 论文提出的方法论

- **问题形式化**：
  - $L$ 表示个体语言清单，$Y(x) \subseteq L$ 是话语 $x$ 的参考语言集合。
  - 单语话语 $|Y(x)|=1$，双语 CS 话语 $|Y(x)|=2$。
  - $P_{train}$ 表示训练集中出现过的 CS 语言对。

- **对比的四类方法**：

  1. **原子对分类（hard-target multi-class）**  
     把单语语言和 CS 语言对当作互斥类别，类别集合为  
     $C_{atomic} = L \cup \{ [\ell_a,\ell_b] \mid \{\ell_a,\ell_b\} \in P_{train} \}$。  
     例如 `jpn-eng` 是一个独立类别。测试时若语言对未在训练中出现，则无法预测。

  2. **软目标分类（soft-target classifier）**  
     保留个体语言输出，对 CS 话语使用均匀软分布目标：
     $$
     q(\ell|x)=
     \begin{cases}
     1/|Y(x)|, & \ell\in Y(x),\\
     0, & \ell\notin Y(x).
     \end{cases}
     $$
     训练目标为 KL 散度 $D_{KL}(q\|p_\theta)$。推理时可用 Top-k 或阈值。

  3. **Sigmoid 多标签分类器**  
     对每个语言输出独立 sigmoid 分数 $r_\ell(x)=\sigma(z_\ell(x))$，使用多热目标 $y_\ell(x)\in\{0,1\}$，训练目标为二元交叉熵（BCE）。

  4. **多标签集合生成器（本文提出）**  
     基于 ESPnet ASR 结构，直接生成语言 token 序列 $\hat{s}(x)$，再转换为无序集合：
     $$
     \hat{Y}(x)=\text{set}(\hat{s}(x))\cap L.
     $$
     预测语言数量 $\hat{k}(x)=|\hat{Y}(x)|$，当 $\hat{k}\ge 2$ 时判定为 CS。  
     训练时使用 decoder 交叉熵，且对 CS 话语的两种 token 顺序都计算损失并取较小者。

- **推理方式对比**：
  - **Oracle Top-k**：已知真实语言数量 $k$，取 top-k 语言，是最强 baseline 但依赖 oracle 基数。
  - **阈值化**：用 softmax 概率或 sigmoid 分数做阈值判断；论文显示没有单一阈值能同时处理 CS 与单语。

- **模型架构与训练**：
  - 所有系统共享 965M 参数 MMS-1B 前端，并在训练中更新。
  - 分类器基于 ECAPA-TDNN + 统计池化 + RawNet3 风格投影 + subcenter cosine head。
  - 集合生成器使用 24 层 Transformer 编码器 + 4 层 Transformer 解码器，隐藏维度 256，注意力头 4。
  - 训练配置：分类器训练 3 epochs，batch size 32，学习率 warmup 后衰减；集合生成器两阶段训练，先冻结前端训练随机初始化的编解码器，再解冻前端联合训练。

## 6. 论文的主要结论与发现

- **Oracle Top-k 是最强 baseline**，但需要预先知道语言数量；阈值化不能稳定替代 Top-k，因为没有单一阈值能同时分离 CS 和单语语音。
- **原子对分类在 seen 语言对上表现好，但 unseen 语言对准确率为 0.0%**，存在结构性缺陷。
- **集合生成器能够在不假设语言数量的情况下，对某些 unseen 语言对预测出正确的语言数量**（MMS unseen 上预测两语言的比率为 96.8%），但精确集合准确率仍低于 oracle Top-k（28.5% vs sigmoid 的 87.3%）。
- **基数预测和语言识别是可分离的子问题**：集合生成器在基数上表现较好，但识别具体组成语言仍不足；分数分类器则相反，需要外部 oracle 基数。
- **合成到真实差距显著**：在人工朗读的 Read 子集上，多数 CS 训练模型接近失败；加入 CS-YODAS 效果有限，可能由于时长、噪声和领域不匹配。
- **英语占比影响明显**：在 Bangor Miami 上，英语占比越高，分数分类器准确率越低，因为 CS-FLEURS 训练数据中英语大多为低比例嵌入语言。
- **三语 CS 对所有模型都是开放挑战**：所有模型在英语–科萨语–祖鲁语三语场景下精确集合准确率为 0.0%。
