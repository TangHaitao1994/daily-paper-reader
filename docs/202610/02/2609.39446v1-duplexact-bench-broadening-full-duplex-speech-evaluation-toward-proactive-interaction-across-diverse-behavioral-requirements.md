## 摘要
现有全双工语音基准仅覆盖实时交互行为的一部分，且通常在有限的上下文条件下开展。我们提出 DuplexAct-Bench，一个双语基准，系统性地覆盖六种互补行为——从打断、让渡到主动发起、主动沉默和反向通道——并跨越会话前、会话中与无明确条件。在1290个中英文流式试验中，我们从时机与内容两个维度评估了12个全双工语音系统。结果表明，不同行为、条件和系统之间存在显著差异，并且语义质量与行为时机经常出现不匹配。这些发现表明，当前系统在实时交互展开时，仍远未具备稳健管理“何时、是否以及如何”参与的能力。项目页面：https://alitaxky.icu/DuplexAct-Bench/

## Abstract
Existing full-duplex speech benchmarks cover only subsets of real-time interaction behaviors, often under limited contextual conditions. We introduce DuplexAct-Bench, a bilingual benchmark that systematically covers six complementary behaviors, from interruption and yielding to proactive initiation, active silence, and backchanneling, across Pre-session, In-session, and No-explicit conditions. Across 1,290 English and Chinese streaming trials, we evaluate 12 full-duplex speech systems on both Timing and Content. Results reveal substantial variation across behaviors, conditions, and systems, as well as frequent mismatches between semantic quality and behavioral timing. These findings show that current systems remain far from robustly managing when, whether, and how to participate as real-time interaction unfolds. Project page: https://alitaxky.icu/DuplexAct-Bench/

- 现有全双工语音基准只覆盖实时交互行为的一部分，且大多集中在**话轮转换和用户触发式响应**上，评估场景和上下文条件较为有限。
- 真实自然的全双工交互还要求智能体能够**主动判断“是否说话、何时说话、如何说话”**，包括打断、让渡、主动发起、主动沉默、反向通道等行为。
- 论文提出 **DuplexAct-Bench**，一个双语（中/英）基准，系统性地覆盖六种互补交互行为，并在 **Pre-session、In-session、No-explicit** 三种上下文条件下进行评测。
- 核心含义是：当前全双工语音系统在“何时、是否以及如何参与实时交互”方面仍远未稳健，单一语义质量或单一时机指标都不足以衡量交互成功。

## 2. 方法论

### 2.1 六种交互行为

- **Agent Interruption（智能体打断）**：在用户进行中的话轮里主动介入。
- **User Interruption（用户打断）**：智能体被用户打断时，需要让渡并回应用户的打断。
- **Interruption Resistance（抗打断维持活动）**：在非破坏性用户输入出现时，维持正在进行的活动（如同声传译、合唱）。
- **Active Silence（主动沉默）**：在应当保持沉默的区间内不发声。
- **Proactive Initiation（主动发起）**：在没有明确用户请求时主动开始说话。
- **Agent Backchannel（智能体反向通道）**：在用户话轮中给出简短、保持话轮的回应。

### 2.2 三种上下文条件

- **Pre-session**：行为要求通过交互开始前的持久化 profile 建立。
- **In-session**：行为要求在被流式传输的交互过程中明确引入。
- **No-explicit**：不给出行为指令，智能体须从语义或声学上下文中自行推断合适的参与行为。

### 2.3 数据构建与流式协议

- 每个行为–条件组合实例化为多个交互场景和 trial；由 LLM 草拟用户话语、期望行为、内容要求和目标说话风格，再经人工审核。
- 英文和中文使用同一构建协议。
- **Agent Backchannel** 的 Pre-session 子集基于真实中文相声文本；No-explicit 子集选自 otoSpeech 对话中仅包含 backchannel 的单通道数据。
- 音频由 TTS 渲染，混合白噪声，使用人工校验的 VAD 边界并对齐到共享时间线。
- 评测时用户音频以约 **80ms chunk、实时率 1.0** 流式输入。

### 2.4 评估协议

- **Content（内容，0–5 分）**：
  - Semantic Fulfillment（语义完成度，0–2）
  - Constraint Adherence（约束遵守，0–1）
  - Contextual Consistency（上下文一致性，0–1）
  - Prosodic Appropriateness（韵律适当性，0–1，由音频指令遵循评估器评分）
- **Timing（时机）**：为每种行为定义特定成功标准和延迟指标：
  - Agent Interruption：首次语义有效打断须发生在标注的最早有效点之后、用户音频结束之前。
  - User Interruption：须在让渡区间内让渡，并在响应区间内给出语义有效回应；L = Lyield + Lresp。
  - Interruption Resistance：须维持目标活动或满足恢复要求；L 按场景定义。
  - Active Silence：整个标注评估区间保持沉默。
  - Proactive Initiation：首个语义有效主动话语须落在标注有效区域。
  - Agent Backchannel：将试验切分为 1 秒窗口，通过高斯平滑构建机会图，计算 **BAS（Backchannel Alignment Score）**：
    \[
    BAS = \frac{\int \min(q_M(t), q_{ref}(t))\,dt}{\int \max(q_M(t), q_{ref}(t))\,dt}
    \]
- **BCR（Behavioral Correctness Rate）**：Content ≥ 2.5 且同时满足 Timing 标准的 trial 比例。

## 3. 实验设计

- **Benchmark 规模**：共 **1,290 个中英文流式试验**，覆盖 **30 个交互场景**。
- **对比系统**：共 **12 个全双工语音系统**：
  - 本地部署 7 个：Freeze-Omni、MiniCPM-o 4.5、Moshi、PersonaPlex、VITA-1.5、Raon-SpeechChat、DuplexCascade。
  - 远程 API 5 个：Nemotron 3 VoiceChat、Qwen3.5-Omni、Grok Voice、GPT Realtime 2.1、Gemini 2.5 Native Audio。
- **语言覆盖**：部分系统仅英文，部分中英双语；不同系统和条件的适用设置不同。
- **对比基准**：论文与 Talking Turns、FDB v1/v1.5/v2/v3、FD-Bench、FLEXI、HumDial-FD、DuplexSLA、DSB-IFEval 等现有全双工基准进行覆盖范围比较。

## 6. 主要结论与发现

- 不同行为、不同条件、不同系统之间差异显著。
- **Interruption Resistance** 在 No-explicit 条件下最佳 BCR 可达 100.0%，但在同声传译和合唱场景中最高仅 20.0% / 30.0%。
- **No-explicit Proactive Initiation** 普遍困难，最佳 BCR 仅 8.8%。
- 同一系统在不同条件下表现可能剧烈波动，如 Freeze-Omni 在 Active Silence 的 Pre-session BCR 为 88.8%，而 In-session 仅 5.0%。
- **语义质量与行为时机频繁脱节**：
  - GPT Realtime 2.1 在 Agent Interruption 上 Content 最高（4.12），但三种条件下 BCR 仅 2.5%、1.3%、1.3%。
  - VITA-1.5 和 DuplexCascade 在 Proactive Initiation 上延迟最低（10.05s），但 Content 低且 BCR 为 0.0%。
- 案例表明，正确交互不仅取决于“何时说”，还取决于“说什么”以及“是否应该说”。

## 7. 优点

- **覆盖范围系统化**：将评估从传统话轮转换扩展到六类主动/被动交互行为，并纳入三种上下文条件。
- **双语设计**：中英文并行构建，提升基准的跨语言适用性。
- **双维度联合评测**：同时评估 Content 与 Timing，并用 BCR 避免单一指标误导。
- **行为特定的 Timing 指标**：不同行为使用不同成功标准和延迟定义，更贴近真实交互需求。
- **部分使用真实数据**：如中文相声、otoSpeech 自然对话，增强生态效度。
- **统一流式协议**：80ms chunk、RTF 1.0，有助于系统间可比性。

## 8. 不足与局限

- **算力与成本未披露**：无法评估基准的运行成本和可复现性。
- **覆盖不完全公平**：不同系统的语言、条件支持差异较大，部分结果缺失，跨系统直接比较需谨慎。
- **自动评判偏差风险**：Content 和韵律评分依赖 GPT-4o、AnyAudio-Judge 等自动评估器，可能存在主观误差和模型偏好。
- **数据来源偏合成**：大量 trial 由 LLM 草拟，虽有手工审核，但自然对话比例有限，可能影响真实场景泛化。
- **样本数量不均衡**：不同行为、条件下的 trial 数量不同，可能影响统计稳健性。
- **无消融或改进方案**：作为评估基准，未分析各失败原因或提供提升建议。
