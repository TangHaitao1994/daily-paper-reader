## 摘要
合成数据如今对LLM训练至关重要，用于增强自主与长时程任务执行等高级能力。然而，近期研究表明，大规模使用合成数据进行训练会降低模型生成质量，因此决定哪些合成数据值得用于训练十分重要。当前的数据筛选实践依赖个体级信号（即孤立地估计每个数据样本的训练效用），但在预训练和后训练场景中，我们表明这对合成数据而言是不充分的；有效的合成数据筛选需要群体级信号（即考虑数据样本间交互的效用估计）。首先，我们表明个体级信号无法捕捉样本对训练的联合影响：具有不同组成的合成数据集在个体级影响下可能无法区分，但在群体级影响下差异显著，并且按后者进行筛选能带来更好的下游性能，尤其是在生成能力方面。其次，我们发现随着训练流程越来越依赖合成数据，群体级信号变得更加重要：在广泛使用的数据筛选方法中，只有纳入这些信号的方法才能超越基线，并且当放大捕捉样本间关系的权重时，增益会进一步增加。最后，我们将这些发现转化为实践——针对计算预算有限的模型开发者，我们提供一种低成本诊断方法，用于优先确定哪些合成数据组最需要进行群体级估计，从而以极小的计算成本获得全量群体级评分的大部分收益。

## Abstract
Synthetic data now is essential to LLM training, used to strengthen advanced capabilities such as autonomous and long-horizon task execution. Yet recent work shows that training on it at scale can degrade model generation, making it important to decide what synthetic data is worth training on. While current data curation practices do so with individual-level signals (i.e., estimates of each data sample's training utility in isolation), across pre-training and post-training settings we show that this is insufficient for synthetic data, and that group-level signals (i.e., estimates of utility that account for interactions among data samples) are necessary for effective data curation. First, we show that individual-level signals are blind to how samples jointly affect training: synthetic datasets with different compositions can be indistinguishable under individual-level influence yet differ sharply under group-level influence, and curating by the latter yields better downstream performance, particularly in generative capability. Second, we find that group-level signals matter more as training pipelines become increasingly synthetic: among widely used data curation methods, only those incorporating them improve over baseline, with gains increasing when weights capturing relations among samples are amplified. Finally, we translate these findings into practice -- for model developers under a compute budget, we offer a cheap diagnostic that prioritizes which groups of synthetic data most need group-level estimation, recovering much of the benefit of full group-level scoring at a fraction of the compute cost.

## 2. 方法论

### 2.1 核心概念：Oracle 评分与个体/群体信号

- 论文使用 **oracle scoring（oracle 评分）** 来量化数据样本或数据组的训练效用。
- 给定训练数据集 \(D_{\text{train}}\)、参考集 \(D_{\text{ref}}\) 和模型参数 \(\theta\)，定义：
  - **个体 oracle 分数**：测量单个样本被加入训练数据后，模型在参考集上的损失变化；
  - **群体 oracle 分数**：测量一组样本被加入训练数据后，模型在参考集上的损失变化；
  - **个体代理 oracle**：用组内所有样本个体 oracle 分数的平均值来近似群体 oracle 分数。

### 2.2 合成数据筛选的两个核心挑战

- **挑战 1：合成数据同质。** 合成语料通常由少量种子提示生成，样本间方差低；个体级数据影响差异小，难以挑选高质量样本。
- **挑战 2：数据价值非加性。** 样本之间的相互作用会带来抵消或放大效应，个体代理 oracle 无法捕捉，造成与真实群体 oracle 的排序不一致。

### 2.3 通过受控实验构建候选数据组

- 构造候选用数据组时，论文采用 **proxy-matched diversity sampling**，目的是：
  - 保持每个组的个体代理 oracle 分数近似相同；
  - 同时让组内语义多样性/组成发生变化。
- 做法：
  - 用 BGE 嵌入将语料聚为 20 个语义簇；
  - 每个组从 1 个簇（同质）到 20 个簇（多样）中采样；
  - 在给定目标个体 proxy oracle 分数附近，进行双侧分层采样，使组的平均分数落在目标区间；
  - 用 **Gumbel-Top-k** 采样选择数据组。
- 这样可以在“个体代理分数高度接近”的控制条件下，观察组级效用与组成的关系。

### 2.4 数据筛选方法对比

- 比较了实践中使用的数据筛选方法：
  - **个体级方法**：GradSim、FineWeb-Edu、BM25，均孤立评分样本；
  - **群体级方法**：GMRel、GREATS，均建模样本间关系。
- 合成数据回收实验：
  - 从 DCLM 等噪声有机文档出发，用 Repro 重写模型生成合成池；
  - 固定池大小为 716,800 个序列，改变 **rephrase factor \(r\)**（1、10、50），控制每个源文档的重写数量；
  - 每组 5120 个序列，每种方法选择 20 组进行训练。

### 2.5 群体级信号的成本诊断

- 群体级评分通常计算成本更高。论文提出用**组内梯度多样性（within-group gradient diversity）** 作为便宜诊断指标。
- 关键理论结果（Proposition 5.1）：
  - 个体代理 oracle 与真实群体 oracle 的差距上界为：
    \[
    I_{\text{proxy}}(G,\theta) - I_{\text{orcl}}(G,\theta)
    \le \frac{\beta \eta^2}{2} \sigma_G^2
    \]
  - 其中 \(\sigma_G^2\) 是组内梯度的离散度，\(\beta\) 衡量参考损失的曲率。
  - 直觉：样本把模型往不同方向拉得越厉害，用均值个体分数估计组效用越可能出错。
- 预算分配策略：
  - 用梯度多样性对数据组排序；
  - 仅对排名靠前（预测差距最大）的 \(B\) 组调用昂贵的群体 oracle；
  - 其余组用便宜的个体代理（如 GradSim）评分。
- 诊断还比较了：
  - GradDiv full、GradDiv q（只计算组内 10% 或 1% 样本梯度）；
  - 梯度无关多样性指标：Vendi、压缩率、distinct-n；
  - 随机分配基线。

## 6. 主要结论与发现

- **发现 1**：在个体代理分数几乎相同的数据组中，群体 oracle 分数差异很大；个体代理无法捕捉组内样本交互。
- **发现 2**：群体 oracle 筛选优于个体代理 oracle 和随机筛选，收益主要来自**生成类任务**（如 LAMBADA、SQuAD、CoQA、MBPP+、IFEval 等），多选题或分类任务上差异不大。
- **发现 3**：在合成数据回收 pipeline 中，个体级方法（GradSim、FineWeb-Edu、BM25）在生成性任务上趋于退化，而群体级方法（GMRel、GREATS）能平衡**价值与多样性**，避免生成能力下降。
- **发现 4**：随着 rephrase factor r 增大（训练数据更合成化），群体级信号更重要；放大 GMRel 中的关系权重可以在 r=50 时进一步改善下游表现。
- **发现 5**：群体级评分与个体代理评分的差距可以用**组内梯度多样性**预测；在有限群体 oracle 预算下，先用梯度多样性选组再打分，可以用较少计算恢复大部分群体级排序收益。
- **发现 6**：梯度多样性诊断在子采样 10% 样本时仍能保持大部分收益，说明只需粗略估计即可指导预算分配。

## 7. 优点

- **问题定位明确**：提出合成数据筛选中“个体级信号不充分”这一关键问题，并用 oracle 评分框架系统证明群体级信号的重要性。
- **实验设计精巧**：通过 proxy-matched diversity sampling 控制了组内平均个体分数，从而较干净地揭示组内多样性和交互对训练效用的影响。
- **覆盖预训练和 RLVR 后训练**：验证结论在两个不同训练阶段均成立，提高了结论的通用性。
- **理论联系实践**：给出梯度多样性与 oracle 差距的界限，并据此设计便宜计算诊断，对资源有限的开发者有实际指导意义。
- **包含计算成本分析**：用 FLOPs 和内存折扣比较不同诊断方案的相对成本，给出了可迁移的内存估算公式。

## 8. 不足与局限

- **模型规模较小**：主实验只使用了 400M 和 1.5B 模型，尚未验证在数十亿/万亿参数模型上的效果，可能无法直接推广到前沿 LLM 的合成数据 pipeline。
- **数据集代表性不足**：仅使用 Repro、GooseReason 以及 DCLM 重写池，未必反映所有合成数据类型（如代码、agent、多模态合成数据）的特性。
- **算力细节缺失**：论文未报告 GPU 型号、数量、训练时长，读者难以评估实际计算成本。
- **oracle 近似与实际训练存在差距**：用一步 AdamW 更新后的参考集损失变化来近似训练效用，可能不能完全反映长期训练效果。
- **参考集选择可能影响

不同参考集可能导致不同的群体 oracle 排序，削弱结论的稳健性。  
- **未充分报告随机性方差**：主要结果未展示多次运行的标准差或置信区间，组大小为 5120 或 128 的设定下随机种子影响可能较大。  
- **群体级方法部署门槛**：虽然提出了梯度多样性作为便宜诊断，但实际预算分配仍需设定排序阈值和群体 oracle 调用预算，且梯度多样性计算本身仍有一定开销，可能限制在极大规模流水线中的直接使用。
