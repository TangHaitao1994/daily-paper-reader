ABSTRACT 

Long-term memory systems for large language models (LLMs) have gained pop-ularity for extending reasoning capabilities across applications. Current memory systems rely on LLM agents to organize and consolidate memory, resulting in costly, inefficient write operations. To address this limitation, we propose MemFit ,a long-term memory system for conversational agents that reduces the cost and latency of memory operations. Unlike existing systems that rely on expensive LLM calls for memory construction or discard surface-level details through compression, 

MemFit stores each turn verbatim in an append-only store with near-instantaneous, LLM-free insertion, indexing turns with segment summaries rather than replacing them. Additionally, MemFit uses an LLM-free, multi-path retrieval strategy that combines lexical and semantic signals with cross-encoder reranking over caption-augmented episodes in both textual and multimodal settings. Empirical results on three widely used benchmarks, LoCoMo, MemGallery, and LongMemEval-S, show that MemFit achieves state-of-the-art performance while reducing memory construction time and cost several-fold, providing a scalable and efficient solution for persistent agentic memory. 1

1 INTRODUCTION 

Large language models (LLMs) have demonstrated strong performance across diverse domains, but remain fundamentally constrained by fixed-length context windows, with performance degrading as token counts increase (Liu et al., 2024). This degradation, often termed context rot (Hong et al., 2025), reflects the model’s difficulty in reasoning over information buried in long prompts. To address this limitation, recent work equips LLMs with external long-term memory systems that store historical in-teractions and retrieve only the most relevant content at inference time (Packer et al., 2023; Maharana et al., 2024; Chhikara et al., 2025; Xu et al., 2025), which has become a new trend in LLM research. This combination introduces two key limitations: high computational cost and susceptibility to context pollution, where irrelevant but semantically similar memories are retrieved. These limitations raise a central research question: 

Can a long-term memory system achieve efficient storage and precise retrieval without relying on frequent LLM calls? 

In this paper, we introduce MemFit , a long-term memory system for conversational agents that addresses this critical question by keeping the LLM out of the write path and out of the search itself. As illustrated in Figure 1, firstly, our system replaces computationally expensive, LLM-driven storage with an append-only episode store : each turn is stored verbatim and indexed by a lexical signal, BM25 (Robertson & Zaragoza, 2009), and an embedding signal, so insertion costs an encoder pass rather than an LLM call, and no stored content is rewritten as the conversation grows. A second layer summarizes each conversational segment in a single call and records the turns it was built from. This means that the summaries index the store rather than compress it, leaving the original interaction content retrievable. Since nothing is merged or discarded at write time, a superseded fact and its correction both survive with their dates, and the choice between them is deferred until the question is known. Secondly, to ensure precise retrieval, MemFit uses an LLM-free retrieval pipeline , in which both indexes score the store, two additive expansions widen the candidate pool, and a cross-encoder (Nogueira & Cho, 2019) decides the final order. The system further supports both textual and multimodal settings via a text-image fusion design, where detailed image captions are embedded directly into the searchable episode text, enabling visual content to be retrieved through the same lexical and semantic pathways as text. To summarize, the primary contributions of this work are as follows: • We introduce MemFit , an efficient and persistent memory architecture that significantly reduces computational overhead while improving retrieval accuracy. • The proposed MemFit is a versatile memory system that extends beyond textual reasoning to support complex multimodal tasks within a unified framework, representing one of the few agentic memory systems designed for multimodal retrieval and reasoning. • Lastly, MemFit achieves a superior balance of retrieval efficiency and reasoning correctness compared to memory systems of comparable cost on representative long-term conversational benchmarks including LoCoMo (Maharana et al., 2024), MemGallery (Bei et al., 2026), and LongMemEval-S (Wu et al., 2024) datasets, under one configuration across every backbone we evaluate, spanning three model families. 

2 RELATED WORK 

Memory systems for LLMs . Memory systems for LLM agents are closely related to Retrieval-Augmented Generation (RAG) (Gao et al., 2023; Lin et al., 2023), as both rely on retrieving relevant external context to ground model responses. Foundational RAG work has shown the effectiveness of augmenting language models with external textual corpora (Lewis et al., 2020), a paradigm that is now adopted in agentic memory systems. Early approaches evolved from simple sliding-window contexts to more structured, persistent memory architectures. For example, A-MEM (Xu et al., 2025) organizes memory as a graph-based Zettelkasten with dynamically generated links to support memory evolution, while Mem0 (Chhikara et al., 2025) introduces an incremental pipeline for extraction and consolidation across sessions. Other work focuses on efficiency. For example, SimpleMem (Liu et al., 2026) applies semantic lossless compression to reduce token overhead, and LightMem (Fang et al., 2025) decouples memory maintenance from inference via a "sleep-time" consolidation process. In contrast to these approaches, MemFit never rewrites what it stores. Instead, it keeps turns verbatim without per-turn LLM calls, and its segment summaries index the stored turns. While RAG has recently expanded beyond text to support multimodal retrieval (e.g., MuRAG (Chen et al., 2022), RA-CM3 (Yasunaga et al., 2022), and UniversalRAG (Yeo et al., 2025)), this capability remains underexplored in agentic memory systems. MemFit bridges this gap through a text-image fusion design that embeds detailed visual descriptions directly into the episode text. This enables fine-grained visual retrieval within a unified text-based search space, avoiding the limitations of standard cross-modal embedding approaches. 2Preprint. Under review. Memory summarization and consolidation . Researchers have explored summarizing or restructur-ing stored content with an LLM to manage large conversational contexts. For example, RAPTOR (Sarthi et al., 2024) builds a tree by recursively clustering and summarizing text segments, allowing for retrieval at varying levels of abstraction. Similarly, MemTree (Rezazadeh et al., 2024), H-MEM (Sun & Zeng, 2025), and HiMem (Zhang et al., 2026) organize conversations into hierarchies whose upper levels an LLM writes, or rewrites, as memories arrive. Consolidation goes further by altering stored content itself: MemoryBank (Zhong et al., 2024) lets memories fade along a forgetting curve, and Mem0 deletes memories contradicted by new information. A close precedent to our design is the memory stream of Generative Agents (Park et al., 2023), which keeps a complete record of experiences and synthesizes higher-level reflections over it by rating each memory’s importance with an LLM as it is recorded. To increase efficiency, MemFit merges and deletes nothing, and segments the conversation without an LLM by applying TextTiling (Hearst, 1997) to episode embeddings. Unlike SeCom (Pan et al., 2025), which retrieves compressed segments as memory units, each segment summary indexes the verbatim turns it describes. 

Iterative retrieval for LLMs . Iterative retrieval methods refine search through repeated LLM feed-back. Self-RAG (Asai et al., 2023) employs self-reflection to improve retrieval quality, FLARE (Jiang et al., 2023) generates intermediate predictions to guide subsequent queries, and IRCoT (Trivedi et al., 2023) interleaves retrieval with chain-of-thought steps for multi-hop questions. MemWalker (Chen et al., 2023) navigates a tree of summaries through step-by-step LLM reading, and Recursive Lan-guage Models (RLMs) (Zhang et al., 2025) frame long-context reasoning as iterative exploration over external inputs. However, these approaches rely on multiple sequential LLM invocations, which increases latency and cost. In contrast, MemFit keeps the LLM out of the search itself, relying on a normalized convex fusion of lexical and dense scores (Bruch et al., 2023), pseudo-relevance feedback for multi-hop questions, and a cross-encoder reranker (Nogueira & Cho, 2019), and achieves sophisticated retrieval without LLM guidance. 3Preprint. 3 METHODOLOGY 

We present MemFit , a long-term memory system for conversational agents that utilizes a write path that never calls an LLM per turn with single-call retrieval. The system can flexibly operate in two modes: a base textual mode for purely textual conversations, and a multimodal mode that additionally handles shared images. Both modes share the same storage, indexing, and retrieval procedure, while the multimodal mode extends each stage with image captions and, at answer time, the images themselves. 3.1 PROBLEM STATEMENT 

A conversational memory system operates over a growing dialogue history H = {(ui, t i, p i, v i)}Ni=1 

of utterances ui with timestamps ti, speakers pi, and optional images vi, and must support two operations: storage , which organizes H into a persistent structure M that grows incrementally, and retrieval , which given a query q returns an answer a grounded in M. This process can be viewed as selecting a small subset of relevant episodes Hk from H and generating an answer via a = f (q, Hk), where f denotes the underlying LLM conditioned on both the query and the retrieved memory. Queries range from direct factual questions (“What is the name of Lena’s dog?”), temporal reasoning (“When did Lena adopt her dog?”), multi-hop synthesis (“Which two dogs are described as intelligent?”), to multimodal tasks that require connecting a new image to previously discussed visual content (“What breed is the dog in this picture?”). To answer such queries, a memory system must (1) locate the relevant episodes from potentially thousands of stored interactions , (2) reconcile information that may have been updated across sessions , and (3) connect visual content to its surrounding conversational context in multimodal settings . Success requires both inexpensive storage , so that every turn can be absorbed as it arrives without an LLM call of its own, and precise retrieval , so that the correct episode is surfaced among many candidates. Specifically, MemFit 

achieves them via an append-only episode store carrying one sparse and one dense index, a layer of 

segment summaries that serves as an index into that store rather than as a replacement for it (detailed in § 3.2), and a single answer-extraction call that reads the retrieved excerpts (detailed in § 3.3). 3.2 MEMORY STORAGE AND THE SUMMARY LAYER 

Memory representation . Each utterance in H becomes one memory episode written as ei =(xi, zi, g i, mi), where the formatted text xi is labeled with time and speaker (e.g., [Time: 2023-05-12] [Speaker: Lena] I adopted a golden retriever yesterday .), zi = fenc (xi) ∈ Rd is the 

L2-normalized embedding of xi from a frozen sentence encoder fenc , gi is a global sequence number for temporal ordering, and mi is the structured metadata, including fields such as timestamps, speaker identifiers, and session and turn identifiers used for filtering and scoring. This granularity is deliberate because it matches the unit each benchmark annotates as gold evidence and the unit an answer usually needs, so no answer is split across a boundary the system chose for itself, and retrieval is scored at the granularity the benchmark defines. In the multimodal setting, an image-bearing turn additionally carries its image identifier and caption, appended to xi as structured text ( [Image D1:IMG_001: a golden retriever on a beach...] ), which makes image content searchable through the same lexical and semantic pathways used for text; we term this text-image fusion . We source captions from ground-truth annotations when available; otherwise, we generate them with a multimodal large language model (MLLM). 

Episode store and indexes . Episodes are stored in an append-only store M = {e1, . . . , e N } under two indexes that answer different kinds of questions about the same text. The first is a BM25 index over the tokens of xi, holding the term frequencies of each episode and the document frequency of each term, so that a bag of query terms scores the store in one pass over the postings of those terms, touching only the episodes in which one of them occurs; this is the signal that matches a name, a date, or a rare noun that has to appear verbatim. The second is a dense index: the L2-normalized embeddings zi stacked into a matrix Z ∈ RN ×d over the N stored episodes, so that scoring the store against a query embedding is the single matrix-vector product Zz q , whose i-th entry is the cosine similarity of episode i. This signal matches a paraphrase that shares no words with the question. Inserting an episode adds one row to Z and its postings to the index, and nothing already stored is rewritten, re-embedded, or re-summarized when later turns arrive, so the memory absorbs a 4Preprint. Under review. conversation at the rate it is produced. The sequence numbers gi preserve chronological order, which retrieval uses to return a retrieved turn together with its immediate neighbors. 

Segment summaries . A second memory layer describes stretches of conversation, and is the only place an LLM touches the write path. TextTiling (Hearst, 1997) segments consecutive episodes without an LLM by comparing their embeddings across each gap. At every gap, the cosine similarity between the mean embeddings of the b episodes on either side gives a coherence score, with 

b = max(3 , round( √n/ 2)) for N stored episodes, and a boundary is placed at each local minimum whose depth below its neighboring peaks exceeds μd + σd/2, where μd and σd are the mean and standard deviation of the depth over all gaps. Every resulting segment of at least three episodes is then summarized in a single LLM call that sees up to 14 evenly spaced member excerpts and returns two sentences ( ≤ 200 tokens). Each summary is stored alongside the episodes, with its members’ identifiers as provenance and its own embedding, and retrieved by the same hybrid score. Summaries deliberately do not compress the store: the episodes they describe remain verbatim and separately retrievable, because the summary finds a stretch of conversation while the raw turn answers the question. 

Updates without consolidation . The memory store intentionally has no merge, rewrite, or delete operation. When a fact changes, the store keeps the original statement and its correction as separate episodes with their own dates, and no contradiction must be detected at write time to keep the store consistent. What stands in for consolidation is the shape of what retrieval returns: competing statements about one subject tend to share the content words a query about that subject uses, so the score that surfaces one tends to surface the other, and the retrieved excerpts are ordered chronologically with each excerpt’s session date attached, leaving the reader the old value, the new value, and the order between them at the moment the question is known. A consolidator chooses which statement survives before it knows what will be asked, and the evidence it discards is unrecoverable; deferring that choice costs nothing, because retrieval already returns both sides. Summaries serve the purpose of consolidation, acting as a compact description of a stretch of conversation while keeping the property recall depends on, since they index the turns they describe rather than standing in for them. 3.3 MEMORY RETRIEVAL FOR ANSWER EXTRACTION 

Once the store has been built, it is used for all downstream query answering. When a user or evaluation benchmark poses a query q (e.g., a factual question, a temporal reasoning task, or a visual search over shared images), retrieval proceeds in four stages, as illustrated in Figure 2: candidate generation over both indexes, two additive expansions of the candidate pool, a cross-encoder rerank that fixes what the reader sees, and then final answer extraction. 

Stage 1: Hybrid candidate generation . Let zq = fenc (q) denote the L2-normalized query em-bedding produced by the same frozen sentence encoder used during storage. Two paths score the stored episodes: a lexical path , lex (q, xi) = BM25 (q, xi), and a semantic path , the cosine similarity sem (zq , zi) = z⊤ 

> i

zq , computed for every episode at once as the matrix-vector product Zz q . The top 

nscan = 60 episodes from each path form a candidate union, over which the two scores are min-max normalized and combined convexly, 

si = α · dsem (zq , zi) + (1 − α) · clex (q, xi), (1) where dsem and clex denote the two scores after min-max normalization over the union, and α is a hyperparameter (by default α = 0 .7). Since BM25 is unbounded while cosine similarity is not, their raw values share no scale, so normalizing before combining makes the two signals comparable. Each candidate additionally receives additive metadata boosts when the query mentions a specific speaker (+0 .10 ), year ( +0 .05 ), or month ( +0 .08 ) that matches the episode’s metadata, encouraging episodes from the queried time period or speaker to surface. Because the boosts are applied after normalization, a boost is a fixed fraction of the observed score range rather than an arbitrary offset between two scales. 

Stage 2: Additive candidate expansion . In practice, candidate generation is the binding constraint for retrieval: far more questions are lost because the gold turn never enters the candidate pool than because it is ranked too low within it. To address this, two expansions widen the pool. First, the summary layer is searched with the same hybrid score, and the highest-scoring summaries pull their member episodes into the pool through their provenance. This means that a summary that 5Preprint. Under review. matches the query retrieves the turns it was built from. Second, pseudo-relevance feedback re-runs candidate generation with the 12 rarest terms, by inverse document frequency, from the two top-ranked episodes; this targets multi-hop questions, whose two supporting turns lie in different sessions where a single query finds only one. Both expansions are strictly additive because they append results to the candidate pool. Therefore, expansion can only add evidence the first stage missed and can never evict what it found. 

Stage 3: Reranking and pack assembly . Once the candidate pool is generated, a cross-encoder scores the top 50 first-stage candidates, together with every expansion candidate, against the original 

question. The lexical and semantic scores therefore decide only membership in the candidate pool, not the final order, so their differing scales stop affecting the ranking. Because a cross-encoder scores a two-sentence summary and a raw turn on different text distributions, we standardize scores within each kind before ordering, so a summary holds a pack slot only if it ranks as well among summaries as an episode does among episodes. The k = 10 highest-ranked candidates form the collection Hk,and every retrieved episode brings the turns within w = 1 of it in the same session, restoring the context a short reply depends on without a second search. 

Stage 4: Answer extraction . With the top k highest-ranked candidates, the collection is rendered as chronologically ordered excerpts, each stamped with its session date and with relative time expressions pre-resolved to absolute dates, and the reader extracts the answer a = f (q, Hk). One prompt serves every question. In multimodal mode, the reader is an MLLM, and the images of the ranked episodes, together with any image attached to the query, are passed in that same call, each labeled with its image identifier; captions remain in the episode text, so retrieval is unchanged. 

Discussion on efficiency . Neither paths calls an LLM per turn or per search step. Insertion is an embedding and two index updates, and no stored episode is ever revisited. The only write-time LLM cost is one call per segment. Retrieval relies on arithmetic to retrieve memories, and only the sparse scan and the matrix-vector product grow with memory size, both of which grow linearly.

Benchmark datasets. We evaluate the performance of MemFit on three diverse benchmarks designed to stress-test long-term memory as follows. Implementation details. We use frozen all-MiniLM-L6-v2 (384-dimensional) for episode, query, and summary embeddings, and the frozen cross-encoder ms-marco-MiniLM-L-6-v2 

for reranking. Candidate generation keeps the top nscan =60 episodes from each of the lexical and semantic paths and fuses them with α=0 .7; the cross-encoder scores the top 50 of the pool, in which the 10 best-matching summaries are interleaved with the episodes, together with every expansion candidate; the pack is k=10 episodes with a context window of w=1 . Pseudo-relevance feedback uses the 12 rarest terms of the top 2 episodes, and the 5 best-matching summaries expand the pool through their provenance. Then, segments that have at least three episodes are summarized from at most 14 excerpts into at most 200 tokens. We use one configuration for every backbone and all benchmarks, with nothing tuned per corpus. For open-source models, we use Ollama as the backbone. We perform a systematic ablation study on the LoCoMo dataset to quantify the contribution of each core component of the MemFit architecture (Table 3, left). Removing the context window produces the largest degradation, with average F1 falling by 1.86 points and the judge score by 1.7, confirming that a retrieved turn is often not self-contained without its neighbors. Pseudo-relevance feedback, summary expansion, the wide first-stage scan, and the summaries themselves each account for between 0.83 and 1.35 average F1. The components therefore overlap, each recovering evidence the others partly reach, and removing all of them at once leaves plain retrieval, which costs 3.32 average F1 and 5.5 judge points ( p < 0.001 ). 5 CONCLUDING REMARKS 

We present MemFit , a long-term agentic memory system that unifies efficient storage and effective retrieval. By drastically reducing LLM calls during memory construction while introducing more sophisticated retrieval, MemFit achieves strong performance while significantly reducing computa-tional cost, specifically during memory insertion. LoCoMo. LoCoMo (Maharana et al., 2024) contains 10 conversations between two speakers, each spanning 19 to 32 sessions over several months, with 5,882 turns in total. Of its 1,986 questions, we evaluate the 1,540 non-adversarial ones, following prior work: • Multi-Hop (282): Requires the model to synthesize and compose information across multiple conversational sessions. • Temporal (321): Involves date arithmetic, event ordering, and reasoning about the timing of specific occurrences. • Open Domain (96): Requires combining interaction-specific details with world knowledge and preferences established during the conversation. • Single-Hop (841): Focuses on factual recall that is local to a single session. • Adversarial (446, excluded): Includes unanswerable distractors and trick questions that test refusal. 

MemGallery. MemGallery (Bei et al., 2026) contains 20 scenarios, each a multi-session con-versation between one user persona and an assistant, with 240 sessions and 3,962 rounds in total; 1,003 rounds share an image, and the dataset provides a caption for each. Each round becomes one episode holding the user message, the assistant reply, and the identifier and caption of its image. The benchmark’s 1,711 questions, 487 of which come with an image of their own, fall into nine categories grouped into three dimensions: • Memory extraction and adaptation. Factual Retrieval (FR, 219): recall explicit textual informa-tion from earlier in the dialogue. Visual-centric Search (VS, 306): find specific images in a long multimodal history. Test-Time Learning (TTL, 337): apply visual or textual knowledge introduced during the conversation; 333 of these questions ask about an image they come with. • Memory reasoning. Temporal Reasoning (TR, 123): resolve time-dependent questions using multimodal clues. Visual-centric Reasoning (VR, 174): infer an answer from visual cues in the conversation’s images. Multi-entity Reasoning (MR, 206): combine several retrieved entities or facts. • Memory knowledge management. Knowledge Resolution (KR, 81): prefer the most recent of several conflicting statements. Conflict Detection (CD, 81): identify a contradiction with stored memory. Answer Refusal (AR, 184): decline when the information was never given. We follow the benchmark’s reference implementation: its system prompt is prepended to the reader prompt, the official answer-format instruction of the AR, CD, and VS categories is appended to their questions, and the reader’s refusal is reported as the benchmark’s refusal string, “Not mentioned.” A question’s own image is described by its caption in the query; in the image-bearing configurations, the image itself is also passed to the reader. We report token-level F1 over all 1,711 questions (the benchmark’s Total) and LLM-judge accuracy. 

LongMemEval-S. LongMemEval-S (Wu et al., 2024) contains 500 questions, each with its own timestamped history of chat sessions between a user and an assistant: 47.7 sessions and roughly 115k tokens per history, with the sessions that hold the evidence embedded among filler sessions. We use the cleaned release published by the benchmark’s authors. The questions fall into six types, and 30 of them are abstention questions (6 SSU, 12 MS, 6 KU, 6 TR) about things that were never mentioned, which the system should decline to answer: • Single-session-user (SSU, 70): recall a detail the user stated in one session. 14 Preprint. Under review. • Single-session-assistant (SSA, 56): recall something the assistant said in one session. • Single-session-preference (SSP, 30): give a response that reflects a preference the user expressed, graded against a rubric. • Multi-session (MS, 133): aggregate or compare information spread across several sessions. • Knowledge-update (KU, 78): report the latest value of user information that changed over time. • Temporal-reasoning (TR, 133): reason about dates, durations, and order from session timestamps and time mentions. Each history is stored exactly as a LoCoMo conversation: one episode per message, from the user and the assistant alike, since SSA questions ask what the assistant said, in chronological order with each session’s timestamp, followed by segment summaries written by the backbone. As in the benchmark’s own reader prompt, the question is followed by the date on which it is asked (“Current date: . . . ”). Because this is the only benchmark that dates its questions, the reader here also sees each excerpt’s date as its distance from that date (“10 days before the current date”), and relative time expressions in the question are resolved against it (“two weeks ago (around 16 May 2023)”). Both are rule-based, like the resolution of dates in excerpts, and retrieval sees the question as asked. A NOT_FOUND reply is reported as “The information is not available in our conversation history.” Answers are graded with the official evaluation prompts, one per question type plus one for abstention. Full context. The entire history is placed in the reader’s context window, with no memory system. This measures how well the backbone reads a long history on its own. 

NaiveRAG. A standard retrieval-augmented baseline: the history is split into chunks, the chunks are embedded, and those most similar to the question are passed to the reader. Nothing is summarized, linked, or rewritten. 

MemoryBank (Zhong et al., 2024). MemoryBank implements a memory management framework based on the Ebbinghaus forgetting curve. It stores past interactions in a vector database and reinforces 15 Preprint. Under review. or decays memories according to their temporal significance and how often they are accessed, so that the agent keeps a consistent persona and recalls behavioral associations relevant to the current dialogue. 

MemGPT (Packer et al., 2023). Inspired by operating systems, MemGPT manages a “virtual context” by treating the LLM’s fixed context window as a tiered memory hierarchy, with a main context (analogous to RAM) and an external context (analogous to disk). The LLM manages its own memory through explicit function calls that move information between the tiers. 

MemoryOS (Kang et al., 2025). MemoryOS applies operating-system memory management to conversational agents. It stores memory in three tiers, short-term, mid-term, and long-term personal memory, and moves content between them with LLM-driven updates: dialogue pages pass from short-term to mid-term memory first-in-first-out and are grouped into topic segments, and frequently accessed segments are promoted to long-term memory, which maintains user and agent profiles. 

A-MEM (Xu et al., 2025). A-MEM is an agentic memory framework inspired by the Zettelkasten method. It represents knowledge as a network of atomic notes connected by semantic links. When a memory is added, an LLM writes its note, links it to related notes, and may update those notes (“memory evolution”), so that the agent maintains an interconnected web of knowledge rather than a list of interaction logs. 

Mem0 (Chhikara et al., 2025). Mem0 maintains a store of salient facts. As messages arrive, an LLM extracts candidate facts, compares each with similar stored memories, and chooses to add, update, or delete memories, or leave the store unchanged; a graph-based variant additionally stores relations between entities. 

LangMem. LangMem is LangChain’s long-term memory library. An LLM extracts memories from conversations and consolidates them by creating, updating, or deleting stored entries, which are retrieved by semantic search. 

LightMem (Fang et al., 2025). Following the Atkinson–Shiffrin model of human memory, Light-Mem partitions memory into sensory, short-term, and long-term stages. A pre-compression step filters redundant tokens before information enters memory, topic-aware segments are summarized into memory entries, and memory organization and updates run offline in a “sleep-time” process that is decoupled from inference. 

SimpleMem (Liu et al., 2026). SimpleMem focuses on semantic lossless compression. It uses an entropy-aware filtering mechanism to distill unstructured interactions into compact, context-independent memory units indexed from multiple views, reducing the token footprint of retrieving from long interaction histories.

D BROADER IMPACTS 

Positive societal contributions. By enabling efficient, long-term memory, MemFit advances the development of agents capable of maintaining context over extended interactions. This technology has the potential to improve accessibility by allowing users to manage complex personal information, assist with educational research, and support long-horizon collaborative tasks without the prohibitive costs of current LLM-based memory architectures. 

Potential harms and risks. MemFit keeps every turn verbatim and, by design, never merges or discards what it stores. This preserves evidence for recall, but it also means that sensitive details persist, and fine-grained search over a person’s textual and visual history could be repurposed for tracking or profiling. Append-only storage is a design choice for recall, not a privacy guarantee: a deployment needs user-initiated deletion (removing an episode from both indexes and re-summarizing its segment), retention limits, and access control. Because nothing is verified at write time, false or malicious content also persists: text injected into a conversation is stored like any other turn and can later reach the reader’s prompt as retrieved evidence, a memory-injection risk shared by retrieval-based memory systems. Finally, retrieval can miss relevant memories, and the reader may then answer from partial evidence; on LongMemEval-S, MemFit declines 80% of the unanswerable questions, so the remainder receive an unsupported answer. 

E LIMITATIONS 

While MemFit provides promising results across the three datasets tested, and substantially reduces memory construction cost and time, we acknowledge there are some important limitations. First, due to the fact that MemFit does not rely on LLM consolidation or organization during storage, retrieving and combining memories across sessions becomes a harder task at retrieval time, leading to slightly decreased performance in questions that require these abilities. Additionally, while applying a similar approach as the text-image fusion to other modalities is feasible, the current system only handles text and image modalities. 20 Preprint. Under review.
