## 摘要
现有的自动化研究基准往往将多种改进来源（包括训练框架、超参数、计算预算和数据）纠缠在一起，因此难以将某个前沿智能体优于另一个的原因归因于具体的研究能力。在这项工作中，我们分离并系统评估了数据智能：智能体理解、操作和改善塑造模型能力的数据的能力。我们引入了 AutoDataBench，这是一个受控测试平台，建立在涵盖数据诊断、数据组织和数据构建的数据智能概念框架之上，通过三个高度策划的优化任务实例化，同时保持非数据因素固定不变。在工具使用、检索和知识注入方面，我们评估了前沿大语言模型在任务特定资源预算下通过迭代实验改善训练数据的能力。除了优化性能之外，我们还追问：大语言模型是否理解它们的数据干预做了什么？我们将训练前做出的预测与观察到的结果进行比较，以寻找超越试错的数据效果推理的证据，并探索迭代反馈是否有助于大语言模型更好地理解训练数据的变化如何影响模型性能。最后，我们表明，将 AutoDataBench 的轨迹重用于中期训练可以提高下游编码性能，突显了它在评估数据智能和生成高质量训练数据两方面的价值。代码和资源可在 https://github.com/AutoDataBench/AutoDataBench 获取。

## Abstract
Existing auto-research benchmarks often entangle multiple sources of improvement, including training frameworks, hyperparameters, compute budgets, and data, making it difficult to attribute why one frontier agent outperforms another to specific research capabilities. In this work, we isolate and systematically evaluate Data Intelligence: an agent's ability to understand, manipulate, and improve the data that shapes model capabilities. We introduce AutoDataBench, a controlled testbed built on a conceptual framework of data intelligence spanning data diagnosis, data organization, and data construction, instantiated through three highly curated optimization tasks while holding non-data factors fixed. Across tool use, retrieval, and knowledge injection, we evaluate frontier LLMs' ability to improve training data through iterative experimentation under task-specific resource budgets. Beyond optimization performance, we ask: do LLMs understand what their data interventions do? We compare predictions made before training with observed outcomes to seek evidence of data-effect reasoning beyond trial and error, and explore whether iterative feedback helps LLMs better understand how changes to training data affect model performance. Finally, we show that reusing AutoDataBench trajectories for mid-training improves downstream coding performance, highlighting its value in both evaluating data intelligence and generating high-quality training data. Code and resources are available at https://github.com/AutoDataBench/AutoDataBench.

## 2. 论文提出的方法论

- **核心思想**：构建一个受控测试平台 **AutoDataBench**，在固定训练管线、数据源、工具和资源预算的条件下，让被评估 LLM 作为“研究智能体”迭代改进训练数据，并通过训练评估反馈来指导后续决策。
- **迭代实验循环**：
  - 智能体检查可用数据；
  - 实施数据干预（过滤、修复、重排、生成、混合等）；
  - 提交训练数据集；
  - 由固定训练和评估管线训练模型并得到目标任务反馈；
  - 根据反馈调整下一轮数据策略。
- **评估维度**：
  - **优化性能（ID）**：在用于反馈的目标分布上的提升；
  - **泛化性能（OOD）**：在隐藏的、分布外评估集上的表现，以识别“benchmaxxing”（过度拟合目标指标）行为；
  - **数据效应预测**：在每次训练前记录智能体对分数的预测、不确定性区间和理由，与实际结果比较，用于探测数据效应推理能力。
- **三个任务实例**：
  1. **数据诊断与修复（工具使用）**：基于 XLAM-Function-Calling-60K 构建约 40k 单轮函数调用示例，注入 7 种概率性 corruption（参数类型错误、缺失参数、多余参数、错误函数标签等）。智能体需要发现未公开的数据质量问题，在最多 16k 示例预算内构造干净训练集。固定微调 Qwen2-1.5B-Instruct（LoRA），评估宏平均 AST 准确率；OOD 使用 BFCL 单轮子集。
  2. **数据组织（检索）**：使用 RLHN 集合（超过 818k 文本对），智能体需要挖掘硬负例、选择负例、平衡来源和混合比例。每轮最多 600k 对，累计预算相当于 10 个满额轮次，最多 20 轮。固定对比学习管线（InfoNCE），基座为 6 层 MiniLM。ID 为 5 个检索数据集的平均 nDCG@10，OOD 为 5 个额外数据集。
  3. **数据构建（知识注入）**：使用预训练至 1931 年的 Talkie 13B 模型，智能体从原始语料中提取 1930 年代后的事实，构造 context–question–answer 示例。训练采用冰冻教师向无上下文学生蒸馏的固定 forward KL 目标。ID 为 Novel（1930 后 1000 个事实），OOD 为 Retention（1930 前知识保持）。评估采用基于似然的多选题准确率。
- **实现细节**：
  - 智能体通过外部 API 访问；每个运行使用单张 A800 GPU，24 小时墙钟限制；
  - 每轮最多 20 次训练评估；
  - 提供 Qwen3-4B-Instruct 和 Qwen3-Embedding-0.6B 作为辅助模型进行批量数据处理和嵌入操作；
  - 每次训练从相同初始 checkpoint 开始，以保证数据干预之间的可比性。

## 3. 实验设计

- **评估对象**：7 个前沿大语言模型，来自 GPT、Claude、Kimi、DeepSeek、GLM 和 Qwen 家族，具体为 GPT-5.6-Sol、Kimi-3、Claude-4.7、Qwen-3.7-Max、Qwen-3.8-Max、GLM-5.2、DeepSeek-V4-Flash。
- **基准设置**：
  - 每个 LLM-任务组合进行 **3 次独立标准运行**，共 63 次运行；
  - 每次运行选择 ID 得分最高的 checkpoint，报告 3 次运行的 ID 均值/标准差、ID 最大值以及对应的 OOD 均值；
  - **Baseline**：工具使用随机采样 16k 污染池；检索随机采样 600k query-positive 对（无显式硬负例）；知识注入使用未训练的 Talkie 模型作为无训练参考；
  - **Expert reference**：工具使用对未污染池进行 schema 验证、去重和按类别比例选择；检索采用人工经验指导的硬负例挖掘和数据重组织；知识注入使用基于关键词和规则的人工挖掘。
- **预测实验**：对 GPT-5.6-Sol 和 Kimi-3 各进行一个任务级预测运行（共 6 个运行），在每次训练评估前记录预测分数、不确定性区间和理由。
- **数据引擎实验**：从 Qwen2.5-Coder-14B 基座出发，设置 50 亿 token 的中期训练预算，对比控制组（原始代码语料）与加入 AutoDataBench 轨迹（80M token，上采样 10 倍）的模型；随后进行相同 SFT，在 MBPP、CRUXEval Input、LiveCodeBench、SWE-bench Multilingual 上评估。

- **总体性能**：Kimi-3 以 60.68 的 Overall 得分最高，主要得益于知识注入任务；GPT-5.6-Sol 在工具使用和检索 ID 上领先。

- **检索**：GPT-5.6-Sol 的 ID 平均 nDCG@10 为 40.46，接近 expert reference（40.62），但其 OOD 表现最差（26.15）；反之 Qwen

Qwen-3.7-Max 和 Qwen-3.8-Max 的 OOD 下降幅度相对较小，但 ID 并非最高，说明检索任务中数据组织策略存在明显的 ID/OOD 权衡：单纯最大化目标指标可能损害泛化能力。  
- **知识注入**：Kimi-3 在 Novel ID（1930 后新事实）上表现突出，这是其 Overall 得分领先的主要原因；但所有模型在 Retention OOD（1930 前旧知识保持）上均出现一定程度的遗忘，说明通过构造数据注入新知识会以牺牲部分旧知识为代价，且不同 LLM 在“新知识获取”与“旧知识保持”之间的平衡能力存在差异。  
- **预测实验**：GPT-5.6-Sol 和 Kimi-3 在每次训练前给出的分数预测与实际结果之间存在系统性偏差，预测误差较大；不确定性区间也未能很好地校准真实波动。这表明当前 LLM 即使具备一定数据效应推理的直觉，仍主要依赖试错而非可靠的因果推断来优化数据。  
- **数据引擎实验**：在 50 亿 token 中期训练预算下，加入 AutoDataBench 轨迹的模型在 MBPP、CRUXEval Input、LiveCodeBench 和 SWE-bench Multilingual 上均优于仅使用原始代码语料的控制组。这说明高质量数据优化轨迹可以作为有价值的合成训练数据被复用，为“AI 生成数据训练 AI”提供了正面证据。

## 7. 论文的局限性与潜在问题

- **任务覆盖有限**：三个任务实例虽然覆盖诊断、组织、构建，但每个任务的具体数据规模和场景相对固定，尚不能全面代表真实数据智能的多样性（如多模态、长尾、隐私敏感数据等）。  
- **单次运行资源上限可能限制策略深度**：24 小时墙钟和单张 A800 GPU 的约束使智能体无法进行非常深层或大规模的数据实验，部分复杂策略可能因计算预算耗尽而无法充分展开。  
- **外部 API 智能体的不可控因素**：不同 LLM 供应商的速率限制、上下文窗口、输出稳定性和成本差异可能影响智能体的探索效率，造成一定不公平性；且 API 模型内部机制不可见，难以严格归因于数据智能本身。  
- **重复次数较少**：每个 LLM-任务组合仅 3 次独立运行，统计功效较低；对于高方差任务（如知识注入），3 次运行的均值可能不够稳健。  
- **预测实验规模小**：仅对两个模型、各一个运行进行预测记录，且与标准运行分离，因此对数据效应推理能力的结论仍属探索性，不具备广泛代表性。  
- **数据引擎实验的消融不足**：虽然控制组与实验组 token 预算和 SFT 设置匹配，但未消融轨迹数量、上采样比例、不同任务轨迹的贡献等关键变量，难以确定哪些轨迹类型真正带来增益。

## 8. 总结与启示

- **AutoDataBench 的核心贡献**：首次在受控条件下系统解耦数据智能与训练管线、超参数、计算预算等因素，为评估 LLM 作为数据研究智能体提供了可重复的基准。  
- **主要结论**：前沿 LLM 在数据优化任务上能够显著超越随机 baseline，部分接近人工 expert reference，但 ID 提升并不自动转化为 OOD 泛化；数据效应预测能力仍较弱；优化轨迹本身具备作为训练数据的复用价值。  
- **实践启示**：对于数据工程和自动化研究，不应只关注最终 ID 指标，还需要引入隐藏 OOD 评估、预测校准和成本约束，才能更全面判断智能体的数据智能水平。
