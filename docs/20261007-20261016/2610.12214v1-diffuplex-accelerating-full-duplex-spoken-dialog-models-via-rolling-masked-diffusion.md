## 摘要
近期全双工语音对话模型实现了同时聆听和说话，但细粒度模型仍以自回归方式在每一交互帧推进其骨干网络。我们提出 DiffuPlex，一种滚动掩码扩散框架，通过在单次骨干网络唤醒中预测多个未来用户与助手帧，来减少这种顺序计算。DiffuPlex 仅消费每个预测未来中置信度高的前缀，同时交互仍以原始帧率继续。当用户语音到达时，它检查相应的用户预测，当交互出现分歧时，保留已播放的助手内容，仅修正未播放的未来部分。我们在同一预测器上考虑两种推理策略：DiffuPlex-LISTEN 在预测到助手静默时消费多个未来帧，而 DiffuPlex-SPEAK 还可以消费预测的助手语音。在全双工交互和口语语言评估中，DiffuPlex 大幅减少了顺序骨干计算，同时基本保持了交互行为和通用能力。DiffuPlex-LISTEN 和 DiffuPlex-SPEAK 分别实现了 $1.46\times$ 和 $1.59\times$ 的部署路径墙上时钟加速，以及 $1.61\times$ 和 $1.80\times$ 的核心语言模型加速，且所有测量的骨干调用均在 80 毫秒交互间隔内完成。人类评估表明，LISTEN 保持了语音自然度和对话质量，而 SPEAK 在对话质量上保持，但语音自然度有所下降。

## Abstract
Recent full-duplex spoken dialog models enable simultaneous listening and speaking, but fine-grained models still advance their backbone autoregressively at every interaction frame. We introduce DiffuPlex, a rolling masked diffusion framework that reduces this sequential computation by predicting multiple future user and assistant frames in a single backbone wake. DiffuPlex consumes only a confident prefix of each predicted future while interaction continues at the original frame rate. As user speech arrives, it checks the corresponding user predictions and, when the interaction diverges, preserves already played assistant content while revising only the unplayed future. We consider two inference policies over the same predictor: DiffuPlex-LISTEN consumes multiple future frames when they predict assistant silence, whereas DiffuPlex-SPEAK can also consume predicted assistant speech. Across full-duplex interaction and spoken-language evaluations, DiffuPlex substantially reduces sequential backbone computation while largely preserving interaction behavior and general capability. DiffuPlex-LISTEN and DiffuPlex-SPEAK achieve $1.46\times$ and $1.59\times$ deployment-path wall-clock speedups and $1.61\times$ and $1.80\times$ Core LM speedups, with all measured backbone invocations completing within the 80ms interaction interval. Human evaluation shows that LISTEN preserves speech naturalness and conversational quality, while SPEAK retains conversational quality with some degradation in speech naturalness.

## 1. 论文的核心问题与整体含义

- **研究背景**：全双工语音对话模型（如 Moshi、PersonaPlex）支持用户与助手同时说话、打断、重叠和反向通道等自然交互行为。
- **核心问题**：细粒度全双工模型通常以 80ms 为交互帧，每帧都需要对时间骨干网络做一次自回归前向计算，导致整个对话期间骨干推理开销巨大。
- **研究动机**：人类对话中约 95.3% 的活跃通话时间只有一方在说话，且说话内容可以被提前规划若干帧；文本生成中的推测解码、扩散语言模型已经利用类似冗余进行加速，但全双工语音的未来用户输入尚未来临，无法直接验证助手草稿。
- **整体含义**：论文提出 DiffuPlex，用滚动掩码扩散替代逐帧自回归推进，在单次骨干唤醒中预测多个未来用户与助手帧，只消费置信前缀，并在用户输入偏离预测时修订未播放的未来，从而显著减少顺序骨干计算，同时基本保持交互行为与通用能力。

## 2. 方法论

- **核心思想**：将逐帧自回归推进替换为对短未来块的掩码预测。每次骨干唤醒（backbone wake）预测一个未来窗口（最大 W=16 帧，约 1.28s），只保留置信的前缀并播放；用户预测被存储用于一致性检查；若观察到的用户输入与预测不一致，则丢弃未播放部分并重新唤醒修订。

- **掩码未来预测（Masked Future Prediction）**：
  - 在训练中，把对话分成可变长度块，块长度 $L_{\text{blk}} \sim U\{1,\dots,W\}$；每个块起始处重置 lookahead $h=1$，块内 $h$ 逐渐增大。
  - 对未来位置，将不可用的流用可学习的流特定 MASK token 替换：$h\ge2$ 时掩码助手文本和助手音频流；$h\ge3$ 时额外掩码用户语义码本 cb0；$h\ge4$ 时掩码用户声学码本 cb1–7。原生码本延迟保持不变。
  - 冻结原骨干，只训练流特定 MASK embedding 和未来门控 LoRA；门控函数 $g(h)=1[h\ge2]$，保证 $h=1$ 走原始自回归路径，$h\ge2$ 使用学习到的未来路径。
  - 训练目标为蒸馏损失：最小化掩码学生分布与干净自回归教师分布之间的 KL 散度，包括文本分布、三状态文本分布（PAD/EPAD/lexical）和加权音频码本分布的 KL。

- **滚动草稿生成（Rolling Draft Generation）**：
  - 对每个 lookahead $h$ 采样助手文本 token $y_h$，置信度 $C_h=\text{softmax}(z_h)_{y_h}$（在温度缩放和 top-k 之前计算）。
  - 定义两种保留策略：
    - **DiffuPlex-LISTEN**：只允许保留助手文本状态为 PAD 的位置，并要求候选前缀达到最小长度 $m=6$。
    - **DiffuPlex-SPEAK**：允许 PAD、EPAD 和 lexical 状态，最小长度 $m=2$。
  - 保留前缀长度 $\tilde r$ 由第一个不满足状态约束或置信度低于 $\tau_{\text{conf}}=0.80$ 的位置决定；若 $\tilde r$ 小于策略最小长度，则只保留 $h=1$。
  - $h=1$ 的下一帧预测总是保留，保证每次唤醒至少推进一个 80ms 帧。

- **用户感知草稿修订（User-Aware Draft Revision）**：
  - 在未唤醒骨干的情况下，比较存储的用户预测分布与观察到的用户语义 token。
  - 修订得分：$S_h = -\log q_h(x_h) + \log P_h(\mathcal{A}_h(y_h)) - \log P_h(y_h)$，其中 $q_h$ 是用户预测分布，$x_h$ 是实际到达的用户 token，$P_h$ 是助手文本分布，$\mathcal{A}_h(y_h)$ 是有效替代 token 集合。
  - 解释为近似后验几率检验：第一项衡量用户输入在预测下的意外程度，后两项衡量助手对所选 token 的承诺强度。
  - 当 $S_h \ge \tau_{\text{rev}}$（默认 $\tau_{\text{rev}}=-0.5$）时触发修订；已播放的助手帧和已接收的用户帧保持固定，仅未播放未来被丢弃并重新预测。
  - 该过程反复进行，称为滚动掩码扩散。

## 3. 实验设计

- **骨干模型**：基于 `personaplex-rl-seamless`（PersonaPlex 的 RL 后训练版本），12.5Hz（80ms/帧），17 条流（1 条助手文本、8 条助手 Mimi 音频码本、8 条用户 Mimi 音频码本）。
- **训练数据**：Seamless Interaction 数据集，过滤后 42,413 个会话、约 2,728.5 小时对话，用 Qwen3-ASR 转写、Qwen3-ForcedAligner 对齐、Silero VAD、Mimi 编码。
- **评估基准与场景**：
  - **全双工交互**：Full-Duplex-Bench v1.0（727 clips，含暂停处理、反向通道、平滑轮流、用户打断）和 v1.5（498 examples，含背景语音、与他人说话、用户反向通道、用户打断）。
  - **通用口语能力**：VoiceBench（7,783 examples，9 个任务）和 OpenAudioBench（2,499 examples，4 个英文子集），分别评估 $s\to t$（文本流）和 $s\to s$（生成语音转录）。
  - **人类评估**：MTurk 上进行 NMOS（语音自然度，200 份有效）和 DMOS（对话自然度，180 份有效）。
  - **推理效率**：固定 60-clip 子集，单张 RTX A6000，报告流式墙钟、端到端 GPU 时间、Core LM 时间、每唤醒推进帧数、唤醒延迟等。
- **对比方法**：
  - 自回归基线：Moshi、PersonaPlex、`personaplex-rl-seamless`。
  - 训练免费延迟执行基线：PAD、SILERO、SMART TURN，这些方法推迟骨干调用并在跳过的帧上强制静音，不预测未来交互。
  - DiffuPlex 两种策略：LISTEN 和 SPEAK。
- **主要超参数**：$W=16$，$\tau_{\text{conf}}=0.80$，$\tau_{\text{rev}}=-0.5$，LISTEN $m=6$，SPEAK $m=2$。

## 6. 主要结论与发现

- **效率提升**：在全双工交互基准上，DiffuPlex-LISTEN 平均每次骨干唤醒推进 1.91 帧，SPEAK 推进 2.23 帧；在固定 60-clip 运行时子集上，墙钟加速分别 1.455× 和 1.590×，Core LM 加速分别 1.608× 和 1.797×，所有骨干调用均在 80ms 内完成。
- **交互行为保持**：与自回归骨干相比，DiffuPlex 在暂停处理、反向通道、轮流、用户打断等指标上总体接近，配对统计检验未检测到显著差异（但不等同于正式等价）。
- **策略差异**：LISTEN 在人类评估中保持语音自然度（NMOS 3.92 vs 3.93）和对话质量（DMOS 4.08 vs 4.09）；SPEAK 保持对话质量（4.07）但语音自然度下降（3.54 vs 3.93），接近 Moshi 水平。
- **通用能力**：LISTEN 在 VoiceBench 和 OpenAudioBench 上与骨干几乎一致；SPEAK 有轻微下降，尤其 OpenAudioBench $s\to s$。
- **延迟执行不足**：训练免费基线通过跳帧静音获得更高速度，但显著抑制反向通道、降低助手说话比例、增加轮流延迟；DiffuPlex 通过预测中间交互更好地保持全双工动态。
- **未来语音质量下降机制**：SPEAK 的语音自然度下降主要源于深度未来位置缺少同一帧语义码本 cb0 的条件输入；恢复同帧 cb0 可将 cb1–7 NLL 降低 0.091（语音期间），自回归重放可将 UTMOSv2 从 2.646 恢复到 2.894，大部分质量差距可恢复。
- **消融结论**：
  - 置信度过滤和修订机制互补：去除置信度过滤增加推进帧数但可能损害交互（尤其 SPEAK 的 Judge 分数大幅下降）；去除修订显著降低响应性（反向通道频率下降、轮流延迟增加）。
  - 未来门控保护原始自回归路径；仅用 CE 硬目标会缩短可用未来；三状态文本蒸馏和 token 级文本 KL 都有贡献。
  - 方法可以迁移到 PersonaPlex 骨干上减少唤醒次数，但交互行为保持不佳，说明迁移不自动。
  - 训练与推理 horizon 不匹配时，推进帧数变化不大，但增大 horizon 会增加单次唤醒成本，降低池化 LM 加速。

## 7. 优点

- **方法创新**：将滚动掩码扩散引入全双工语音对话场景，解决“未来用户输入尚未到达”的核心挑战，利用联合预测用户与助手流实现并行推进。
- **保留/修订机制设计合理**：通过置信度阈值、策略特定状态约束和最小长度，保留自信前缀；修订规则基于近似后验几率，结合用户输入意外度和助手承诺度，无需额外骨干调用即可判断是否修订。
- **两种策略提供灵活速度-质量权衡**：LISTEN 保守但保持语音自然度；SPEAK 激进但保持对话质量。
- **扎实的实验设计**：
  - 与训练免费延迟执行基线对比，清晰证明预测未来优于简单跳帧。
  - 广泛消融覆盖训练目标、规模、horizon、置信度、修订阈值、注意力模式、修订信号分解等。
  - 深入分析未来语音质量下降机制，通过干预实验和自回归重放定位原因。
  - 统计检验、人类评估、固定子集运行测量保证结果可信。
- **保持骨干冻结与自回归路径不变**：只训练 LoRA 和 MASK embedding，训练成本低；$h=1$ 路径与原始模型完全一致，实现逐 token 等价的边界情况验证。

## 8. 不足与局限

- **未来语音质量下降未完全解决**：SPEAK 策略在人类评估中语音自然度明显下降，尤其是在较长助手语音段；论文仅提供诊断分析，未给出实际可用的未来语音建模改进。
- **骨干迁移性有限**：方法在 `personaplex-rl-seamless` 上效果良好，但迁移到原始 PersonaPlex 骨干时交互行为显著退化，说明依赖骨干已有的交互能力；未在其他全双工架构（如单流模型）上验证。
- **运行效率受硬件和实现影响**：报告的速度提升依赖特定 GPU、软件栈和实现；仅用了英文评估，未测试多语言或低资源场景。
- **人类评估范围**：NMOS 和 DMOS 仅基于用户打断示例，可能无法代表所有交互场景的主观质量。
- **训练免费基线的不公平之处**：SILERO 和 SMART TURN 的控制器 CPU 推理成本不计入墙钟时间，而实际部署中可能影响实时性。
- **延迟执行基线设计限制**：延迟期间强制助手静音，导致反向通道和说话活动被抑制；但这类基线仍回答了“不预测未来能否达到类似加速”的问题，结论有参考价值。
- **推理策略规则是启发式的**：保留前缀长度和修订阈值由手工设定，未与未来预测器联合学习；可能存在更优的学习式策略。
- **没有正式等价性证明**：统计检验未检测到显著差异，但不能作为系统等价性的证据；某些指标（如 LISTEN 的暂停 TOR、SPEAK 的反向通道 TOR）在数值上有变化，实际应用中需权衡。
