## 摘要
最近的语音全双工（FDX）模型能够通过同时倾听和说话来进行自然对话。在此基础上，最近的架构引入内部思维流以增强智能。为了确保这些流在实时中成功处理，现有方法强制执行固定解码速率，这假设了能够达到特定延迟的硬件配置。我们认为这种静态方法严重次优。由于内部思维本质上是异步的，理想的FDX模型应在维持实时对话流的同时，允许每个流以其自身的硬件自适应速率解码。思维流必须以硬件允许的最快速度处理，以便更快地给出准确答案。为了解决这一问题，我们提出了RUBATO，一种新颖的多流位置编码，为各流分配独立时钟以完全解耦。这种结构隔离使模型能够零样本插值到任意推理解码速度。它大幅简化了数据集构建，只需在两种极端解码速度上训练，同时在部署期间平滑适应任意中间速率。RUBATO在五个语音推理任务上表现出一致的鲁棒性。在Spoken GSM8K上，基线模型在插值速度下准确率骤降至1.7%。相反，RUBATO-Full在所有速率下保持48.7%至51.1%的准确率，利用更快硬件将回答时间缩短6.5倍，同时首次响应时间保持不变。这一优势在BIG-Bench Audio上依然成立，并在复杂的全双工打断中显著放大。具体而言，当用户在模型正在说话和推理时插话，RUBATO-Full达到40.0%至45.1%的准确率，而基线完全失败。

## Abstract
Recent Speech Full-Duplex (FDX) models are capable of engaging in naturalistic conversation by listening and speaking at the same time. Building on this foundation, recent architectures introduce internal thinking streams to enhance their intelligence. To guarantee these streams process successfully in real time, existing methods enforce a fixed decoding rate, which assumes a hardware profile capable of a specific latency. We argue this static approach is severely suboptimal. Because internal thinking is intrinsically asynchronous, an ideal FDX model should sustain real-time conversational flow while allowing each stream to decode at its own hardware-adaptive rate. Thinking streams must process as fast as the hardware allows to deliver accurate answers faster. To solve this, we propose RUBATO, a novel multistream positional encoding that assigns independent clocks to entirely decouple the streams. This structural isolation empowers the model to zero-shot interpolate across any inference decoding speed. It drastically simplifies dataset construction by requiring training on only two extreme decoding speeds while smoothly adapting to any intermediate rate during deployment. RUBATO demonstrates consistent robustness across five spoken reasoning tasks. On Spoken GSM8K, a baseline model collapses to 1.7% accuracy at interpolated speeds. Conversely, RUBATO-Full sustains 48.7% to 51.1% accuracy across all rates, leveraging faster hardware to achieve a 6.5x shorter time-to-answer with a constant time-to-first-response. This advantage holds on BIG-Bench Audio and amplifies significantly during complex full-duplex interruptions. Specifically, when a user interjects while the model is actively speaking and reasoning, RUBATO-Full achieves 40.0% to 45.1% accuracy, whereas the baseline fails completely.

## 1. 论文的核心问题与整体含义

- **研究背景**：语音全双工（Speech Full-Duplex, FDX）模型能够同时听和说，支撑自然对话。近期工作进一步引入“内部思维流”（thinking stream），使模型在实时对话中执行链式思考、推理或工具调用。
- **核心矛盾**：实时音频流（用户音频、系统音频、用户文本、系统文本）必须按严格物理时间步进，而内部思维流本质上是异步的、不需要实时对齐。传统 FDX 模型把两类流放在同一个位置时钟下，并强制固定思维解码速率，假设某个特定硬件延迟。
- **问题表现**：
  - 解码速率固定为某硬件假设时，若硬件更快，模型无法“想得更快”，浪费算力；
  - 若硬件更慢，模型可能无法实时生成音频，导致响应停滞；
  - 不同 GPU、软件框架、服务器负载会使实际解码速度大幅波动，而针对每种速度分别训练不现实。
- **整体含义**：论文提出应让每条流拥有独立、硬件自适应的节奏：实时流保持稳定向前，思维流能随可用算力尽可能快地解码。这样既能保持对话流畅度，又能用更快硬件直接换取更短的回答时间。

## 2. 论文提出的方法论

### 2.1 核心思想：独立时钟解耦

- **现有方案缺陷**：传统 Single-Clock 把扁平序列中所有 token 用同一个连续位置索引编码。一旦在不同帧之间插入数量可变的思维 token，实时 token 之间的位置距离就被拉伸或压缩，造成时序分布偏移，模型无法稳定学习真实的流对齐关系。
- **RUBATO 核心**：给不同流分配独立的位置时钟。实时流（用户音频、系统音频、用户文本、系统文本）共用一个实时时钟；思维流用另一个思维时钟。每个时钟只在自己对应 token 上递增，在其他 token 上暂停。
- **位置表示**：每个 token 不再只有一个标量位置，而是携带一个 C 维位置向量。对两时钟设置，C=2，一个维度是实时位置，另一个是思维位置。
- **位置定义**：对任意扁平序列位置 t，设 κ(t) 表示该 token 所属时钟；n_c(t) 表示截至 t 位置时钟 c 出现过的 token 数；p_c(t) 为最近一个时钟 c token 的零基索引。这样实时 token 的位置不因思维 token 数量而变化，思维 token 的位置也不因实时 token 插入而中断。

### 2.2 三种注意力变体

- **RUBATO-Split**：
  - 将旋转位置编码（RoPE）的 D 维旋转空间划分成 C 个连续子空间。
  - 每个子空间使用对应时钟的位置进行旋转。
  - 注意力分数是各子空间旋转后点积之和。
  - 缺点：所有时钟都会对任意 query-key 对施加旋转，可能引入无关时钟的噪声，并且频率分辨率被稀释。

- **RUBATO-Gated**：
  - 为避免无关时钟干扰，只对 query-key 对中“关键 token 所属时钟”对应的子空间做旋转，其余子空间保持原始点积。
  - 理论依据：同流 token 自然使用共享时钟；不同流 token 使用 key 的时钟，使 query 能区分该 key 所在流。

- **RUBATO-Full**：
  - 进一步看到：每个 query-key 对实际只有 key 的时钟决定旋转，因此直接用该时钟旋转全部维度。
  - 不再划分子空间，因此避免频率基稀释，保持与预训练 backbone 原 RoPE 频率范围完全一致。
  - 实验证明该变体最稳定、性能最好。

### 2.3 训练与推理实现

- **训练**：
  - 为在不修改 FlashAttention 等融合 kernel 的情况下实现按 key 时钟旋转，采用“维度扩展”技巧。
  - 对 query，预先计算所有可能时钟的旋转并并排放置；对 key，只保留其自身时钟的旋转，其余置零。点积自然选出正确时钟分量。
  - 该实现等价于原始公式，且不需要自定义 Triton kernel。
- **推理**：
  - 去掉训练时的维度扩展，避免解码速度下降。
  - 维护多个独立 KV cache；每个 key 按其时钟旋转后存入对应 cache。
  - 对 query 生成多个旋转副本，分别与对应 cache 计算 attention，再用 log-sum-exp 合并 softmax 结果。
  - 实测多 KV cache 解码速度与 Single-Clock 基本持平，保障思考预算 B 不受额外延迟损害。

### 2.4 训练数据简化：只用两个极端预算

- 定义每帧可插入的思维 token 数为 thinking budget B。
- 训练只在两种边界布局上构建数据：
  - **B=1**：思维 token 逐帧与实时 token 交错，思考过程跨多帧完成，系统可先生成语音填充（filler）保持对话轮次；
  - **B=∞**：整个思维轨迹在一帧内瞬时完成，系统直接说答案，思考过程从物理时间上解耦。
- 由于 RUBATO 结构上把两类时间线分离，模型能够在训练端点之间进行零样本插值，无需为每个中间 B 重新生成对齐数据。

## 6. 论文的主要结论与发现

- **RUBATO 在未见预算上鲁棒插值，Single-Clock 崩溃**：
  - Spoken GSM8K 上，Single-Clock 在插值速度下准确率跌至 **1.7%**；
  - RUBATO-Full 在所有速率下保持 **48.7% 到 51.1%** 的准确率；
  - 在 BIG-Bench Audio 上同样保持明显优势。
- **RUBATO 直接利用更快硬件降低回答延迟**：
  - RUBATO-Full 在保持 TTFR 稳定的同时，TTA 随预算增大显著下降，最高可达 **6.5 倍** 缩短。
- **RUBATO-Full 在复杂全双工打断场景中优势放大**：
  - 用户插话且模型正在说话/推理时，Single-Clock 与 RUBATO-Split 几乎完全失败；
  - RUBATO-Full 在从未见过的速率下回答插话问题准确率达到 **40.0% 到 45.1%**，基线和 Split 则接近失败。
- **时钟构造选择影响显著**：
  - RUBATO-Split 因为对所有 query-key 对施加所有时钟旋转，存在跨时钟噪声，插值稳定性较差；
  - RUBATO-Gated 消除该噪声，单轮场景接近 Full，但在重叠对话中差距扩大；
