## 摘要
现有的全模态大语言模型令牌压缩方法通常依赖一种模态来决定另一种模态中需要保留的内容。我们证明了这一假设经常失效：对于相同的查询，音频和视频的相关性往往在不同时刻达到峰值。这种跨模态显著性不匹配使得单向引导在激进压缩下容易丢弃对答案至关重要的线索。我们提出 OmniScope，一个无需训练的令牌压缩框架，以查询作为共享语义锚点，同时分别估计音频和视频的相关性。OmniScope 分配模态特定的令牌预算，通过锚点-增量策略修剪视觉令牌，既保留全局上下文又保留时间变化，并在每一秒内合并音频令牌，以减少冗余同时保持时间连续性。在四个音视频基准和两个 Qwen2.5-Omni 模型规模上，OmniScope 在所有压缩设置下均取得最佳平均准确率。在总体令牌保留率为 25% 时，它实现了高达 3.53 倍的预填充加速和超过 15% 的 GPU 内存减少，而平均准确率仅下降 0.35 个百分点。这些结果表明了全模态大语言模型推理的一个简单设计原则：跨模态共享查询，但不共享显著性估计。代码可在 https://github.com/MAC-AutoML/OmniScope 获取。

## Abstract
Existing token compression methods for omnimodal large language models typically rely on one modality to determine what to retain in the other. We show that this assumption often breaks down: for the same query, audio and video relevance often peaks at different moments. This cross-modal salience mismatch makes unidirectional guidance prone to discarding answer-critical cues under aggressive compression. We propose OmniScope, a training-free token compression framework that uses the query as a shared semantic anchor while estimating relevance separately for audio and video. OmniScope allocates modality-specific token budgets, prunes visual tokens with an anchor-delta strategy that preserves both global context and temporal changes, and merges audio tokens within each second to reduce redundancy while maintaining temporal continuity. Across four audio-video benchmarks and two Qwen2.5-Omni model scales, OmniScope achieves the best average accuracy across all compression settings. At 25% overall token retention, it delivers up to 3.53x prefill speedup and more than 15% GPU memory reduction, with only a 0.35-point drop in average accuracy. These results suggest a simple design principle for OmniLLM inference: share the query across modalities, but not the salience estimates. The code is available at https://github.com/MAC-AutoML/OmniScope.

## 1. 论文的核心问题与整体含义

- **研究背景**：全模态大语言模型（OmniLLMs）能够同时处理视觉、听觉和文本模态，在视频问答、内容审核等任务中展现出优势，但推理时音视频令牌数量随视频时长急剧增长，带来严重的计算与内存开销。
- **核心问题**：现有训练无关的全模态令牌压缩方法（如OmniZip）采用**单向跨模态引导**策略——用一种模态的重要性分数决定另一种模态哪些令牌要保留。这种策略隐含假设两种模态对同一查询的相关性模式是同步的。
- **关键发现**：论文通过分析发现，**跨模态显著性错位**普遍存在：视频和音频对同一查询的相关性峰值往往出现在不同时刻（约78.3%的样本仅有弱相关）。在激进压缩下，单向引导容易**丢弃回答所需的关键线索**（例如音频中“哨声”在早期突出，而视觉“手势”在晚期重要）。
- **整体含义**：提出一个简单却有效的设计原则——**跨模态共享查询（语义锚点），但不共享显著性估计**，从而让每个模态独立决定自身的压缩策略，避免跨模态干扰。

## 2. 方法论

OmniScope 是一个**训练无关、查询感知的全模态令牌压缩框架**，分为三个阶段。

- **阶段一：查询感知的模态独立评分**
  - **视觉评分**：使用外部 CLIP 模型计算每一帧与查询的余弦相似度，得到帧级重要性分数 \(s_v^{(t)}\)。
  - **音频评分**：不用外部模型（如 CLAP 粗粒度不适用），而是**复用 OmniLLM 自身的音频编码器输出和投影后的嵌入**。将音频令牌嵌入与查询令牌嵌入计算门控交叉相似度，利用词嵌入范数作为门控信号抑制无信息令牌，得到每秒的音频重要性分数 \(s_a^{(s)}\)。在此基础上，对高分秒附近的位置施加衰减传播增强，以利用音频的时序连续性。
  - **预算分配**：给定全局保留比，按位置重要性比例分配每个帧/秒应保留的令牌数，**视觉和音频独立分配**，不跨模态比较。

- **阶段二：视觉令牌压缩——锚点‑增量时空压缩（AD‑STC）**
  - 交替将视频帧划分为 **锚点帧（偶数帧）** 和 **增量帧（奇数帧）**。
  - **锚点帧**：采用基于密度峰值的 K 近邻聚类方法，选择局部密度最低（即最具区分性）的令牌保留，以捕获当前时刻的核心语义。
  - **增量帧**：根据该帧分配到的保留比 \(r\)，自适应切换评分策略：
    - **低压缩（\(r \ge \tau_r\)，预算充裕）**：采用**联合时空不可替代性得分**，同时考虑帧内空间可替代性和相对于前一锚点帧的时间可替代性，通过乘积融合，仅当令牌在两个维度同时高度可替换时才被丢弃，从而在空间和时间上实现均匀的全局覆盖。
    - **高压缩（\(r < \tau_r\)，预算紧张）**：**仅使用时间差异准则**，保留与前一锚点帧同一位置变化最大的令牌，集中有限预算获取密集的局部时间增量，避免信息碎片化。

- **阶段三：音频令牌压缩——每秒二分软合并**
  - 在每一秒内，将音频令牌按奇偶索引分为源集和目的集，计算相似度矩阵，选择最相似的 \(m\) 对进行**令牌合并**（平均融合），而不是简单丢弃。合并操作可迭代进行，从而在保持时间连续性的同时减少冗余。

## 6. 主要结论与发现

- **性能最优**：在所有压缩设置下，OmniScope 均取得**最佳平均准确率**。在 45% 保留率时接近无损（7B 模型准确率甚至略超全令牌基线）；在 25% 激进压缩下，7B 模型平均准确率仅下降 0.35 点，而 OmniZip 下降 1.55 点。
- **鲁棒性强**：独立性压缩比扫变实验表明，OmniScope 随压缩率增大性能下降最平缓，而基于单向引导的方法在高压缩比下骤降。
- **效率显著**：25% 保留时实现**最高 3.53× 预填充加速**和**超过 15% 的 GPU 显存减少**，且内存开销低于 OmniZip。
- **核心发现**：验证了“跨模态共享查询但不共享显著性估计”的设计原则——各模态独立评估自身与查询的相关性，可有效避免因显著性错位导致的信息丢失，并使压缩带来的跨窗口注意力增强集中到任务相关线索上。

## 7. 优点

- **设计原则简洁有效**：直接针对跨模态显著性错位问题，提出模态解耦方案，避免复杂的跨模态依赖。
- **训练无关**：无需任何微调，可即插即用于多种 OmniLLM。
- **双模态细致处理**：
  - 视觉端利用锚点‑增量交替机制，平衡全局语义覆盖与时间增量，并根据压缩比自适应切换策略。
  - 音频端利用模型内部嵌入进行细粒度评分，并通过合并而非丢弃保持时间连续性。
- **实验扎实**：大量消融定量证实了每个组件的必要性，鲁棒性分析充分。
- **开源**：代码公开，有利于复现与后续研究。

## 8. 不足与局限

- **视觉评分的额外负担**：依赖外部 CLIP 模型进行视觉评分，引入额外计算开销和存储需求，且在非常短的生成场景下延迟占比较高（尽管会随生成长度摊销）。
- **视觉评分器选择**：实验显示小模型（3B）自身视觉‑文本对齐不佳，使用内部嵌入效果较差，暗示未来更大模型可能不需要外部评分器，但目前仍需 CLIP。
- **压缩比固定**：方法虽在不同压缩比下表现稳定，但视觉和音频压缩比需手动指定，尚未实现完全自适应的预算确定。
- **仅限于训练无关压缩**：未探索与训练结合的方法（如 OmniSIFT），虽然此类方法可能因需要训练而泛化性受限，但对比缺失可能使性能上界不完全明确。
- **数据集可能有限**：虽已覆盖四个基准，但视频领域尚缺乏更多元的长视频、细粒度事件理解任务，进一步测试可增强说服力。
- **解码阶段收益有限**：加速主要体现在预填充阶段，在仅输出短答案的 QA 任务中端到端提升不如长生成场景显著。
