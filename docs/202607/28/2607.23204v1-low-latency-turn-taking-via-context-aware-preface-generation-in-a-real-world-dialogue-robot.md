## 摘要
基于大语言模型（LLM）的对话系统因仅在最终语音识别完成后才开始生成而遭受响应延迟。虽然固定填充语是一种变通方法，但时间一长就会显得不自然。我们提出了一种两阶段增量框架，将序言响应的准备与语音开始相解耦。一旦用户意图变得可预测，意图就绪检测器就会触发基于LLM的短序言响应生成。同时，语音活动投影（VAP）模型决定何时传递它。通过在购物中心与路线引导机器人进行的实地实验，我们评估了三种条件：无填充语、固定填充语和上下文序言。相对于无填充语，固定填充语和上下文序言均显著降低了初始响应延迟。相对于固定填充语，上下文序言的初始响应延迟显著更长，但初始到主要内容之间的间隔显著更短。探索性评分显示无显著差异。这些结果表明了一种时间权衡。

## Abstract
Large language model (LLM)-based dialogue systems suffer response delays because generation begins only after final speech recognition. While fixed fillers are a workaround, they become unnatural over time. We propose a two-stage incremental framework that decouples prefatory-response preparation from speech onset. Once user intent becomes predictable, an intent readiness detector triggers LLM-based generation of a short prefatory response. Concurrently, a voice activity projection (VAP) model determines when to deliver it. Through a field experiment with a route-guidance robot in a shopping mall, we evaluated three conditions: no-filler, fixed-filler, and contextual-preface. Both fixed-filler and contextual-preface significantly reduced initial response latency relative to no-filler. Relative to fixed-filler, contextual-preface had significantly longer initial response latency but a significantly shorter initial-to-main gap. Exploratory ratings showed no significant differences. These results indicate a timing trade-off.

### 2. 论文提出的方法论

*   **核心思想**： 提出一个**两阶段增量式响应生成框架**，将序言回应（prefatory response）的准备与语音的起始点（speech onset）解耦。系统不需要等用户说完完整的一句话，而是在其意图初步显现时就提前准备一个简短、上下文相关的开场白。
*   **关键技术细节与流程**：
    *   **整体架构**：
        1.  **增量式语音转文本（STT）**： 持续获得用户的局部识别结果。

            *   **训练数据与策略**： 采用两阶段训练。首先在 LLM 伪标注的大规模语料库（约76.5万条）上预训练，然后在人工标注的语料库（约3.1万条）上微调。数据经过多样化处理，包含犹豫、自我修正等真实口语现象。训练时使用焦点损失（focal loss）和加权采样来处理类别不平衡问题。
        3.  **语音活动投影（VAP）模型**： 独立工作，根据用户的声学信号实时预测用户是否即将结束当前话轮，从而决定系统发言的**最佳时机**。
        4.  **序言回应生成（Stage 1）**： 当意图就绪检测器“开火”后，系统调用一个速度较快的 LLM（`gpt-4o-mini`），基于对话历史和当前部分话语，生成一个极其简短的序言回应。该回应有严格限制，例如不超过 10 个日语字符，且不能引入新信息或做出具体承诺，仅作为填充或过渡。
        5.  **主回应生成与交付（Stage 2）**： 当完整的 STT 结果可用后，系统调用能力更强的 LLM（`gpt-4o`）生成主体的、包含实质性信息的回应。主回应的生成与序言回应的**播放是并行的**，从而大大缩短了主回应出现前的间隔。
*   **工作流示例**：
    *   系统问：“您想去哪里？”
    *   用户说：“麦当劳…”（部分语音）
    *   意图检测器触发 → 系统准备序言回应：“汉堡店…”
    *   VAP预测用户说完 → 系统立即说出：“汉堡店…”
    *   同时，用户语音结束（“…挺不错的。”），系统后台生成主回应 → 序言说完后立即衔接：“…在一楼。”
