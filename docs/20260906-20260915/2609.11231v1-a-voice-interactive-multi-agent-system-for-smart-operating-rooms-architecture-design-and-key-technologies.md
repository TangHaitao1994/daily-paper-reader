## 摘要
本文提出了SurgicalRoomAgent，一个基于大语言模型（LLMs）的智能手术室语音交互多智能体系统。该系统通过分层架构实现自然语言理解、设备控制、术中记录和手术报告生成，该架构包括语音交互流水线（唤醒、ASR、说话轮次检测、智能体推理、TTS）和智能体核心（技能注册表、任务规划器、设备管理器）。研究了三项关键技术：（1）面向低延迟推理的KV Cache前缀预热，通过字节级最长公共前缀复用，将重计算开销从约500毫秒降至数十毫秒；（2）流式部分JSON解析与提前并行任务执行，使端到端延迟降低约30%；（3）渐进式技能提示披露，根据用户角色、已连接设备和手术阶段动态过滤系统提示，以在有限上下文窗口内最大化信息密度。系统采用Qwen3-27B模型，并使用llama.cpp/sglang推理引擎实现。实验分析表明，系统在16,384个token的上下文限制内能够有效运行，且多设备并行控制的响应时间满足手术室实时性要求。

## Abstract
This paper presents SurgicalRoomAgent, a voice-interactive multi-agent system for smart operating rooms based on large language models (LLMs). The system achieves natural language understanding, device control, intraoperative recording, and surgical report generation through a layered architecture comprising a voice interaction pipeline (wake, ASR, turn detection, agent reasoning, TTS) and an agent core (skill registry, task planner, device manager). Three key technologies are investigated: (1) KV Cache prefix warming for low-latency inference, reducing recomputation overhead from approximately 500 ms to tens of milliseconds via byte-level Longest Common Prefix reuse; (2) streaming partial JSON parsing with early parallel task execution, reducing end-to-end latency by approximately 30%; and (3) progressive skill prompt disclosure, which dynamically filters system prompts based on user role, connected devices, and surgical phase to maximize information density within limited context windows. The system is implemented using the Qwen3-27B model with llama.cpp/sglang inference engines. Experimental analysis demonstrates effective operation within a 16,384-token context limit and multi-device parallel control response times meeting OR real-time requirements.

### 2.2 关键技术细节

1. **KV Cache前缀预热（KV Cache Prefix Warming）**
   - **问题**：设备状态变化导致系统提示+用户消息前缀变化，需重新预填充约12,662个token，耗时约500ms。
   - **核心思想**：将用户输入放在JSON末尾，空字符串占位符 `""` 恰好2字节；替换为真实输入不改变前缀字节，使llama.cpp的token级最长公共前缀（LCP）匹配缓存命中。
   - **PromptWarmer组件**：
     - 去重（TTL 10s）、防抖（300ms）、单线程执行（`ThreadPoolExecutor(max_workers=1)`）、静默失败、强制模式。
     - 预热请求参数：`max_tokens=1, stream=True, timeout=30s, cache_prompt=True`。
   - **效果**：预填充开销从约500ms降至约50–80ms（改善83%–90%），TTFT从约600ms降至约150–200ms。
   - **诊断机制**：通过MD5短哈希比对预热前缀与真实请求前缀是否一致。

2. **流式部分JSON解析与提前任务执行**
   - **核心思想**：LLM流式输出过程中实时解析部分JSON，检测到完整 `tasks` 数组后立即启动并行任务执行，实现“边生成边执行”。
   - **实现**：
     - `extract_partial_field`、`try_extract_tasks`、`is_field_complete` 等函数提取部分JSON字段。
     - 检测到 `tasks` 数组闭合（`]`）后，用 `ThreadPoolExecutor(max_workers=1)` 提交 `execute_parallel_sync`。
     - `response` 字段完全闭合时立即触发TTS，无需等待完整JSON。
   - **效果**：端到端延迟降低约30%，TTS播放延迟改善约40%。

3. **渐进式技能提示披露（Progressive Skill Prompt Disclosure）**
   - **三层过滤**：
     - **角色过滤**：按用户角色过滤无权限技能。
     - **设备条件过滤**：检查技能YAML frontmatter中 `conditions.connected_devices`，跳过未连接设备的技能提示。
     - **手术阶段过滤**：检查 `conditions.surgery_phase`，跳过当前阶段不相关的技能提示。
   - **技能提示文件格式**：YAML frontmatter声明激活条件 + Markdown正文。
   - **效果**：护士角色/少设备场景可减少系统提示约15%–20%，释放2,000–3,000 tokens。

4. **二元话轮检测（Binary Turn Detection）**
   - 采用独立LLM实例，GBNF语法约束输出为 `"0"`（闲聊/噪声）或 `"2"`（医疗命令）。
   - 维护最近5轮 `{user, assistant}` 对话对，利用语义理解区分环境噪声和有效命令。

5. **DAG任务规划与调度**
   - **任务计划JSON格式**：支持单任务（`slots + response`）和多任务DAG（`tasks` 数组，含 `id`、`intent`、`slots`、`depends_on`）。
   - **Kahn算法分层拓扑排序**：构建邻接表和入度表，同层任务无依赖可并行。
   - **DFS三色环检测**：用白/灰/黑标记检测循环依赖。
   - **执行**：同层任务并行，层间顺序执行；支持依赖关系自动串行。
