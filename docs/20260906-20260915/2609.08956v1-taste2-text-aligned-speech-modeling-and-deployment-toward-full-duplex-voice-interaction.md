## 摘要
全双工语音交互需要的不仅是话语级转换。它必须处理流式语音，管理话轮转换与打断，同时保留预训练的语言能力和声学副语言线索。我们探究 TASTE（文本对齐语音分词与嵌入）是否为这一目标提供可行路径。我们提出 TASTE2，它将话语级 TASTE 转换为增量式对话栈。共享的文本 token 词汇表消除了词级平均；模态对齐的对话训练为每个文本 token 预测一个连续音频隐变量，而无需交织异构 token 流。增量式语音解分词器通过 CosyVoice2 实现流式合成。经过语音和对话训练后，TASTE2（Merge）在 LLaMA-Questions 上达到 56.3%，而纯文本 Qwen2.5-7B Instruct 参考为 57.3%（准确率保持 98.2%）；TASTE2（Direct）达到 53.0%（保持 92.4%）。我们构建了 TASTE2 VoiceBot，它增量处理用户语音、流式输出合成音频，并在用户插入打断时停止生成。在 Full-Duplex-Bench v1.0 上，TASTE2 和 TASTE2 VoiceBot 能良好处理打断，同时保持较高的对话连贯性。自然对话仍具挑战性；经过 TensorRT 加速后，在两块 NVIDIA RTX A6000 上部署的平均首音频时间为 2.701 秒。最后，据我们所知，我们首次系统地表征了基于 TASTE 模型中的显式副语言控制。在对话 SFT 之后，快速语速可作为跨策略的概念验证；情感控制依赖于策略，其余属性仍较弱。综上，这些结果表明基于 TASTE 的建模是通往全双工系统的可行路径，同时指出自然对话鲁棒性、语音生成延迟和通用副语言控制是有待解决的挑战。TASTE2 可在线体验。

## Abstract
Full-duplex voice interaction requires more than utterance-level conversion. It must process streaming speech, manage turn-taking and interruptions, while preserving pretrained linguistic competence and acoustic paralinguistic cues. We ask whether TASTE (Text-Aligned Speech Tokenization and Embedding) provides a viable path toward this goal. We present TASTE2, which transforms utterance-level TASTE into an incremental dialogue stack. A shared text-token vocabulary removes word-level averaging, while modality-aligned dialogue training predicts one continuous audio latent per text token without interleaving heterogeneous token streams. An incremental Speech Detokenizer enables streaming synthesis through CosyVoice2. After speech and dialogue training, TASTE2 (Merge) reaches 56.3% on LLaMA-Questions against a 57.3% Qwen2.5-7B Instruct text-only reference (98.2% accuracy retention), and TASTE2 (Direct) reaches 53.0% (92.4% retention). We build TASTE2 VoiceBot, which processes user speech incrementally, streams synthesized audio, and stops generation on barge-in. On Full-Duplex-Bench v1.0, TASTE2 and TASTE2 VoiceBot handle interruptions well while maintaining high conversational coherence. Natural conversation remains challenging, and deployed mean time to first audio is 2.701 s on two NVIDIA RTX A6000 after TensorRT acceleration. Finally, to our knowledge, we provide the first systematic characterization of explicit paralinguistic control in a TASTE based model. Fast speaking rate serves as a cross-strategy proof of concept after dialogue SFT, while emotion control is strategy dependent and the remaining attributes stay weak. Together, these results establish TASTE based modeling as a practical route toward full-duplex systems while identifying natural conversation robustness, speech generation latency, and feature general paralinguistic control as open challenges. ## 1. 论文的核心问题与整体含义

- **研究问题**：全双工语音交互不仅需要将完整用户话语转换为回复，还要求系统：

  - 在适当时间决定“接话”或“让出话轮”；
  - 在用户插入打断时立即停止生成；
  - 同时尽量保留预训练语言模型的语言能力与声学副语言线索（如情感、语速、韵律）。
- **背景矛盾**：

  - 完全端到端联合训练虽然信息流通顺畅，但组件耦合度高、难以独立优化和部署；
  - 传统 ASR–LLM–TTS 级联管道只传递文本，丢失了副语言信息。
- **整体含义**：论文试图回答“TASTE 这种文本对齐语音 tokenization 是否能作为通往全双工语音交互的可行建模路径”，并通过模型改造、训练与部署系统验证这一路径的可行性。

## 2. 论文提出的方法论

TASTE2 将原 TASTE 从“话语级”改造为“增量对话栈”，核心思想是**每个文本 token 对应一个连续音频隐变量（audio latent）**，使模型序列长度与纯文本完全一致，避免异构 token 交织造成的序列膨胀。

### 2.1 模型架构

- **Speech Tokenizer**：
  - 使用冻结的 Distil-Whisper 编码器；
  - 将解码器的输入嵌入层替换为 Spoken LM 的 token 词汇表并随机初始化；
  - 移除 LM 头，解码器直接输出连续音频隐变量；
  - 经过 Residual Vector Quantizer（RVQ）约束隐变量空间；
  - 输出与文本 token 一一对齐的连续音频 latent。
- **TASTE2 Spoken LM**：
  - 基于 Qwen2.5-7B（base 或 instruct 版本）；
  - 使用 LoRA 微调；
  - 自回归地同时预测文本 token 和对应音频 latent；
  - 输入位置为文本 token 嵌入与其音频 latent 嵌入的加权和，不插入额外序列位置；
  - 生成时文本 token 先于其音频 latent 预测（音频目标向后移动一个位置）。
- **Speech Detokenizer**：
  - 将 Spoken LM 输出的文本 token–音频 latent 对映射到 CosyVoice2 的 S3 单元；
  - 基于 Qwen2.5-0.5B 的 text-to-S3 架构；
  - 采用增量 chunk 处理：每 5 个输入对产生 15 个 S3 单元，实现流式合成；
  - 下游 flow-matching 模型和 vocoder 继承自 CosyVoice2，保持冻结。

### 2.2 训练流程

- **Stage 1**：联合训练 Speech Tokenizer 和 Speech Detokenizer，建立音频隐变量空间；
- **Stage 2**：Spoken LM 预训练，使用 LoRA 学习预测对齐的文本 token 与音频 latent；
- **Stage SFT**：对话监督微调，训练多轮对话、话轮边界估计与打断响应。
- **两种指令跟随初始化策略**：
  - **Approach 1（Merge）**：Stage 2 从 Qwen2.5-7B base 开始，训练完成后通过 TIES-merging 将 Qwen2.5-7B-Instruct 的任务向量注入 Spoken LM，再进入 SFT；
  - **Approach 2（Direct）**：Stage 2 直接初始化自 Qwen2.5-7B-Instruct，不进行模型合并。
- **对话模板**：使用 ChatML 风格，`<|im_start|>` / `<|im_end|>` 分隔 system/user/assistant 段，音频 latent 附着在每个文本 token 位置。
- **打断感知损失**：
  - 正常轮次：对全部 token 计算损失；
  - 打断轮次：将 interrupted assistant 末尾的 `<|im_end|>` token 损失权重设为 0，其余内容 token 仍参与损失；
  - 推理时使模型能在检测到用户语音开始后立即停止生成。
- **模型门控话轮决策**：模型学习将 `<|im_end|>` 概率作为话轮结束信号；部署时，VAD 检测到语音结束（100 ms 静音）后，由 Agent Response Generator 评估该概率，通过 top-k 或概率阈值判断是否接话。

### 2.3 部署系统：TASTE2 VoiceBot

- **微服务架构**：四个 WebSocket 服务：
  1. **User Speech Processor**：VAD、ASR、TASTE tokenization、打断检测；
  2. **Agent Response Generator**：维护对话历史，运行 Spoken LM，处理话轮门控；
  3. **Agent Speech Generator**：Speech Detokenizer + CosyVoice2 flow-matching + vocoder，流式生成音频；
  4. **Orchestrator**：路由消息、缓冲音频、拉取式投递、同步反馈与打断清理。
- **打断处理**：VAD 检测到 silence→voice 转换立即发出打断事件，执行关闭 Speech Generator、清空未播放音频缓冲、重置事件标志、重连服务等清理流程。
- **同步反馈机制**：采用拉取式音频投递；只将实际投递给用户的对应 token 加入对话历史，保证对话上下文与用户体验一致。

## 6. 论文的主要结论与发现

- **语义保留**：TASTE2 通过保持序列长度与文本一致，在 LLaMA-Questions 上保留了 98.2%（Merge）和 92.4%（Direct）的文本模型准确率，显著优于 Mini-Omni（29.7%）、Moshi（83.1%）等交织型语音 LM。
- **性能差异原因**：Merge 与 Direct 的差距主要来自指令跟随初始化策略，而非连续语音建模本身，说明可通过模型合并避免部分语义损失。
- **RVQ 的作用**：RVQ 不是为了提高表示保真度，而是**约束隐变量空间使其可预测**；移除 RVQ 会提高 Stage 1 重建准确率，但导致 Stage 2 收敛差、文本准确率大幅下降。
- **全双工行为**：TASTE2 在用户打断场景下反应极快（0.060 s），同时保持较高连贯性（GPT-4o 评分 3.275）；但平滑话轮切换延迟较高（约 1.2 s），是模型门控话轮决策的直接代价。
- **部署延迟**：经过 TensorRT 加速后平均 TTFA 为 2.701 s，仍不如 ChatGPT Voice（1.370 s）；瓶颈主要在 Agent Speech Generator。
- **副语言控制**：快速/慢速语速在对话 SFT 后仍能较好控制；情感控制受训练策略影响大（如 angry 在 Direct 下达到阈值，Merge 下失败）；其他属性整体较弱；Stage 2 表示质量是 SFT 后控制能力的重要上限。
- **总体结论**：文本对齐语音建模是通向全双工系统的实用路径，但自然对话鲁棒性、语音生成延迟、跨属性副语言控制仍是开放挑战。

## 7. 优点

- **核心思想简洁有效**：文本 token 与音频 latent 一一对齐，不增加序列长度，从根本上缓解了语音建模对文本语言能力的侵蚀。
- **模块化与可部署性**：各部分可独立优化，同时通过共享词汇表和模态对齐保持信息流动；实际构建了可工作的 VoiceBot 系统。
- **系统性评估**：不仅报告模型精度，还覆盖全双工行为、端到端延迟、副语言控制等实际系统维度。
- **首次系统表征 TASTE 模型的显式副语言控制**：为后续研究提供了有价值的基准和 failure case。
- **公开资源**：论文提供了主页、Spoken LM 实现、VoiceBot 部署栈、预训练 checkpoint 和副语言对话语料，有助于复现和后续工作。

## 8. 不足与局限

- **自然对话鲁棒性不足**：在自然对话（CANDOR）上的表现不如合成场景，仍存在较大改进空间。
- **话轮切换延迟高**：平滑轮次等待时间约 1.2 s，远高于 Moshi（0.265 s）和 Freeze-Omni（0.953 s），可能影响真实用户体验。
- **语音生成延迟大**：首音频延迟 2.701 s，主要瓶颈在 Speech Detokenizer / CosyVoice2 流式合成，尚未达到商用水平。
- **副语言控制不一致**：除语速外，情感、音量等控制效果弱且策略依赖强；Stage 2 表示质量直接限制 SFT 后控制能力。
- **Backchannel 未实现**：部署配置下系统不产生 listener feedback，全双工互动能力不完整。
- **实验样本与覆盖有限**：TTFA 单样本
